## 1. 방법론 골격

### 1.1 DCX가 디자인씽킹과 다르다고 주장한 지점

발표자료는 두 방법론을 정면으로 대비시킨다.

| | 디자인씽킹 | DCX |
|---|---|---|
| 가설 | 제한된 가설 | 데이터로 해석하고 기회로 확장 |
| 대상 | 하나의 페르소나에 집중 | 다수의 마이크로 세그먼트 |
| 근거 | 관찰된 고객의 감정 | 소셜 리스닝 데이터의 Need · Pain |
| 결과 | 페르소나를 이해 | 고객 경험의 다차원적 의미 재설계 |

DCX 흐름은 `비즈니스 문제 정의 → 소셜 데이터 확보 → 고객 페르소나 분석 → 고객 행동 분석 → 미래 주거 경험 설계` 다섯 마디로 표현된다.

### 1.2 DCX Process — 5 진행단계

`DCX™ : Data-driven Customer eXperience` · 특허 2021-0049276 / 상표 40-2022-0012292

| 진행단계 | 활동 | 적용 모델 |
|---|---|---|
| ① 비즈니스 문제정의 | 타겟 디자인 | — |
| ② 데이터 준비 | 데이터 수집 및 클렌징 | — |
| ③ 데이터 분석 | 텍스트 마이닝 / CAM | **3A Model** |
| ④ 인사이트 도출 | 기회영역 분석 · 인사이트 도출 | **4D-CX Model** |
| ⑤ 고객 경험 설계 | 트렌드 분석 · 경험디자인 아이디어 워크샵 | — |

한 문장 요약(자료 원문) — *"비즈니스 문제 정의를 시작으로 타겟 맞춤형 데이터를 수집하여 고객 관점에서 다양한 맥락(context)을 찾아 필요로 하는 경험 측면에서 서비스 컨셉을 제안함"*

### 1.3 8개 실행 블록

5 진행단계 아래에 실제 작업 단위가 8개 놓인다.

```
데이터 수집·전처리 → 클러스터링 → 고객 액션(마이크로 세그먼트별 LDA) → 고객 액션 맵
  → 기회 영역 & 4D-CX → 인사이트 도출 → 경험디자인 아이디어 워크샵 → 서비스 컨셉 제안
```

### 1.4 3A Model

데이터 분석 단계에 적용되는 3층 구조. **Actor(누가) · Action(무엇을) · Artifact(무엇으로)**

발표자료 본문에서 Actor와 Action은 명시적 산출 단위로 쓰이고, Artifact는 Part 2의 SERVICE 정의에서 등장한다.

### 1.5 4D-CX Model — 네 개의 경험의 장

인사이트 도출 단계의 해석 프레임. "어떤 **경험**을 하는가?" → "어떤 **기회**가 있는가?"

| 경험의 장 | 사용자 경험 | 정의 | 던지는 질문 |
|---|---|---|---|
| **정신적** | 더 깊은 | 알고리즘 기반 누적 데이터로 맞춤형 정보·서비스를 받아 얻는 가치 | 집에서의 잠재적 욕구? 집(공간)의 의미는? |
| **물리적** | 더 선명한 | 감각을 자극하는 뚜렷한 경험을 제공받아 얻는 가치 | 무엇을 하는가? 얼마나 머무르는가? |
| **문화적** | 더 넓은 | 다른 사람과 소통하고 경험을 공유할 때 얻는 가치 | 누구와 함께 하는가? 어떤 문화가 생성될까? |
| **시스템** | 더 높은 | 단순 경험을 넘어 더 높은 차원의 가치를 실현할 때 얻는 가치 | 어떤 공간과 연결되는가? 어떤 과정이 필요할까? |

## STEP 02 · 타겟 대상 · 채널 선정

발표자료가 **「타겟 디자인」** 이라 부르는 작업의 전반부. 3개 Step으로 진행된다.

### Step 1-a · 인구통계학적 타겟 조사

선행연구(기업 리포트 · 통계자료 · 논문)를 검토해 인구통계 축을 잡는다.

- 성·연령대별 1인 가구 비중에서 **39세 이하**와 **60대 이상**이 높게 나타남
- 취업 1인 가구 추이 — 2017년 3,431 → 2021년 4,140 (천 가구), 꾸준한 증가
- 고령자 1인 가구 — 2010년 106.6만(34.3%) → 2020년 166.1만(35.1%)
- 50+ 세대 1인 가구 유형 순위 — 미혼 › 사별 › 이혼 › 기러기

### Step 1-b · 트렌드 타겟 조사

| 트렌드 타겟 | 근거 | 출처 |
|---|---|---|
| **리치 싱글** | 1인 가구 연소득 상위 10% 증가 추세 | KB경영연구소, 「2022 한국 1인가구 보고서」 |
| **액티브 시니어** | 온라인 카드 결제 증가율 60대+ **142%** (전체 71%, 20대 45%) | 신한카드 빅데이터연구소, 2022 |
| **비혼** | 비혼 가치관 수요 증가 | 통계청, 「한국의 사회동향 2022」 |
| **반려 가구** | 7대 주거공간 트렌드 중 07 「펫·붓·인 스테이」 | 피데스개발, 2020~2021 |

### Step 2 · 채널 조사

- 20~30대 **70% 이상**이 최근 한 달 내 온라인 커뮤니티 이용 (대학내일연구소)
- 시니어는 네이버 블로그보다 **카카오 브런치** 이용률이 높음
- 일주일 내 관심사 공유 플랫폼 이용률 — 네이버 **91.5%** > 유튜브 85.4 > 카카오톡 80.8 > 구글 66.2 > 인스타그램 56.8 (다이티데이터마켓)

### Step 3 · 최종 채널 11개 확정

선정 기준은 두 가지다. ① 인구통계/트렌드 적합성 ② **게시글을 직접 검토해 needs와 pain point 등 다양한 맥락이 실제로 보이는지 확인**

#### 인구통계학적 축

| 타겟 | 채널 | 선정 근거 |

| 20-40대 남성 1인 가구 | 디시인사이드 자취·독거/룸 갤러리 + **유튜브 자막(자취남)** | 관심사별 갤러리 구조 · 자취남 구독자 61.9만, 영상 자막으로 데이터 확보 |

| 액티브 시니어 | 브런치 / 은퇴 후 50년 | 브런치는 작가 심사 통과자만 활동 · 은퇴 후 50년 회원 약 6만 |
| 신혼부부 | 다이렉트 결혼준비 | 회원 약 85만, '신혼집/인테리어' 게시판 |

## STEP 03 · 카테고리 / 키워드 선정 + 3V 검토

「타겟 디자인」의 후반부. **7단계 발산-수렴 사이클**을 돈다.

```
① 주거 관련 카테고리 발산
② 부적합 카테고리 1차 소거
③ 카테고리 1차 수렴
④ 세부 카테고리 2차 발산
⑤ 부적합 카테고리 2차 소거
⑥ 카테고리 최종 수렴
⑦ 최종 카테고리 검증
```

### ① 1차 발산 — 22개

선행연구 + 브레인스토밍 워크시트 + 데이터 탐색으로 22개를 뽑는다.

> 내부 공간 · 외부 공간 · 기술 · 친환경 · 주거 서비스 · 커뮤니티 시설 · 네트워크 · 라이프스타일 · 워라밸 · 인스피리언스 · 주거 경제 · 운동 · 건강 관리 · 감정 · 인테리어 · 새로운 주거형태 · 바운드리스 · 청소/위생 · 위치/치안 · 반려동물 · 자녀 · 싱글맘/대디

### ② 1차 소거 — 22 → 20

- **싱글맘/대디 제거** — 채널을 특정하기 어렵고 주거 관련 데이터 품질이 낮음
- **운동 + 건강관리 + 감정 병합** — 연관 키워드가 많아 `헬스/건강`, `감정/케어` 두 개로 통합
  - 홈짐·헬스케어·헬시플레저·케어푸드 → **헬스/건강**
  - 외로움·감정해독 → **감정/케어**

### ③ 1차 수렴 — 8개 묶음

유사 context를 가진 카테고리를 묶고 각 묶음에 **한 줄 해시 문장**을 붙인다. 이 문장이 이후 해석의 앵커가 된다.

| 묶음 | 구성 | 해시 문장 |
|---|---|---|
| 인테리어 디자인 | 내부 공간 + 인테리어 | #내가 머무는 공간을 직접 계획하고 꾸미다 |
| 편의시설 | 외부 공간 + 바운드리스 | #집 주변의 시설을 편리하게 이용하다 |
| 에코 주거 | 기술 + 친환경 + 새로운 주거형태 | #기술과 자연이 함께하는 새로운 주거형태를 경험하다 |
| 홈 라이프 | 워라밸 + 인스피리언스 | #실외에서 하던 일과 휴식을 집에서 즐기다 |
| 건강하고 안전한 삶 | 감정/케어 + 헬스/건강 + 위치/치안 | #건강하고 안전한 삶을 누리다 |
| 1인 소비 | 라이프스타일 + 주거 경제 | #새로운 라이프 스타일에 따라 1인 소비 트렌드를 만들다 |
| 공유 공간 | 주거 서비스 + 커뮤니티 시설 + 네트워크 | #때로는 여러 사람과 공간을 공유하다 |

## STEP 06 · 삼중 준지도 학습

### 문제 인식

*"광고 제거 및 전처리 작업 후에도 여전히 연구 목적에 부합하지 않은 노이즈 데이터가 존재"* — 명시적 규칙으로는 걸러낼 수 없는 글을 제거하기 위해 고안한 프로세스다.

### 라벨 정의

| 라벨 | 코딩 | 정의 |
|---|---|---|
| **Informative** | 1 | needs / desire / pain point / context / action 이 담김 |
| **Uninformative** | 0 | 채널 가입 인사, 홍보 글, 타겟과 관련 없는 글 |

**Informative 예시** — *"혼자 살기 적당한 크기가 몇이라고 하던데 지금 사는 곳이 평 욕실 주방 분리된 곳 빼면 살거주하는 곳이 평 정도임"*
**Uninformative 예시** — *"인테리어 발코니를 홈카페처럼 구미동 현대 차 아파트 평 인테리어 이반장 안녕하세요 인테리어 이반장입니다 오늘 소개해 드릴 시공사례입니다"*

### 1단계 · 사람 라벨링 (3%)

- 전체의 **3%, 약 11,550건**을 사람이 라벨링 — 나머지 97% 분류를 위한 "참값"
- **3차 교차검증** 구조 — `Coder A,B` → 불일치 시 `Coder C,D` → 다시 불일치 시 `판단자(judge)`

### 2단계 · 3개 모델 계단식 판정

```
          레이블링 완료 텍스트 (3%)
                    │
        ┌───────────┴───────────┐
   Model 1 (LSTM)          Model 2 (CNN)
   val_acc 0.8129          val_acc 0.8205
   4h 50m 07s              41m 03s
        └───────────┬───────────┘
              예측값 비교
        ┌───────────┴───────────┐
      일치 318,244건        불일치 47,596건
      → GRU Train set       → GRU Test set
                    │
             Model 3 (GRU)
             val_acc 0.9793
             1d 15h 05m 47s
                    │
   Total 377,347 / Informative 118,648 / Uninformative 258,699
```

> **설계 의도** — LSTM과 CNN이 **합의한 것을 정답으로 간주**해 GRU 학습셋으로 삼고, **합의하지 못한 것만 GRU에게 판정시킨다.** 사람 라벨 3%를 두 모델로 증폭한 뒤 세 번째 모델이 경계 사례를 처리하는 구조다. GRU의 0.9793은 "합의된 라벨을 얼마나 잘 재현하는가"이지 사람 기준 정확도가 아니다.

## STEP 07 · Ward Clustering → Touch Point

### 분석 단위

**`게시글 제목 + 본문 + 댓글`을 하나의 document로 묶어** 진행한다. 댓글이 본문과 같은 단위에 들어간다는 점이 중요하다 — 질문 글의 답글에 맥락과 해결 시도가 담기기 때문이다.

### 방법

- **Ward Clustering** 알고리즘으로 유사한 의미·맥락의 텍스트를 군집화
- 성능 평가는 **실루엣 스코어**
- **내부** / **외부·주거 서비스** 로 나누어 각각 클러스터링

| 구간 | 검토한 k | 채택 | 실루엣 계수 |
|---|---|---|---|
| 내부 | n=5, n=7 | **n=5** | 0.043963 |
| 외부·주거 서비스 | n=3, n=5 | **n=3** | 0.035835 |

→ **총 8개 Touch Point**

## STEP 08 · SNA → 마이크로 세그먼트 → Actor

### 3단계 절차

**1) 노드 생성** — 의미 있는 품사(명사·형용사·동사)로 노드를 만든다. (예: 안되다, 바닥, 다시, 문제, 시공, 가능하다, 설치, 도배, 타일 …)

**2) 공출현 빈도 계산** — 동일 문단에서 두 노드가 동시 등장하면 카운트해 대칭 행렬을 만든다.

**3) 모듈성 분석** — **아이겐벡터 중심성**(노드의 네트워크 영향력)을 기준으로 군집화한다. 모듈은 색상으로 구분된다.

```
예시 · TP3 인테리어 시공에서 잡힌 모듈
  [업체] [문의] [견적] [추천] [비용] [직접] [정보] [고민]
   → 인테리어 업체 시공 문의 관련 마이크로 세그먼트
```

### Actor 정의

마이크로 세그먼트를 **읽고 그 안의 Desire를 파악해 Actor를 정의**한다. 클러스터가 달라도 Desire가 유사하면 통합한다. 이 판단은 알고리즘이 아니라 사람이 한다.

## STEP 09 · 마이크로 세그먼트별 LDA → Action

### 방법

- 마이크로 세그먼트 내에 혼재된 여러 토픽(액션)을 **LDA(Latent Dirichlet Allocation)** 로 식별
- **토픽 가중치를 활용해 각 문서를 액션에 할당**
- LDA 후 토픽이 비슷하거나 동일한 마이크로 세그먼트는 추가 통합
- → **총 59개 Action**

### LDAVis 해석 규칙

Python으로 구현한 LDAVis로 토픽을 시각 검증한다.

| 요소 | 의미 |
|---|---|
| 원의 크기 | 토픽의 크기 |
| 원의 거리 | 토픽 간 유사성 — **두 원이 겹치면 유사 토픽** |
| 토픽별 단어 막대 | 토픽을 형성하는 주도적 키워드 |
| **Relevance (λ)** | 특정 토픽에서의 출현 빈도와 전체 문서에서의 출현 빈도를 균형 조정하는 파라미터 |

> λ가 0에 가까울수록 해당 토픽을 다른 토픽과 **차별성 있게** 구분하는 단어가 부각된다.
> Sievert & Shirley (2014)에 따르면 **λ = 0.6** 이 가장 효과적이나, 연구 도메인·데이터셋에 따라 다르다.

### Action ID 체계

`[Touch Point][Actor][Action]` 3자리 숫자다. 이 표기가 이후 Opportunity Map의 점 라벨이 된다.

```
422  =  TP4(집안일) · Actor2(요리 후 뒷정리가 귀찮은) · Action2
        → "배달음식을 시키거나 밀키트를 사용해 간단하게 요리함"

313  =  TP3(인테리어 시공/업체) · Actor1(시공업체 선정 고민) · Action3
        → "부분 리모델링을 해야 하는데 원하는 방식대로 시공이 가능한지 궁금함"
```

### 10-B · Opportunity Map

각 Action에 **감성분석**을 걸어 Pain 정도와 긍·부정 감정을 수치화하고, 그 감정점수로 **만족도**와 **중요도**를 계산한다.

**만족도 (Satisfaction)**
키워드별 감정점수를 계산한 후 `토픽 × 키워드` 행렬에 element-wise로 곱해 합산한 값을 그 토픽의 만족도로 본다.

```
SS_k = Σ SentimentMatrix_i,j   (where t = Topic_k)
Satisfaction_k = 10 × (SS_k − SS_Min) / (SS_Max − SS_Min)
```

**중요도 (Importance)**
`토픽 × 문서` 행렬에서 토픽이 각 문서에서 차지하는 비중의 합을 중요도로 본다.

```
CS_k = Σ TDMatrix_i,j   (where t = Topic_k)
Importance_k = 10 × (CS_k − CS_Min) / (CS_Max − CS_Min)
```

> 출처 — Jeong, Yoon & Lee (2019), *Social media mining for product planning: A product opportunity mining approach based on topic modeling and sentiment analysis*

**6개 영역 구획** — 측정된 감정 평균선과 중요도 평균선, 그리고 두 사선으로 구획한다.

| 영역 | 이름 | 정의 |
|---|---|---|
| **A** | Exciting Area | 고객이 기대조차 못한 내용을 잘 만족한 영역 — 잠재적 감동 |
| **B** | Experiencing Area | 기대한 만큼 충족한 영역 |
| **C** | Competitive Area | 좋은 감정 + 높은 중요도 — 미래 핵심 경쟁 우위 |
| **D** | Forgiven Area | 불만족했지만 중요하지 않아 용인 가능한 영역 |
| **E** | Dangling Area | 안 좋을 것이라 기대한 경험이 실제로 좋지 못한 영역 — 잠재적 이탈 원인 |
| **F** | At-risk Area | 중요도는 높으나 부정적 감정 — **지금 당장 개선** |

| 합성 영역 | 구성 | 해석 |
|---|---|---|
| **Underserved** | C + F | 중요도 대비 만족도 낮음 — **개선 우선도 최고** |
| **Well-served** | B + E | 기대와 결과가 일치 |
| **Overserved** | A + D | 중요도 대비 만족도 높음 — **파괴적 혁신 장기 관찰** |

### 10-C · 고객 경험 평가 (required CX)

우선도가 높은 액션이 **어떤 종류의 경험을 요구하는지**를 정량화한다.

```
1) Computed / Connected / Shared 각각의 대표 문장 데이터셋을 원문으로부터 구축
2) 대상 문장(Action 대표 문장)과 세 대표 문장 간 코사인 유사도 측정
3) 유사도 벡터를 softmax로 정규화 → 레이더 차트
```

**예시** — Micro Segment 1
대표 문장: *"식세기 써 보신 분들 어떠신가요 1인 가구고 주방이 좁아 망설여지는데 실제로 어떤지"* / *"붙박이장 슬라이딩 여닫이 사용해 보신 분 의견 좀 부탁드려요"*

| 경험 | 코사인 유사도 | Softmax |
|---|---:|---:|
| Computed | 0.4 | 0.38 |
| Connected | 0.1 | 0.20 |
| Shared | 0.8 | 0.42 |

→ **Requirement: Shared Experience** → 서비스 컨셉 방향 제시

| 요구 경험 | 서비스 방향 | 언어 단서 |
|---|---|---|
| **Computed** | 개인 맞춤형 서비스를 더 정교하게 | 맞춤형, 딱 맞는, 스타일에 맞춰 |
| **Connected** | 서비스의 전달력을 더욱 명료하게 | 시각화, 변화, 알람, 기록 관리 |
| **Shared** | 소통을 더욱 확장 | 정보공유, 소통, 함께, 나눔, 의견, 추천 |

## STEP 11 · Pain Point 맥락 맵핑 → Insight → 경험 디자인 컨셉

### 11-A · Pain Point 맥락 맵핑

3단계로 진행한다.

```
① Pain Point 카테고리화
   데이터로부터 도출된 Pain Point를 검토해 공통 맥락을 재구성
   (대분류: 취향&공유 / 공간 활용 및 창출 / 스마트홈 / 귀차니즘&귀뚫 /
           깨끗한 집 / 아날로그&네트워크 / 문제 해결)
        ↓
② 트렌드 리포트 참고
   1차 카테고리화한 pain point로부터 인사이트를 얻기 위해
   1,2인 가구 및 주거 라이프 관련 트렌드 리포트와 대조
        ↓
③ INSIGHT 도출
   본 연구 결과에 적합한 1,2인 가구 미래 주거 인사이트 도출
```

### 11-B · 7개 INSIGHT

| # | Insight | 핵심 페인포인트 |
|---|---|---|
| 1 | **"당신의 취향이 담길 공간, 알잘딱깔센 큐레이션으로 취향 저격"** | 입주할 때부터 내 취향에 맞춰 자유롭게 꾸밀 수 있는 공간이 필요 / 홈 인테리어 경험을 공유하고 싶음 |
| 2 | **"내가 공간에 맞춰 사는 것이 아닌, 공간을 나에게 최적화"** | 라이프스타일에 맞춰 공간을 언제든지 자유자재로 바꾸고 싶음 |
| 3 | **"실시간으로 직시, 직접 안 봐도 실시"** | 집 안의 모든 걸 스마트폰으로 실시간 확인·제어하고 싶음 |
| 4 | **"해답을 알려주세요, 자이(Xi)-집PT"** | 집에 오면 모든 일이 다 귀찮고 시간 쓰기가 싫음 |
| 5 | **"전에 없던 깔끔함, 한 차원 높은 쾌적함"** | 집에서는 온도·습도·먼지·냄새·적절한 편안함을 느끼고 싶음 |
| 6 | **"아날로그, 잃어버린 감성 찾기"** | 혼자 있는 게 너무 좋지만 가끔은 너무 외로워, 비슷한 사람들과 교류하고 싶음 |
| 7 | **"집에서 생긴 문제, 집이 해결해 줄 수 있나요"** | 아파트 내에서 생기는 문제를 어디서 해결할 수 있는지 모르겠음 |

각 Insight는 **그것을 구성하는 Action들을 역으로 매달고**, 각 Action의 **Opportunity Score를 막대그래프로 함께 표시**한다.
예 — Insight 1은 8개 Action으로 구성되며 평균 Opportunity Score는 **5.3482**, 최고는 집·인프라·환경-Actor2-action4 의 **9.6965**.

### 11-C · 경험 디자인 컨셉

경험디자인 아이디어 워크샵을 거쳐 **4블록 구조**로 정리한다.

| 블록 | 내용 |
|---|---|
| **01. PERSONA** | Actor에서 도출. 이름/신분 · Pain Point · From(어느 Insight에서 왔는지) · 공간 · 해시태그 |
| **02. SERVICE** | Artifact. 4D-CX 중 어느 경험의 장에 해당하는지 우상단에 표기 |
| **03. EXPERIENCE** | Action. 서비스 사용 후의 1인칭 경험 서술 + 일러스트 |
| **04. INTERVIEW** | 고관여자 인터뷰 인용으로 컨셉 검증 |

**예시 — 페르소나 "영호(29세), 직장인"**
- Pain Point: 가구 위치를 변화시키며 공간을 디자인하고 싶음 / 한정된 공간 분리 고민
- From: Insight 1 + Insight 2 · 공간: 거실, 침실
- SERVICE: 가변형 패키지 옵션 + 자이 평면도 3D 시뮬레이션 → **정신적 세계 + 물리적 세계**
- EXPERIENCE: *"3D로 구현된 자이 평면도에 내가 원하는 가구를 배치하고 꾸며보고 결과물을 바로 SNS에 공유할 수 있어서 너무 편하고 뿌듯하다"*

### 11-D · 고관여자 인터뷰

각 페르소나에 대응하는 실제 거주자를 인터뷰해 컨셉을 검증한다. 주거 유형·평형·방 개수를 명시하고, **평면도 위에 9개 공간별 코멘트를 얹는** 형식이다. (현관 · 다용도실 · 주방/식당 · 침실1 · 침실2,3 · 드레스룸·파우더룸 · 욕실 · 거실 · 발코니·실외기실 + 외부공간/주거서비스)

STEP 02에서 리치 싱글 데이터가 부족하다고 인정한 부분을 여기서 메운다.

| 다용도실 | 2 |
| 발코니 · 실외기실 | 2 |

> 같은 데이터를 **경험 축(Touch Point)**과 **물리 축(공간)** 두 번 자른다. 건설사라는 클라이언트가 평면 설계 단위로 의사결정하기 때문에, 경험 축 결과만으로는 실행으로 넘어가지 않는다는 판단이 깔려 있다.

---

## 13. 요약 — DCX 1.0의 구조적 특징

**① 사람의 판단이 6곳에 들어간다**
채널 선정 · 카테고리 수렴 · 3V 검증 · 3% 라벨링 · Actor의 Desire 해석 · Pain Point 카테고리화. 자동화된 것은 군집화 · 분류 · 토픽 추출 · 감성 점수뿐이다.

**② 계층은 3층이다**
`Touch Point(8) → Actor(14) → Action(59)`. Actor는 인구통계가 아니라 **Desire 문장**으로 정의되고, Action은 LDA 토픽으로 정의된다.

**③ 우선순위가 수치로 결정된다**
Opportunity Map의 만족도 × 중요도가 "무엇부터 할 것인가"를 결정한다. 이 두 값의 산식이 Jeong et al.(2019)로 명시돼 있다는 점이 DCX가 임의적 워크샵과 갈라지는 지점이다.

**④ 결론이 원문까지 추적 가능하다**
`Insight → Action(ID) → Actor → Touch Point → 원문` 경로가 끊기지 않는다. 다만 이 추적은 문서 상에서 수동으로 유지되며, 시스템이 보장하지 않는다.

**⑤ 데이터가 못 하는 것은 인터뷰로 메운다**
리치 싱글처럼 소셜 데이터로 잡히지 않는 타겟은 처음부터 "고관여자 인터뷰로 보완"이라고 선언하고 넘어간다. 데이터의 한계를 숨기지 않는 구조다.
