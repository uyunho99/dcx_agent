# DCX 1.0 (AS-IS) → DCX Agent 2.0 (TO-BE) 대비표

> **읽는 법** — 1.0의 11 STEP 골격을 그대로 세로축으로 쓴다. 한 단계에 변경점이 여러 개면 행을 나누고 단계명은 첫 행에만 적는다.
> **효과 태그** — `재현성` 같은 입력이면 같은 결과 · `효율성` 사람 시간·비용 감소 · `추적성` 결론에서 원문까지 경로 보장 · `일관성` 맥락이 전 단계에 전파 · `신규성` 이미 아는 것을 걸러냄 · `검증성` 품질을 수치로 판정 · `비교가능성` 기존 방법과 나란히 대조

---

## 1. 한눈에 보기

| | DCX 1.0 (AS-IS) | DCX Agent 2.0 (TO-BE) |
|---|---|---|
| **수행 형태** | 6개월 연구 프로젝트 · 단계마다 산출물이 문서로 넘어감 | 세션 단위 파이프라인 · 단계 간 산출물이 스키마로 넘어감 |
| **사람의 판단** | 6곳 (채널 선정 · 카테고리 수렴 · 3V 검증 · 3% 라벨링 · Desire 해석 · Pain Point 분류) | 3곳 (키워드 방향 지시 · 캘리브레이션 + escalate 검수 · 페르소나 확정) |
| **사람 검수량** | 전체의 3% 수기 라벨링 (약 11,550건) | 목표 오류율 α가 검수량을 결정 (캘리브레이션 300~500건 + 자신 없는 건만) |
| **분석 채널** | 선행연구로 11개 채널 수기 선정 | 네이버 카페 단일 채널 + 카페 포함/제외 필터 |
| **추적 가능성** | 경로는 있으나 문서 상에서 수동 유지 | 계층 ID(`CL0-P1-A1`)로 시스템이 보장 |
| **서술의 지위** | 관측인지 추측인지 구분 없음 | 모든 서술에 인식론 등급(관측/추론/추측) 부착 |

## 2. 단계별 대비표

| 단계 | AS-IS — 기존 방식 | TO-BE — 바꾸는 방식과 이유 | 효과 |
|---|---|---|---|
| **STEP 01**<br>비즈니스 문제 정의 | 문서와 회의로 합의하고 넘어간다. **산출물이 없고**, 이 선언이 이후 절차에 자동으로 전달되는 장치도 없다. | 문제 정의를 **13개 구조화 필드**로 받고, 그중 '한줄 정의'가 전 단계 프롬프트 헤더에 상주한다. 키워드 생성부터 최종 처방까지 같은 맥락 위에서 만들어진다. | `일관성` `재현성` |
| | 회사가 아는 사실(제약)과 소비자에 대한 가설(타겟)이 한 덩어리로 들어간다. | **가드레일과 기준선을 분리**한다. 사내 제약은 위반 시 오류로 잡고, 타겟 가설은 해석에 개입시키지 않고 마지막에 대조만 한다 — 알아내려는 것을 미리 답으로 넣으면 순환 논증이 된다. | `검증성` |
| | "이건 이미 아는 내용"을 판별할 장치가 없다. 분석 결과에 기존 지식이 그대로 섞여 나온다. | **known_insights 입력**을 신설한다. 실무자가 이미 아는 5~10문장을 받아 좌표를 부여하고, 근거 수집 단계에서 페널티 항으로 써 '아는 이야기'를 순위에서 내린다. | `신규성` |
| **STEP 02**<br>타겟·채널 선정 | 선행연구·통계·논문을 검토해 **11개 채널을 수기 선정**한다. 6개월 연구의 상당 부분이 여기 들어간다. 그러고도 리치 싱글은 데이터 확보에 실패해 인터뷰로 보완했다. | 채널 선정 스텝을 **없앤다.** 네이버 카페 단일 채널로 고정하고, 채널 취사선택은 수집 단계의 포함/제외 필터가 맡는다. | `효율성` `재현성` |
| | 소득 등 소셜 데이터로 관측 불가능한 항목을 타겟 조건에 넣는다. | 관측 불가 항목을 제거하고 **가격 감도 서수(상·중·하)로 대체**한다. 측정할 수 없는 값을 정밀하게 적으면 거짓 정밀도가 된다. | `검증성` |
| **STEP 03**<br>카테고리·키워드 선정 | 발산–소거–수렴 **7단계 사이클을 수기로** 돈다. 3V(Volume·Variety·Velocity) 타당성도 사람이 눈으로 검증한다. | 라운드마다 **다른 발상 기법을 배정**한다 (R1 5W1H·JTBD / R2 SCAMPER / R3 수렴 / R4 역발상). 기존에는 R2~R4가 모두 같은 프롬프트를 타서 라운드를 나눈 의미가 없었다. | `재현성` |
| | 데이터 양의 타당성(Volume)을 사람이 판단한다. | **검색량 자동 스코어링**으로 대체한다. Volume은 코드로 판정되고, Variety는 사용자 승인 게이트가 흡수한다. | `효율성` |
| | 키워드 승인·거절이 **그 라운드에서 소모되고 버려진다.** 다음 라운드가 같은 실수를 반복한다. | 거절에 **사유 태그**를 붙여 다음 라운드 프롬프트에 누적 주입한다. 사람의 개입이 on/off가 아니라 방향 지시가 된다. | `효율성` `일관성` |
| | 7개 카테고리가 한 층에 평면 배열된다. 물리적 맥락(시간·공간)과 심리적 맥락(감정·니즈), 그리고 "누구인가"가 뒤섞인다. | **물리 · 심리 · 행동 3축**으로 재편한다. 축이 분리돼야 발산 톤 분기와 최종 대조가 코드로 성립한다. | `재현성` |
| **STEP 04**<br>소셜 리스닝 수집 | 11개 채널을 **각각 수기로** 크롤링한다 (642,496건 / 1년 7개월 분). | **크롤링 모듈이 그대로 승계**한다. 쿼리 조합·기간·광고 필터·중복 제거·배치 저장까지 기존 확정안이며 이번 개정 대상이 아니다. | `효율성` (유지) |
| | 중단되면 처음부터 다시 돌아야 한다. | **500건 단위 배치 저장 + 재개.** 중단 지점부터 이어서 수집한다. | `효율성` |
| **STEP 05**<br>전처리 | **OKT 형태소 분해**가 정제의 중심이고, 이 산출물이 이후 SNA 노드와 감성점수 계산의 전제가 된다. | 의미 임베딩이 그 자리를 대신하되 **형태소도 병행 산출**한다. 기존 방법(SNA·LDA)과 신규 방법을 비교하려면 같은 입력에서 출발해야 하므로 한쪽을 지우지 않는다. | `비교가능성` |
| | 벡터가 필요한 단계마다 **각자 따로** 임베딩을 만든다. | 임베딩을 **이 단계 한 곳으로 모은다.** 총 계산량은 늘지 않고 중복 호출이 사라지며, 벡터 공간이 하나로 통일돼 이후 단계가 같은 좌표계를 공유한다. | `효율성` `일관성` |
| | 광고·중복·저품질 필터링 | **동일하게 유지.** 규칙 기반 필터는 이미 잘 작동하므로 손대지 않는다. | (유지) |
| **STEP 06**<br>준지도 학습<br>→ 근거 판정 | 전체의 **3%(약 11,550건)를 사람이 라벨링**한다. 3차 교차검증(A/B → C/D → 판단자) 구조라 인건비가 크다. | **AI가 전량 판정하고 사람은 두 곳만 본다** — 기준을 만드는 캘리브레이션 300~500건, 그리고 AI가 자신 없어 올린 건. 검수량이 데이터 규모에 비례해 늘지 않는다. | `효율성` |
| | 검수량을 **경험칙으로 정한다.** "정확도가 정체하면 멈춘다" 외에 근거가 없고, 채택된 라벨이 얼마나 틀렸는지는 끝까지 알 수 없다. | **목표 오류율 α를 먼저 정한다.** 그러면 판정 임계값이 데이터에서 도출되고, 사람 검수량은 입력이 아니라 결과가 된다. 품질이 보장값이 된다. | `검증성` `재현성` |
| | LSTM·CNN 합의 → GRU 판정의 계단식 구조. 학습에만 LSTM 4시간 50분, GRU 1일 15시간이 든다. | 판정 근거축이 다른 **평가자 k개로 같은 문서를 판정**시키고 일치율을 신뢰도로 쓴다. 사람 2인 이중 라벨에서 일치도를 얻는 것과 같은 논리이고, 대규모 재학습이 없다. | `효율성` `검증성` |
| | 관련/무관 **2분류**. 하류 단계가 필요로 하는 정보가 라벨에 남지 않는다. | **Core / Supporting / 제외(사유코드)** 로 분할한다. "관련이냐"가 아니라 "이 원문 하나로 상황을 재구성할 수 있느냐"를 묻는다 — 기계적으로 검증 가능한 기준을 준다. | `추적성` |
| **STEP 07**<br>Clustering<br>→ Touch Point | **Ward 군집화**로 8개 Touch Point 도출. 내부/외부를 사람이 나눠 각각 돌리고, k도 사람이 채택했다. 실루엣 계수는 0.044 / 0.036으로 매우 낮다. | **기존 방법과 임베딩 기반 분할을 나란히 병행**한다. 1.0 결과는 이미 검증된 산출이고 신규 방법이 그것을 얼마나 보존하는지는 아직 아무도 모른다 — 한쪽을 지우면 그 질문에 영구히 답할 수 없다. | `비교가능성` |
| | 실루엣 점수는 **k 선택에만 내부적으로 쓰이고 폐기**된다. 사람은 군집이 좋은지 나쁜지 볼 수 없다. | 같은 계산을 **Validity · Stability · Coherence 3축 진단**으로 화면에 노출한다. 단, 배지는 진단만 하고 병합·분할을 자동 실행하지는 않는다. | `검증성` |
| | 군집 안에서 어느 문서가 볼 가치가 있는지 가릴 근거가 없다. | **'이미 아는 것과의 유사도'와 '조합 희소성'을 함께 표시**한다. 각 값은 흔한데 조합이 드문 문서는 중심 근처에 앉아 있어 거리 기준으로는 절대 걸리지 않는다. | `신규성` |
| **STEP 08**<br>SNA → Actor<br>→ 페르소나 | 공출현 행렬 + 중심성 분할로 마이크로 세그먼트를 만든 뒤, **사람이 읽고 Desire를 해석해** 14개 Actor를 정의한다. 알고리즘이 아니라 판단이다. | 이 자리를 **확정 절차로 정형화**한다. Actor 층을 Persona로 되살리고 (`클러스터 > 페르소나 > 컨텍스트` 3층), Desire·Goal을 여기서 확정한다. | `재현성` |
| | 서술 단계의 LLM이 이름·상황·페인포인트를 뱉으면서 **페르소나 개수까지 정한다.** 구획과 산출물 수가 어긋난다. | **구획을 만드는 단계가 개수를 확정**하고, 서술 단계는 그것을 받아 쓰기만 한다. 순서가 맞아야 이후 배분이 정의된다. | `일관성` |
| | 중심성 상위 키워드로 Desire를 읽는 방식 | **그대로 승계.** 어느 방법으로 경계를 잡았든 같은 방식으로 뽑으므로, 두 갈래 모두에서 같은 화면이 재현된다. | `비교가능성` (유지) |
| **STEP 09**<br>LDA → Action<br>→ 근거 수집 | **LDA 토픽 모델링**으로 59개 Action을 뽑고 LDAVis를 사람이 눈으로 해석한다 (λ 값도 도메인마다 다시 잡아야 한다). | **가설 문장을 만들어 검색**하는 방식으로 바꾼다. 클러스터·페르소나 필터를 필수로 걸어, 클러스터 3의 근거에 클러스터 7 문서가 섞이던 문제를 구조적으로 막는다. | `추적성` |
| | 검색 순위가 **관련성 단독**으로 정해진다. 관련성이 가장 높은 문서는 대개 실무자가 이미 아는 이야기다 — 근거로는 맞고 인사이트로는 0이다. | 순위 산식에 **'이미 아는 것과 유사하면 감점' · '조합이 희소하면 가점'** 두 항을 곱한다. 서로 다른 축의 새로움 신호를 겹쳐야 "아직 모르는데 진짜인 것"이 남는다. | `신규성` |
| | 클러스터 요약과 검색 결과를 **다음 단계 프롬프트에 그대로 흘려넣는다.** 프롬프트를 고치지 않으면 이 단계를 개선할 수 없다. | 출력을 **Evidence Package 단일 계약 스키마**로 고정한다. 스키마가 같으면 이후 프롬프트를 건드리지 않고도 근거 수집 로직만 따로 개선할 수 있다. | `추적성` `일관성` |
| **STEP 10-A**<br>CAM<br>→ 컨텍스트 맵 | CAM을 **사람이 수기 작성**한다. (구현 버전에서는 LLM이 이름·상황·페인포인트·인사이트 4필드를 한 번에 뱉어, 상황과 결론만 있고 그 사이가 비어 있었다.) | 1.0 CAM의 **행 구조를 그대로 승계**하고 열의 단위를 Action으로 바꾼다. 4개 필드가 4개 화면으로 펼쳐지면서 상황→행동→장벽의 중간 과정이 드러난다. | `추적성` |
| | 각 서술이 **관측인지 추측인지 구분이 없다.** 읽는 사람이 신뢰도를 판단할 수 없다. | **관측 / 추론 / 추측 3등급을 기계 판정으로 부착**한다. 인용할 원문이 있으면 관측, 유도만 가능하면 추론, 어느 쪽도 아니면 추측 — LLM이 스스로 등급을 매기지 않는다. | `검증성` `추적성` |
| | 서술이 개인 단위라 여러 사람의 조각이 **한 인물로 합성될 위험**이 있다. | 각 칸을 **담론 단위**로 서술하고 지지 비율을 함께 둔다. 소수 담론은 지우지 않고 반례로 남긴다. 빈칸은 **비워둘 수 있게** 허용한다 — LLM이 빈칸을 그럴듯하게 메우는 것이 가장 큰 오염원이다. | `검증성` |
| **STEP 10-B**<br>Opportunity Map | 중요도 × 만족도 2축, A~F 6개 영역 구획 | **그대로 유지.** 다만 새 모듈이 아니라 **앞 단계 산출물의 집계 뷰**로 재정의한다 — 새로 계산하는 값이 없다. | `효율성` (유지) |
| | 1.0 장표에는 **배치만 있고 점수 정의가 없다.** 같은 그림을 다시 그릴 수 없다. | **ODI = 중요도 + max(중요도 − 만족도, 0)** 로 정식화한다. 점의 단위는 Action, 색은 페르소나. | `재현성` |
