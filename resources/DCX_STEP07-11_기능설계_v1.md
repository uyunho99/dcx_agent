## 1. STEP 07 — Clustering → Touch Point  `구조적으로 모두 승계`

### 승계
- **실루엣 스코어 그래프** — k 3~14 스캔 곡선을 그대로 노출한다. 1.0 실측 실루엣 `0.044 / 0.036`(내부·외부 별도 실행)을 화면에 병기한다. 최댓값만 찍고 곡선을 감추면 k=6이 얼마나 임의적인지 알 수 없다.
- **Touch Point 정의 패널** — 좌측 상위 어휘 랭킹 + 우측 하위 주제별 대표 원문 그리드. 1.0 장표의 형식 그대로.

### 바뀌는 것
| 항목 | 1.0 | 2.0 |
|---|---|---|
| 어휘 산식 | 클러스터별 TF-IDF | **c-TF-IDF** — 클러스터를 한 문서로 합쳐 계산 → 구별하는 어휘가 올라온다 |
| 소주제 칸 | 사람이 원문을 읽고 4~6개로 묶음 | **L2 서브 K-means 구획을 그대로 칸으로 사용** → 같은 입력이면 같은 장표가 재현된다 |
| 반례 | 없음 | 마지막 칸에 **반례 담론 고정 보존** (Edge 밴드) — 삭제 대상이 아니다 |

## 2. STEP 08 — SNA → Actor → 페르소나  `구조적으로 모두 승계`

### 승계
- **3단계 절차 카드** — ① 노드 생성(명·형·동) ② 공출현 빈도 행렬 ③ 아이겐벡터 중심성 기준 모듈성 분석. 산식 동일, 모듈성 Q 표시.

## 3. STEP 09 — LDA → Action → 근거 수집  `신규 설계`

### 문제 (기획안)
> 검색 순위가 관련성 단독으로 정해진다. 관련성이 가장 높은 문서는 대개 실무자가 이미 아는 이야기다 — 근거로는 맞고 인사이트로는 0이다.

### 설계

**3-1. LDA 토픽맵 승계** — 토픽 간 거리 산점도(원 크기=비중, 원 거리=유사성) + 주도 어휘 막대 + λ 슬라이더(기본 0.60). 1.0과 달리 **Action 문장을 여기서 끝내지 않는다** — Action은 토픽 가중치가 만든 라벨일 뿐이므로 Action마다 근거 수집을 한 번 더 돌린다.

**3-2. 클러스터 중심 문장 — 기준선으로 고정 노출** *(신설)*

```
centroid_sentence = argmin_s dist(embed(s), centroid(cluster))
```

- 추천 순위표에 **섞지 않고** 상단에 별도 카드로 고정한다.
- 이 문장은 정의상 가장 전형적 → `max_sim_to_known`이 높아 quality 순위에서는 내려간다(예시 31위 / relevance 1위). 그게 정상이다.
- 그럼에도 지우지 않는 이유: **중심을 모르면 아래 목록이 얼마나 가장자리인지 판단할 수 없다.**

**3-3. 랭킹 산식과 3항 분해 UI** *(치환)*

```
quality = relevance
        × (1 − 0.5 · max_sim_to_known)     ← 아는 것과 유사하면 감점
        × (1 + 0.3 · combo_rarity)         ← 조합이 희소하면 가점
```

화면 요구사항 — 공식을 주석에 적는 것으로는 부족하다:
1. `relevance` · `known ▼` · `rarity ▲` · `quality`를 **각각 컬럼으로 분해**한다.
2. **relevance 정렬 대비 순위 이동량**(`▲23`, `▼8`)을 매 행에 찍는다.
3. `quality` / `relevance 단독` **토글**로 두 정렬을 나란히 대조한다.
4. relevance 1위였다가 감점되어 내려온 행은 색으로 강조하고 그 사유를 인라인으로 적는다.

> 계수 `α=0.5` · `β=0.3`은 **설계 시작값**이며 실측 캘리브레이션 대상이다.

## 4. STEP 10 — CAM → 최종 Insight 도출  `신규 설계`

### 문제 (기획안)
> CAM을 사람이 수기 작성한다. 구현 버전에서는 LLM이 이름·상황·페인포인트·인사이트 4필드를 한 번에 뱉어, **상황과 결론만 있고 그 사이가 비어 있었다.**

### 4-1. 4필드 → 4화면 펼침

| 1.0의 필드 | 2.0에서 담당하는 화면 |
|---|---|
| ① 이름 · Desire | STEP 08 페르소나 확정 |
| ② **상황 → 행동 → 장벽** | **STEP 10 CAM** ← 비어 있던 자리 |
| ③ 페인포인트 우선순위 | STEP 10-B 기회 영역 |
| ④ 인사이트 | STEP 11 |

### 4-2. CAM 매트릭스 — 행 구조 승계 · 열 단위 = Action

| 행 | 출처 | 비고 |
|---|---|---|
| 상황 `Context` | 1.0 승계 | |
| **행동 `Action`** | 1.0 승계 | 강조 행 |
| **장벽 `Barrier`** | **신설** | 상황과 결론 사이를 메우는 유일한 신설 행 |
| 키워드 `Keywords` | 1.0 승계 | |
| `Artifact` | 1.0 상세 페이지 행을 매트릭스로 승격 | |
| `Sentiment` | 1.0 승계 | |
| `Opportunity` | 1.0 승계 | ODI + 구역 |
| 근거 | 신설 | 건수 · 작성자 수 · 반례 유무 |

열은 `CL0-P1-A1` **계층 ID를 가진 구획**이다. 1.0도 열이 Action이었으나 각 열은 LDA 토픽 라벨일 뿐이었고, 2.0의 열은 Evidence Package와 1:1로 붙는다.

### 4-3. Action 상세 + Reviews
1.0 상세 페이지 구조(Keywords · Action · Context · Artifact · Sentiment · Reviews)를 승계하되 **Reviews를 다시 검색하지 않는다** — STEP 09 Evidence Package에서 확정된 인용이 그대로 올라온다.

### 4-4. 관측 / 추론 / 추측 — 기계 판정 *(신설)*

```
for 서술문 s in {상황, 행동, 장벽, 의도, 처방}:
    hits = retrieve(s, scope = 이 Action의 Evidence Package)
    if len(hits) >= 1 and lexical_overlap(s, hits[0]) >= 0.40:
        grade = 관측 ;  attach = 인용 원문 id
    elif derivable_from(s, 상위 서술):
        grade = 추론 ;  attach = 유도 경로
    else:
        grade = 추측 ;  attach = "근거 없음"
```

- **LLM에게 등급을 묻지 않는다.** 물으면 모델은 자기가 방금 쓴 문장을 변호한다. 등급은 검색 히트 여부라는 **기계적 사실**이다.
- 추측 건은 **지우지 않는다.** 지우면 서술이 매끄러워지지만 무엇이 근거 없이 쓰였는지 알 수 없게 된다.
- **추측 비율 > 30% → 페르소나 신뢰도 `하`**, STEP 11 종합에서 가중치 하향.

### 4-5. 정리한 것
- Opportunity Map을 이 화면에서 제거하고 **STEP 10-B 한 곳**으로 모았다. CAM의 Opportunity 행과 같은 값이라 두 번 그릴 이유가 없다.
- 화면 내 `8-A ~ 8-E` 표기를 제거하고 DCX STEP 번호로 통일했다.

## 5. STEP 11 — Insight → 컨셉  `구조적으로 모두 승계`

### 5-1. 11-A 인사이트 도출 (기존 화면 유지)
인사이트별 Pain Point · 기여 페르소나 · 경험차원 레이더(Computed·Connected·Shared) · Opportunity Score 막대. 확정 인사이트는 세션 종료 시 `known_insights`로 승격된다.

### 5-2. 11-B 경험 디자인 컨셉 **(아트보드 신설)**
1.0 컨셉 장표의 4블록 + 4D-CX 4분면을 **레이아웃까지 그대로** 승계한다. 이 화면은 발표 산출물의 형태 그 자체여야 한다.

| 블록 | 승계 | 2.0에서 더해지는 것 |
|---|---|---|
| 01 PERSONA | 이름/신분 · Pain Point · From Insight · 해시태그 | `CL0-P1` · `A1` 계층 ID 접지 |
| 02 SERVICE | 한 줄 정의 + 불릿 3개 | **근거 Action 칩**(ODI 포함) — 어느 Action이 어느 불릿을 낳았는지 |
| 03 EXPERIENCE | 1인칭 경험 서술 | **문장 단위 등급** — 앞부분 `관측`(현재), 뒷부분 `추측·미래`(아직 없는 제품). 1.0은 둘을 한 문단에 섞어 데이터와 제안의 경계가 없었다 |
| 04 INTERVIEW | 고관여자 인용 | **지지 / 반박을 함께 센다.** 반박은 폐기되지 않고 `컨셉 수정 요청`으로 남는다. 인터뷰 미달 컨셉은 장표에 `검증 대기`로 찍힌다 |
| 4D-CX | 정신적·물리적·문화적·시스템 4분면 | 표시 승계 + **산식 없음 명시**(1.0에도 근거 미문서화) |

### 5-3. 컨셉 목록표 *(신설)*
`From Insight` · `페르소나` · `근거 Action` · `ODI 합` · `인터뷰 진척` · `4D-CX 주축`을 한 표에 둔다. 1.0은 인사이트 7개 → 컨셉 16개였으나 계보가 장표 순서로만 남았다. 정렬 한 번으로 **근거가 얇은 컨셉**이 드러난다.

### 5-4. 반례가 기능을 낳는 경로
```
STEP 07 Edge 밴드 보존 → STEP 09 counter 인용 → STEP 10 반례 담론(A3)
→ STEP 11 SERVICE 세 번째 불릿 "기준기 대조 오차 공시"
```
반례를 어느 단계에서든 버렸다면 이 기능은 설계되지 않았다.

## 8. 어드민 — 프롬프트 · 파이프라인 상수  `신설`

### 8-1. 현재 상태 (코드 실측)

프롬프트는 **하드코딩 f-string으로 7곳**에 흩어져 있고, `model` · `max_tokens` · `timeout`은 `call_claude()` 호출 인자로 지점마다 따로 박혀 있다. 버전도 롤백도 없다.

| ID | STEP | 호출 지점 | max_tokens | timeout |
|---|---|---|---|---|
| `kw.expand` | 03 | `routers/keywords.py:34` | 8000 | 120 |
| `kw.converge` | 03 | `routers/keywords.py:72` | 8000 | 120 |
| `kw.suggest` | 03 | `routers/keywords.py:150` | 2000 | 60 |
| `filter.relevance` | 05 | `utils/text.py:28` | 배치 | 60 |
| `persona.generate` | 08 | `services/personas.py:67` | 8000 | 180 |
| `chat.qa` | 전 단계 | `routers/chat.py:56` | 2000 | 60 |
| `chat.edit` | 11 | `routers/chat.py:157` | 4000 | 120 |

07~11 설계가 요구하는 신설 5종: `cluster.label`(07) · `evidence.query`(09) · `cam.describe`(10) · `insight.synth`(11-A) · `concept.generate`(11-B).

### 8-2. 설계 원칙

**이 화면의 위험은 "편집"이 아니라 "편집한 뒤 무엇이 나빠졌는지 모르는 것"이다.** f-string을 UI로 빼는 순간 `{bk}` 같은 변수 누락이 컴파일 오류에서 **런타임 오류**로 내려앉고, 프롬프트 한 줄의 결과는 다음 세션에 가서야 드러난다. 그래서 중심은 편집기가 아니라 **린트 + 드라이런 대조**다.

| 기능 | 설계 |
|---|---|
| **프롬프트 세트 고정** | 세션은 시작 시점의 `prompt_set` 버전을 붙들고 끝까지 간다. 편집은 다음 세션부터 적용된다 — 그래야 "어제 세션과 오늘 세션이 같은 프롬프트였는가"가 항상 답해진다 |
| **레지스트리** | 행이 **코드 호출 지점과 1:1**. 화면에만 있는 가상 프롬프트를 만들면 코드와 어긋나는 순간 아무도 믿지 않는다. 미외부화 7건은 **읽기 전용** |
| **변수 린트** | 호출부 시그니처와 대조: (a) 호출부가 넘기지 않는 변수 (b) 템플릿이 쓰지 않는 변수 (c) 금지어 정규식 충돌. **오류가 있으면 활성화 버튼이 잠긴다** |
| **드라이런 대조** | 고정 샘플 20건 · 같은 seed로 이전/새 버전을 나란히. **종합 점수를 만들지 않는다** — 예시에서 v3는 장벽 생성률 11→19로 올렸지만 금지어 위반은 3→5로 늘었다. 지표가 엇갈릴 때 판단은 사람이 한다 |
| **가드레일** | STEP 09 코드 검증 4항목을 그대로 올린 것 + STEP 10의 **등급 자기판정 금지** 검사(출력에 "관측"·"추론" 문자열이 섞이면 경고) |
| **파이프라인 상수** | §7의 미결 항목이 사는 곳. <mark>잠정</mark> 배지는 **"기본값"이 아니라 "실측으로 정해질 값"**이라는 뜻이다. 각 행은 **바꾸면 다시 돌아야 하는 단계**를 같이 들고 있다. 지난 세션 결과는 당시 값으로 동결 |

### 8-3. 미결
권한과 감사 로그 — 프롬프트·상수 편집은 분석 결과를 바꾸는 행위다. 감사 로그는 전제이고, 편집 권한을 운영자 단일 역할로 둘지 단계별로 나눌지는 미정.

## 9. 듀얼 테마 — Linear · Liquid Glass

같은 `parts/*.body.html`을 시트만 갈아 끼워 두 벌로 렌더한다. 구조·밀도·타이포 스케일은 **공유**하고 표면 언어만 갈린다.

```
parts/*.body.html   (공유 · 구조와 내용 한 벌)
  ├ _shell.css          → <name>.dc.html          Linear
  └ + _shell.glass.css  → <name>.glass.dc.html    Liquid Glass
```

**14화면 × 2테마 = 28 아트보드.** 캔버스는 Linear 블록과 Glass 블록으로 나뉘고, 두 블록의 격자 위치가 같아 같은 화면을 세로로 대조할 수 있다. 내용을 고칠 때는 `parts/*.body.html` 한 곳만 고치고 `node build.mjs`를 돌린다.

### 9-1. 참조 문서 두 벌을 역할로 나눈다

| 문서 | 담당 |
|---|---|
| `DESIGN.apple.md` <span class="qu">(getdesign.md/apple)</span> | **규율** — 지면 · 색 · 타이포 · 라운드 스케일 · 버튼 문법 |
| `DESIGN copy.md` <span class="qu">(Liquid Glass)</span> | **재질** — 블록의 유리 질감 |

### 9-2. 첫 시도에서 틀렸던 것

첫 버전은 지면에 홍채 그라디언트 8겹을 깔고 블록을 반투명하게 만들었다. **방향이 반대였다.** Apple md가 정면으로 반박한다:

> *"**No decorative gradients.** Apple is the rare luxury-brand site with zero gradient-based design tokens."*
> *"Don't use gradients as decorative backgrounds; atmosphere comes from photography."*

배경을 화려하게 칠하면 블록은 그 위에 얹힌 구멍이 될 뿐 **유리가 되지 않는다.** 떠 보이는 힘은 배경이 아니라 **블록 자체의 재질**에서 나와야 한다.

### 9-3. 다시 만든 것 — 지면을 비우고 재질로 세운다

**지면**: 장식 없는 평평한 회색 파치먼트 `#e6e6ec`. Apple 파치먼트(`#f5f5f7`)보다 한 계단 낮췄다 — 유리판이 들리려면 **바닥이 유리보다 어두워야** 한다. 상단 내비는 Apple 스펙대로 진짜 검정(`#000`).

**블록**: 리퀴드 글래스 재질 4겹.

| 겹 | 구현 | 역할 |
|---|---|---|
| ① 상단 스페큘러 | `inset 0 1.5px 0 rgba(255,255,255,1)` + 상단 렌즈 `inset 0 18px 24px -18px` | 광원이 위에 있다는 신호 |
| ② 림 굴절 | `::before` + `mask-composite:exclude` 1.5px 그라디언트 링 (좌상단 최대 밝기 → 중앙 어둠 → 우하단 재상승) | 테두리에서 빛이 꺾인다 |
| ③ 하단 두께 | `inset 0 -16px 26px -18px rgba(29,29,31,.30)` | 유리판의 두께감 |
| ④ 접지 그림자 | `0 1px 2px` (근접) + `0 16px 40px -14px` (원거리) 2단 | 바닥에서 떠 있다 |

본체는 `backdrop-filter: blur(30px) saturate(190%)` 위에 176° 흰색 그라디언트(.94→.60→.82)를 얹었다. hover 시 `translateY(-1px)` + 그림자 확장 480ms.

### 9-4. Apple 규율 적용

| 항목 | 값 |
|---|---|
| 액센트 | **단일** Action Blue `#0066cc` — 인디고 전량 교체. 포커스 `#0071e3` |
| 잉크 | `#1d1d1f` / `#333333` / `#7a7a7a` |

| 프레스 | 전역 `transform: scale(.95)` |

### 9-5. 의도적으로 어긴 것

- **"카드에 그림자 금지"** — Apple md는 그림자를 제품 사진에만 허용한다. 그러나 리퀴드 글래스는 정의상 떠 있어야 하므로 카드에 접지 그림자를 넣었다. 두 문서가 충돌하는 유일한 지점이고, 사용자 요구("블록 자체가 떠야 한다")를 따랐다.
- **세 등급 색(관측·추론·추측)** — Apple은 단일 액센트를 요구하지만 이건 "클릭하세요" 신호가 아니라 **데이터 인코딩**이라 남겼다. 다만 채도를 Apple 톤에 맞춰 낮췄다.
- **본문 17px** — Apple의 시그니처지만 이 화면은 마케팅 페이지가 아니라 고밀도 분석 도구다. 밀도 스케일은 Linear를 유지하고 **자간 규율과 가중치 사다리만** 가져왔다.

SVG 데이터 마크는 속성 셀렉터(`[fill="#4f5bc8"]`)로 Action Blue에 매핑해 차트 색이 테마를 따라간다.
