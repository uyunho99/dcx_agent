# DCX 1.0 → 2.0 · 단계별 방법론 변화

- 작성 2026-10-02 · 기준: 1.0 = 「DCX 1.0 원본 프로세스 상세」(GS E&C × 한양대 DCX Lab, 2023 최종발표), 2.0 = `docs/development/` 기획 · 결정 기록(D-0xx ~ D-2xx)
- 목적: 기술 구현이 아니라 **방법론 차원**에서 무엇을 이어받고 무엇을 바꿨는지 한눈에 보기. 근거가 필요하면 괄호 안 결정 번호를 따라간다.
- 진행 상태: 0~5단계 구현 · 머지 완료 / 6~8단계 기획 · 설계 완료, 구현 전(6단계 구현 계획까지 승인)

---

## 0. 한 장 요약

| 1.0 STEP | 2.0 단계 | 한 줄 변화 |
|---|---|---|
| 01 비즈니스 문제 정의 | 0 입력 | 회의로 합의하고 끝나던 선언이 **양식이 되어 모든 단계에 자동 전달**된다 |
| 02 타겟 · 채널 선정 | 0 입력 | 타겟은 수집을 좁히지 않는 **느슨한 범위**가 되고, 채널은 정해진 목록에서 고른다 |
| 03 카테고리 · 키워드 + 3V | 1 키워드 | 사람의 발산 · 수렴 워크숍 → **AI가 4라운드 발산 · 수렴, 사람은 라운드마다 승인 · 거절** |
| 04 소셜 리스닝 수집 | 2 크롤링 | 대표 × 마스터 키워드 교차 → **키워드 단독(제품명 없이)**. 목록을 먼저 보고 사람이 거른 뒤 본문 수집 |
| 05 전처리 | 3 전처리 | 규칙 제거를 줄이고 판단은 뒤로 넘긴다. 글의 **의미 벡터**를 한 번 만들어 뒤 단계가 같이 쓴다 |
| 06 삼중 준지도 학습 | 4 라벨링 · 5 학습 | 사람 3% · 있다/없다(0/1) → **AI 두 명이 전량을 경험 태그로 판정**, 등급은 규칙으로 계산 |
| 07 Ward → Touch Point | 6 L1 Cluster | 같은 방법. 단어 대신 **뜻**으로 묶고, 군집 품질을 화면에 보여 준다 |
| 08 SNA → Actor | 6 L2 Persona | 같은 방법. 클러스터를 넘나드는 Actor **통합은 하지 않는다**(제안만) |
| 09 LDA → Action | 6 L3 Context | 같은 방법(토픽 수 2~10). 이름 확정이 정식 단계가 된다 |
| (없음) | 7 근거 탐색 | **새 단계.** Context마다 근거 원문 10건을 골라 묶는다 — 희소한 목소리 · 반례 · "새 발견" 구분 |
| 10 CAM · Opportunity Map · 경험 평가 | 8 페르소나 카드 · Opportunity Map | 틀은 같다. 모든 서술에 **원문 인용과 관측 / 추론 / 추측 표시**가 붙는다 |
| 11 Pain Point 맵핑 → Insight → 컨셉 | 8-E 인사이트 · 8-F 컨셉 | AI가 초안, 사람이 채팅으로 고치고 확정. 트렌드 리포트 대조 · 인터뷰는 빠졌다 |
| 12 공간별 Actor 병행 트랙 | (없음) | 빠졌다. 1.0은 건설사 평면 단위였고, 2.0은 제품 도메인이 매번 달라서 |

## 1. 단계별 비교

### 0단계 · 입력 ← 1.0 STEP 01 · 02

**1.0** 연구 과제명 · 목표 · 통계 근거를 문서와 회의로 합의했다. 원본 문서도 "이 선언이 이후 절차에 자동으로 전파되는 장치는 없다"고 적는다. 타겟은 인구통계 · 트렌드 조사로 11개 군을 정하고, 군마다 맞는 커뮤니티 11곳을 사람이 직접 골랐다(게시글을 열어 맥락이 보이는지까지 확인).

**2.0**
- 문제 정의를 **15칸짜리 양식**으로 받는다. 한 줄 정의 · 리서치 질문 · 분석 목적 · 핵심 지표 · 사내 제약 · 브랜드 포지셔닝 · 이미 아는 것 + 제품군 · 연령 · 성별 · 가구 · 생애주기 · 미래 고객. 이 내용이 이후 **모든 AI 판단의 첫 줄**에 붙는다(D-017).
- 선언과 어긋나는 결과는 **막지 않고 "방향과 다를 수 있음" 표시만** 한다. 제약을 절대 조건으로 걸면 의외의 발견까지 잘리기 때문이다(D-012).
- 타겟은 **수집을 좁히는 조건이 아니다.** 1.0처럼 "육아맘" 글을 미리 지우지 않고, 각 글이 대상과 관련 있는지는 4단계 판정이 본다. 타겟 선언은 8단계에서 "선언 밖 고객 → FUTURE" 표시에 쓴다(D-210).
- 채널은 네이버 카페 · 블로그 · 유튜브 댓글 · 뽐뿌 · 클리앙 중에서 **고른다**(D-035). 1.0의 "타겟별 맞춤 채널 리서치"는 없어졌다.
- **새 개념: 이미 아는 것(Known Insight).** 실무자가 이미 아는 이야기를 처음부터 적어 두고, 뒤에서 "새 발견"과 구분하는 데 쓴다(D-016).

> 예: 1.0이라면 "1인 가구 남성 → 디시 자취 갤러리"를 사람이 찾아야 했다. 2.0은 "LG 에어컨 · 30~40대 · 맞벌이"를 적고 채널 5개 중 고른다. 대신 그 커뮤니티 특유의 목소리를 잡는 정밀함은 줄었다.

### 1단계 · 키워드 ← 1.0 STEP 03

**1.0** 연구진이 22개 카테고리를 펼치고(발산) → 지우고 → 8개 묶음 + 해시 문장으로 모으고(수렴) → 다시 펼치고 → 8대 24세부로 확정했다. 3V(양 · 다양성 · 추세)를 데이터랩 · 썸트렌드로 보고 키워드를 **탈락시켰다.**

**2.0**
- 발산 · 수렴을 **AI가 4라운드로** 한다. R1 육하원칙 · 해야 할 일(JTBD) → R2 대체 · 결합 · 응용 → R3 균형 맞춰 수렴 → R4 역발상 · 극단 사용자 · 빠진 공간. 네 라운드는 **항상** 다 돈다(D-020).
- 분류 축이 주거 카테고리 대신 **물리 · 심리 · 행동 3축**이 된다. 어느 제품에나 쓸 수 있게(D-021).
- 사람은 라운드 전에 방향을 주고, 라운드 뒤에 승인 · 거절 + **사유**(관련 낮음 · 흔함 · 문장형 · 분류 틀림)를 단다. 이 피드백이 **다음 라운드에 그대로 반영된다**(D-022).
- 3V는 **탈락 기준이 아니라 표시**다. 검색량이 적어도 버리지 않고 배지만 단다(D-027). 키워드가 실제로 글을 모으는지는 수집 단계 게이트에서 본다(D-026).
- 현재 상태: 검색량 데이터(네이버 검색광고)는 키를 받을 수 없어 **미연결**이다. 그래서 지금은 3V 중 "양" 신호 없이 축 균형만으로 수렴한다(B-110).

### 2단계 · 크롤링 ← 1.0 STEP 04

**1.0** "대표 키워드(미래 주거 · 공간) × 1,2인 가구 마스터 키워드"를 **교차 결합**해 검색했다. 제목 · 본문 · 댓글 · 날짜를 모았다(64만 건).

**2.0**
- 검색어는 **확정 키워드 단독**이다. "에어컨 러닝"이 아니라 "러닝". 제품명을 붙이면 제품을 직접 언급한 글만 모여 **제품 밖 경험**을 놓친다(D-014). 1.0의 교차 결합이 하던 "관련성 거르기"는 4단계 판정이 맡는다.
- 수집을 두 번에 나눈다. **목록 먼저** → 사람이 "글이 0건이거나 거의 안 나오는 키워드"를 빼고 → 본문 · 댓글 수집(D-033). 비싼 본문 수집 전에 사람이 한 번 거른다.
- 모으는 것은 1.0과 같다(제목 · 본문 · 댓글 · 날짜). 목표 규모는 100만 건 이상(D-031).

### 3단계 · 전처리 ← 1.0 STEP 05

**1.0** 광고어 포함 글 삭제 + "육아맘 · 아기랑" 같은 **타겟 무관어 포함 글 삭제** + 채널 정형 문구 치환 + 형태소 분석(OKT).

**2.0**
- 광고어 · 정형 문구 제거는 그대로.
- **타겟 무관어로 지우지 않는다.** 위 0단계와 같은 원칙 — 규칙은 앞에서 거칠게 자르지 않고, 판단은 뒤에서 글 단위로 한다.
- 형태소 분석은 그대로 한다(분석기만 Kiwi로 교체, D-102). 6단계 네트워크 · 토픽 분석의 재료다.
- **추가:** 모든 글의 **의미 벡터**(뜻을 숫자로 바꾼 것)를 여기서 한 번 만든다. 라벨링 · 학습 · 군집 · 근거 검색이 모두 같은 벡터를 쓴다.

### 4 · 5단계 · 라벨링 · 학습 ← 1.0 STEP 06 (가장 크게 바뀐 곳)

**1.0** 사람이 전체의 3%(약 1만 1천 건)에 **유용함(1) / 무용함(0)** 을 달고(코더 2명 → 2명 → 판정자), LSTM과 CNN이 합의한 것을 정답 삼아 GRU가 나머지를 판정했다. 결과는 유용 / 무용 두 칸뿐이었다.

**2.0**
- **판정자가 사람 → AI 두 명**(Jev · GPT)이고, 표본이 아니라 **전량**을 본다.
- **0/1 대신 경험 태그**를 단다.
  - 대상 관련성(anchor) — 우리 제품 · 문제와 관련 있나
  - 경험 6차원 — 감각 · 감정 · 생각 · 행동 · 관계 · 결과
  - 상황 — 언제 · 어떤 맥락인지 드러나나
  - 무관하면 사유(광고 · 니즈 없음 · 순수 비방 · 기타), 관련 있으면 신호(불편 · 미충족 · 우회법 · 기쁨)
- 등급은 사람도 AI도 정하지 않고 **규칙이 계산**한다. Core = 관련 + 경험 차원 2개 이상 + 상황 / Supporting = 관련 + 차원 1개 이상 / Non = 나머지.
- **사람은 두 AI가 다르게 본 글 + 판정 실패 + 무작위 감사만** 본다(D-143 · D-145). 기획안에 있던 목표 오류율(α) 계산 · 사전 캘리브레이션은 당분간 뺐다(D-144).
- 5단계는 두 AI가 합의한 라벨로 **가벼운 모델을 만들어 저장**한다. 다음 세션부터는 이 모델로 AI 호출 없이 판정할 수 있다(D-108 · D-130). 1.0의 모델이 "그 프로젝트 안에서 쓰고 버리는 것"이었다면, 2.0은 **세션을 넘어 재사용**한다.

> 예: "에어컨 틀고 자면 아침에 목이 칼칼해서 결국 타이머 2시간으로 맞춰요" — 1.0이면 그냥 "유용(1)". 2.0이면 관련 ○ · 감각(목 칼칼) · 행동(타이머) · 상황(잠잘 때) · 신호 = 우회법 → **Core**. 뒤 단계가 "어떤 종류의 경험인지"를 알고 시작한다.

### 6단계 · 구획 ← 1.0 STEP 07 · 08 · 09

1.0의 **세 층 구조와 방법을 그대로 따른다**(사용자 결정: "1.0으로만", D-204). 이름만 바뀐다 — Touch Point → **Cluster**, Actor → **Persona**, Action → **Context**. ID도 1.0의 3자리(`422`)처럼 `CL4-P2-C2`로 이어진다.

| 층 | 1.0 | 2.0 | 바뀐 점 |
|---|---|---|---|
| L1 Cluster | Ward 군집 · 실루엣 | Ward로 개수 진단 → K-means | 단어가 아니라 **뜻(의미 벡터)으로** 묶는다. "워치랑 이어폰 둘 다 챙기기 귀찮다"와 "기기 두 개 차는 게 번거롭다"가 같은 군집이 된다(D-205) |
| L2 Persona | 명사 동시출현 네트워크 → Desire 문장 | 같음 | 1.0은 클러스터가 달라도 Desire가 비슷하면 **합쳤다.** 2.0은 "비슷함" 배지만 보이고 합치지 않는다. 묶는 일은 8-E 인사이트가 맡는다(D-206) |
| L3 Context | Actor 안 LDA 토픽 | 같음(토픽 수 2~10 중 가장 일관된 수) | — (D-235) |

- **품질을 보여 준다.** 1.0은 실루엣 0.04 수준이었고 "최종 판단은 사람이 원문을 읽고 내렸다". 2.0은 군집마다 응집 · 경계 · 안정성 · **채널 편중**(한 채널이 80% 이상이면 경고)을 화면에 보인다. 진단만 하고 자동으로 쪼개거나 합치지 않는다.
- **사람 확정이 정식 관문이 된다.** AI가 이름 · Desire · Goal 초안을 내고, 사람이 Cluster → Persona → Context 순서로 확정해야 다음으로 넘어간다(6-A · 6-B · 6-C).

### 7단계 · 근거 탐색 ← 1.0에 없던 단계

**1.0** CAM을 쓸 때 연구진이 마이크로 세그먼트의 원문을 읽으며 맥락을 파악했다. 어떤 원문을 근거로 삼았는지는 사람의 손에 있었다.

**2.0** 이 "원문 읽고 근거 고르기"를 정식 단계로 만들었다.
- Context마다 경험 차원별로 **소비자 말투의 질문 문장 8개**(감각 · 감정 · 생각 · 행동 · 관계 · 결과 · 반대 사례 · 나머지)를 만들어 그 Context 안에서만 원문을 찾는다.
- 찾은 후보에서 **근거 10건**을 고른다. 기준은 대표성 + **서로 다른 이야기**(비슷한 글 10개 대신 다양하게) + **희소한 목소리 최소 2건**(군집 가장자리의 불편 · 미충족 글).
- **반례**(같은 Context인데 반대로 말하는 글)를 따로 모은다.
- 이미 아는 이야기와 겹치는 원문은 깎지 않고 **"전체 / 새 발견" 두 탭**으로 나눈다. 사람이 "아는 얘기로 넘기기"를 누르면 다음 검색의 새 발견에서 빠진다.
- 이 묶음(Evidence Package)이 8단계의 **유일한 입력**이다. 8단계는 여기 없는 말을 할 수 없다.

### 8단계 · 페르소나 · Opportunity Map ← 1.0 STEP 10

**1.0** Actor마다 CAM(Desire · Goal · Pain Point + Action별 만족도 · 기회 점수) → Opportunity Map 6구역 → Underserved 7개 Action → Computed / Connected / Shared 레이더.

**2.0** **틀은 이어받는다.** CAM은 페르소나 카드의 8-A(고객 맥락 맵)로, Opportunity Map은 같은 기준선 · 같은 6구역(Exciting ~ At-risk)으로, 레이더도 같은 세 축으로. 바뀐 것은 "무엇을 믿을 수 있는지"를 드러내는 장치다.
- 페르소나 수 · 이름 · Desire는 6단계 확정값을 **그대로** 쓴다. 8단계가 다시 지어내지 않는다.
- 모든 칸에 **원문 인용**이 붙고, 등급이 표시된다. 🟢 관측(원문에 그대로 있음 · 코드가 확인) / 🟡 추론 / 🔴 추측(근거 없음). 1.0에서 "결론 → 원문 추적"은 문서에서 사람이 유지했다면, 2.0은 **시스템이 확인**한다.
- 근거가 없으면 **빈칸으로 남긴다.** 가격 민감도 같은 속성을 그럴듯하게 채우지 않는다.
- **반례 Context**를 카드에 표시한다.
- 처방(8-D)은 0단계의 사내 제약에 걸리는지 **검사**하고, 선언한 타겟 밖이면 **FUTURE**를 붙인다.
- Opportunity Map에 **★ "몰랐고 기회도 큰 지점"**(새 발견 근거가 많고 기회 점수가 높음)을 표시한다.
- 점수 산식(만족도 = 감성사전 점수, 중요도 = 토픽 비중)은 1.0을 따르되, 1.0 장표 산식이 확인될 때까지 **"잠정"** 표시를 단다.

### 8-E · 8-F · 인사이트 · 컨셉 ← 1.0 STEP 11

**1.0** Pain Point를 사람이 7개 범주로 묶고 → 트렌드 리포트와 대조 → 인사이트 7개 → 아이디어 워크숍 → 4블록 컨셉(PERSONA · SERVICE · EXPERIENCE · INTERVIEW) → 고관여자 인터뷰로 검증.

**2.0**
- AI가 페르소나 카드 전체에서 **인사이트 3~8개 초안**을 낸다. 각 인사이트는 기여한 Context ID와 기회 막대를 매단다(1.0의 "인사이트에 Action 역으로 매달기"와 같다).
- 사람은 오른쪽 **채팅으로 고친다**("인사이트 2를 두 개로 나눠줘"). 숫자(레이더 · 막대)는 AI가 쓰지 않고 코드가 다시 계산한다(D-208).
- 컨셉은 PERSONA(🔴 합성값 표시) · Pain Points(원문) · JOURNEY 지금 / 앞으로 + **4D-CX** 경험의 장 표시. 1.0의 4블록 중 SERVICE · EXPERIENCE는 JOURNEY로 합쳐졌다.
- **빠진 것:** 트렌드 리포트 대조, 고관여자 인터뷰 검증(기획안 보류 · 백로그).
- 확정한 인사이트는 **다음 세션의 "이미 아는 것" 추천**으로 이어진다(D-217).

## 2. 단계를 가로지르는 변화

1. **사람의 자리가 "직접 만들기" → "AI 초안 검토 · 확정"으로 옮겼다.** 1.0의 사람 판단 6곳(채널 · 카테고리 수렴 · 3V · 3% 라벨 · Desire 해석 · Pain Point 묶기)은 2.0에서 키워드 라운드 승인 · 수집 게이트 · 라벨 불일치 검수 · 6단계 이름 확정 · 인사이트 확정이 된다. 사람이 하는 일은 줄었지만 **관문**은 더 많다.
2. **관련성 판단을 앞에서 뒤로 미뤘다.** 1.0은 교차 키워드 · 타겟 무관어 삭제로 앞에서 걸렀다. 2.0은 넓게 모으고 글 하나하나를 판정한다. 목적은 **제품 밖 경험**을 놓치지 않는 것.
3. **"유용함" 한 칸 → 경험의 종류.** 0/1 대신 6차원 · 상황 · 신호를 달아, 뒤 단계가 "무슨 경험인지"를 알고 움직인다.
4. **결론 → 원문 추적을 시스템이 보장한다.** 인용 위치를 코드가 원문과 대조하고, 관측 / 추론 / 추측을 구분해 보여 준다.
5. **"이미 아는 것"을 다룬다.** 1.0에는 없던 개념. 0단계 입력부터 근거 탐색 · 인사이트까지 "새 발견"을 따로 보이게 한다.
6. **1회성 프로젝트 → 반복 가능한 세션.** 1.0은 주거 도메인 6개월 프로젝트 한 번이었다. 2.0은 0단계 양식만 바꾸면 어느 제품에나 돌고(LG 에어컨 · 아산병원 데모), 버전 · 학습 모델 · 확정 인사이트가 다음 세션으로 이어진다.
7. **막지 않고 표시한다.** 선언 위반 · 검색량 부족 · 군집 품질 낮음 · 채널 편중 모두 자동 탈락 대신 경고를 붙이고 판단은 사람에게 둔다.

## 3. 그대로 이어받은 것

- 11 STEP의 큰 흐름: 문제 정의 → 키워드 → 수집 → 정제 → 걸러내기 → 군집 → 세그먼트 → 행동 → 기회 → 인사이트 → 컨셉
- **3층 구조**(Touch Point / Actor / Action = Cluster / Persona / Context)와 각 층의 방법(Ward · 네트워크 모듈성 · LDA)
- **Actor를 인구통계가 아니라 Desire 문장으로 정의**한다는 DCX의 핵심 주장
- 제목 + 본문 + **댓글**을 한 단위로 보는 것
- Opportunity Map 기준선 · 6구역, Computed / Connected / Shared, 4D-CX 경험의 장
- 데이터가 못 하는 것을 숨기지 않는 태도 — 2.0에서는 "잠정" · 🔴 추측 · 빈칸 · "미연결" 표시로 이어진다
