# 키워드 R2 잠금 · R1→R3 바로 진행 · R3 수렴 / R4 마지막 발산 — 기획

기준: origin/main `a63ffa9`(운영 8400과 같은 코드, 지시문 r1.v3 · r2.v2 · r3.v2 · r4.v2)

## 문제
세라젬 세션(`s89d92341bdb340b0bd7a5943a1c86dc7`, 질문 "귀농·귀촌인은 왜 내려왔고, 내려온 뒤 집에서 몸과 생활이 언제 기대와 어긋나는가?")에서 R1은 의도대로 나왔다(승인 67 · 거절 20). 그런데 R2(134개, 미확정)는 R1과 가까운 단어로만 채워졌다.

| R1 승인 | R2 생성 |
|---|---|
| 시골집결로 · 전원집곰팡이 · 시골집온도차 · 전원욕실추위 | 시골집외풍 · 전원바닥냉기 · 농가난방편차 · 주말집예열 · 시골집동파 · 전원수도녹물 · 농가지하수 · 시골집석회물 … |

"시골집 · 전원 · 농가 · 주말집 + 집안 불편"이 반복된다. R2 지시문(SCAMPER 대체·결합·응용)이 "승인 키워드 변형"을 요구하다 보니 앞말이나 사물만 바꾼 인접어가 나온다. 새로운 상황은 거의 생기지 않는다.

## 결정 (사용자, 2026-10-02)
- **R2를 로직에서 잠근다.** R1을 저장한 뒤 "다음 라운드 생성"을 누르면 R3가 생성된다. 화면 구성(단계 표시 R1~R4 · 최종, 문구, 버튼)은 바꾸지 않는다.
- **R3 = 수렴 + 약간의 균형.** 지금 R3는 "부족한 축 채우기"가 중심이다. 이를 비슷한 단어를 주제별로 모아 그 주제를 더 깊게 채우는 쪽으로 바꾸고, 축 균형은 보조로만 맞춘다.
- **R4 = 마지막 발산 · 정리.** R2가 맡던 확장(대체 · 결합 · 응용)을 R4가 흡수한다. R4는 기존 역발상 · 제거 · 극단 사용자와 함께 아직 다루지 않은 상황을 찾아 목록을 마무리한다.

|---|---|---|

## 동작 (요약)
- 서버
  - 잠긴 라운드 목록(`{2}`)을 한곳에 둔다.
  - 잠긴 라운드는 생성 · 다시 생성 · 확정 요청을 거절한다(안내: "R2는 사용하지 않습니다. R1 다음은 R3입니다").
  - 순서 검사에서 잠긴 라운드는 건너뛴다. R3는 R1만 확정되어 있으면 생성할 수 있다.
- 기존 세션
  - 세라젬처럼 R2가 생성만 되고 확정되지 않은 경우: 그 R2 키워드는 없는 것으로 본다. 키워드 화면 응답에서 빠지고, R3 생성 때 중복 판정에도 쓰지 않는다. 저장 파일은 지우지 않는다.
  - 이전에 R2를 이미 확정한 세션: 승인된 R2 키워드는 그대로 승인 목록에 남고, R2 기록도 그대로 보인다.
- 화면 로직(모양은 그대로)
  - "다음 라운드 생성"을 R1에서 누르면 R3를 만든다.
  - 커버리지를 받는 동안 R1에서 다음으로 넘어가는 것을 막는다. 지금 R2→R3 경계에 있는 막음을 R1→R3 경계로 옮긴다.
  - R1에서 남긴 방향 지시는 R3 몫으로 저장한다.
  - 저장되지 않은 R2만 있는 세션은 R1 화면으로 열리고, "다음 라운드 생성"이 활성화된다.
  - 단계 표시줄의 R2 칸은 그대로 두고 "다가올 단계"로 남는다.
- R3 지시문 r3.v3 (수렴 + 약간 균형)
  1. 승인 키워드 · 직접 추가 · 이동 키워드를 의미가 비슷한 주제로 묶는다. 예: "겨울 냉기 · 결로", "마을 관계 거리", "귀촌 후회 · 역귀촌".
  2. 사용자 신호가 강한 주제(승인 많음 · 직접 추가 · 이동)를 골라, 같은 상황 안의 다른 사물 · 현상 단어로 채운다.
  3. **앞말(맥락어)만 바꾼 변형은 금지한다.** 예: 시골집외풍 ↔ 전원외풍 ↔ 농가외풍은 한 단어로 본다.
  4. 생성량의 약 7할은 주제 수렴, 약 3할은 가장 얇은 축 보완에 쓴다. 커버리지 신호가 있으면 이 3할에 반영한다.
  5. 거절 사유 · 과거 0건 키워드는 지금처럼 피한다.
- R4 지시문 r4.v3 (마지막 발산 · 정리)
  1. R1 · R3 승인 키워드의 주제를 훑어 아직 다루지 않은 상황 · 사람 · 시점을 찾는다.
  2. SCAMPER 대체 · 결합 · 응용(이전 R2)과 역발상 · 제거 · 극단 사용자(기존 R4)를 함께 써서 새 상황을 만든다.
  3. 기존 주제의 인접어, 앞말만 바꾼 변형은 금지한다. 새 단어마다 기존과 다른 상황이어야 한다.
  4. 정리: 결과 목록이 세 축에 고르게 걸치도록 마무리한다.
- 두 지시문 모두 r1.v3의 형태 규칙(맥락어 + 핵심어 두 단어 이하 · 8자 이하)을 그대로 쓴다. 최소 생성 수는 R3 60 · R4 60으로 유지한다.

## 수용 기준
- AC1: R1 확정 후 R3 생성 요청이 성공한다(R2 없이). R1 미확정이면 지금처럼 "이전 라운드를 먼저 확정하세요"로 막힌다.
- AC2: R2 생성 · 다시 생성 · 확정 요청은 거절된다(4xx, 안내 문구). R2 작업은 시작되지 않는다.
- AC3: 화면에서 R1 저장 후 "다음 라운드 생성"을 누르면 R3 생성이 시작되고 단계가 `r3`로 저장된다.
- AC4: 저장되지 않은 R2가 있는 세션(세라젬 형태)은 키워드 화면이 R1로 열리고 R2는 선택 목록에 없다. R3를 생성하면 R2 미확정 단어가 중복으로 걸러지지 않는다.
- AC5: R2를 이미 확정한 이전 세션은 R2 승인 키워드 · 기록이 그대로이고 R3 · R4 진행이 가능하다.
- AC6: R3 생성 지시문은 r3.v3이고, 주제 묶음 · 맥락어 변형 금지 · 수렴 7할 / 균형 3할 문구를 포함한다. R4는 r4.v3이고, 대체 · 결합 · 응용 + 역발상 · 제거 · 극단 사용자 · 인접어 금지 · 정리 문구를 포함한다. 둘 다 r1.v3의 형태 규칙을 포함한다.
- AC7: 화면 구성(단계 표시 · 문구 · 버튼 배치)은 바뀌지 않는다.
- AC8: 기존 백엔드 · 프런트 테스트와 린트 · 빌드가 통과한다.
- AC9(실제 LLM 확인, 결과 보고용): 세라젬 세션 복사본에서 R1→R3를 실제로 생성하고, R2 대비 "앞말만 바꾼 인접어" 비율이 줄었는지 사례로 보고한다. 결과는 판정용이 아니라 사용자 판단 자료다.

## 제외 범위
- 화면 문구 · 단계 표시 · 레이아웃 변경(R2 칸 제거 등).
- R1 지시문 · 형태 규칙(D-325) 변경, 최소 생성 수 변경.
- 기존 세션 저장 데이터 이전 · 삭제.
- 별도 실행 `kw-popover-spacing`(팝오버 · 띄어쓰기)의 범위.

## 위험
- R3가 수렴 쪽으로 기울면 R1의 편향(예: 집안 냉기 주제)이 커질 수 있다 → 균형 3할과 R4 발산으로 보완한다. AC9 사례로 확인한다.
- "앞말만 바꾼 변형 금지"를 모델이 어길 수 있다 → 지시문에 예시를 넣는다. 서버 측 자동 판정은 이번 범위에서 제외한다(필요하면 백로그).
- 프롬프트 버전이 바뀌므로 이후 생성 결과는 이전 세션과 바로 비교하기 어렵다 → 라운드 기록에 promptVersion이 남는다.
- 운영(8400)에는 이 브랜치를 배포해야 반영된다. 배포는 사용자가 따로 요청한다.
