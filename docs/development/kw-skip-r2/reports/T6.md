# T6 — Locked pending round feedback and manual keyword provenance

## Rule and implementation

Following design sections 2/5 and D-328, feedback excludes `reject`, `move`, `approve`, and `unreject` events when their `kwId` occurs in a locked, uncommitted round's keywords and does not occur in the session's top-level keywords. The filter uses keyword membership rather than the event's round tag. Top-level keywords take precedence, preserving committed history. Unlocking R2 or marking it committed preserves its feedback.

`direction` and `add` events always survive, including direction events tagged round 2 by the previous frontend. Filtering happens before cumulative rendering, so hidden restoration events cannot cancel visible rejections with the same spelling. Events without an identified hidden keyword remain unchanged. The events JSONL file is never rewritten; only derived Markdown is refreshed. The writer reads session state from the same directory as its events while under the existing storage lock.

Manual additions use the highest stored round that is not both locked and uncommitted, defaulting to 1. The keyword and its `add` event receive the same round.

GET feedback preview reads the cached Markdown. This fix applies when that Markdown is regenerated (including subsequent round inputs and event writes); it does not migrate already cached files on a read-only GET.
