## Final DDL

`CREATE IF NOT EXISTS` is used for new collection databases. Epoch timestamps are seconds. NULL adapter cursors are stored as the empty string so SQLite composite primary keys deduplicate first-page tasks.

```sql
CREATE TABLE IF NOT EXISTS runs (
 run_id TEXT PRIMARY KEY, sid TEXT NOT NULL, kind TEXT NOT NULL CHECK(kind IN ('list','detail')),
 pid INTEGER NOT NULL, status TEXT NOT NULL, started_at REAL NOT NULL,
 heartbeat_at REAL NOT NULL, config_json TEXT NOT NULL
);
CREATE TABLE IF NOT EXISTS list_tasks (
 kw TEXT NOT NULL, source TEXT NOT NULL, cursor TEXT NOT NULL DEFAULT '',
 status TEXT NOT NULL DEFAULT 'pending' CHECK(status IN ('pending','done','failed')),
 fetched INTEGER NOT NULL DEFAULT 0, total_hint INTEGER,
 attempts INTEGER NOT NULL DEFAULT 0, last_error TEXT,
 PRIMARY KEY(kw, source, cursor)
);
CREATE TABLE IF NOT EXISTS keyword_meta (
 kw TEXT PRIMARY KEY, kw_axis TEXT NOT NULL, kw_sub TEXT NOT NULL, kw_order INTEGER NOT NULL
);
CREATE TABLE IF NOT EXISTS urls (
 url_norm TEXT NOT NULL, source TEXT NOT NULL, kw TEXT NOT NULL,
 kw_axis TEXT NOT NULL, kw_sub TEXT NOT NULL, snippet TEXT NOT NULL, title TEXT NOT NULL,
 date TEXT, src_meta_json TEXT NOT NULL,
 status TEXT NOT NULL DEFAULT 'pending'
 CHECK(status IN ('pending','leased','done','failed','excluded','filtered')),
 lease_until REAL, lease_run_id TEXT, attempts INTEGER NOT NULL DEFAULT 0,
 last_error TEXT, doc_count INTEGER NOT NULL DEFAULT 0, first_seen_kw_order INTEGER NOT NULL,
 fetch_level TEXT, access TEXT, retry_at REAL, filter_rule TEXT,
 UNIQUE(url_norm, source)
);
CREATE TABLE IF NOT EXISTS url_hits (
 url_norm TEXT NOT NULL, source TEXT NOT NULL, kw TEXT NOT NULL,
 kw_axis TEXT NOT NULL, kw_sub TEXT NOT NULL, kw_order INTEGER NOT NULL,
 PRIMARY KEY(url_norm, source, kw)
);
CREATE TABLE IF NOT EXISTS snapshots (
 snapshot_id TEXT PRIMARY KEY, created_at REAL NOT NULL, url_count INTEGER NOT NULL, hash TEXT NOT NULL
);
CREATE TABLE IF NOT EXISTS snapshot_urls (
 snapshot_id TEXT NOT NULL, url_norm TEXT NOT NULL, source TEXT NOT NULL,
 PRIMARY KEY(snapshot_id, url_norm, source)
);
CREATE TABLE IF NOT EXISTS excluded_keywords (
 snapshot_id TEXT NOT NULL, kw TEXT NOT NULL, PRIMARY KEY(snapshot_id, kw)
);
CREATE INDEX IF NOT EXISTS urls_status_source ON urls(status, source);
CREATE INDEX IF NOT EXISTS list_tasks_status ON list_tasks(status);
```

## Public queue API and types

- `CrawlQueue(path: str | Path)` opens a process-local writable connection; `path` is an absolute `Path`, `connection` is a `sqlite3.Connection`, and `run_id` is `str | None`.
- `CrawlQueue.open_readonly(path: str | Path) -> sqlite3.Connection`: caller closes the connection (SQLite's connection context manager alone does not close it).
- `close() -> None`.
- `add_list_tasks(kws: list[KwMeta], sources: Iterable[str]) -> None`.
- `next_list_task() -> ListTask | None`: deterministic pending-task peek. T13 must maintain its own in-flight list-task set when scheduling async calls; repeated peeks do not claim a task.
- `record_list_page(task: ListTask, items: list[ListItemLike], next_cursor: str | None) -> None`: atomic URL/hit insertion, page completion, and next-page insertion; completed-page replay is a no-op.
- `add_urls(items: Iterable[ListItemLike | Mapping[str, Any]]) -> int`: newly inserted URL count. Duplicate URLs only add keyword-hit records.
- `take_snapshot() -> str`: UUID hex ID with immutable URL membership and deterministic SHA-256 of the sorted `(url_norm, source)` set.
- `lease_urls(snapshot_id: str, n: int, lease_s: float) -> list[UrlRow]`: effective `(kw_order, source, url_norm)` ordering, snapshot membership, retry eligibility, and keyword exclusions applied atomically. Every lease increments attempts.
- `mark_done(url_norm: str, source: str, doc_count: int, last_error: str | None = None, fetch_level: str | None = None, access: str | None = None) -> None`: all reporting fields written in one transaction. Excluded/filtered rows and another run's lease cannot be completed.
- `mark_failed_attempt(url_norm: str, source: str, last_error: str, max_attempts: int = 3, backoff_s: float = 1) -> None`: delay `backoff_s * 2**(attempts-1)`; pending until maximum attempts, then failed awaiting worker fallback.
- `mark_filtered(url_norm: str, source: str, rule: str) -> None`: stores status plus rule number for aggregates.
- `exclude_keywords(snapshot_id: str, kws: Iterable[str]) -> int`: cumulative exclusions; returns newly excluded URLs only. Surviving representative keyword is the earliest non-excluded hit. All hits remain available.
- `reclaim_expired_leases() -> int`: returns count reset to pending; expiration, dead PID, heartbeat older than 30 seconds, or non-running owner qualify.
- `register_run(kind: str) -> str`: `list` or `detail`; live same-kind registration is checked and rejected inside the insertion transaction. Attaches future leases to this run and reclaims abandoned leases at startup.
- `heartbeat(run_id: str) -> None`; `finish_run(run_id: str, status: str) -> None`: only the current process may update its run.
- `counts() -> dict`: counts for all six URL statuses, `total`, completed `doc_count`, and dictionaries `fetch_level`, `access`, `filter_rules`. Uses a separate `mode=ro` connection and consistent read transaction.

The actual mutable defaults use dataclass factories. `UrlRow.url` aliases `url_norm`. `ListItemLike` is a structural protocol with `url/title/snippet/date/src_meta`; adapter instances with those attributes work directly in `record_list_page`, which obtains keyword and source context from `ListTask`. Standalone `add_urls` inputs additionally require `source` and `kw`; optional `kw_axis/kw_sub/kw_order` carry metadata. Mappings work as well. T13 should use `record_list_page` for adapter pages, or enrich objects/mappings before `add_urls`. No coupling to T12 types is required.

## P2 API and decisions

`FilterConfig(date_from, date_to, ad_words, exclude_sources, include_sources, product_name_filter=False, bk="")`; all fields have defaults. Date defaults span today minus 365 days through today. Explicit None disables a bound. ISO dates/timestamps, compact YYYYMMDD, Python dates/datetimes are accepted; unknown dates do not exclude a row. Bounds are inclusive.

`check_list(item, cfg) -> str | None` and `check_doc(doc, cfg) -> str | None` return the first matching numbered rule. Order is ① date, ② ad words, ③ excluded source, ④ included source, ⑤ optional product name. Source rules apply to list items only. Matching is case-insensitive. Product matching uses title+snippet for lists and title+body for documents. Rule ⑥ is enforced by the queue's UNIQUE key. Caller persists P2 rejections via `mark_filtered` after recording the URL.

`DEFAULT_EXCLUDE_SOURCES` copies `crawling.py`'s list verbatim. **Source discrepancy:** the existing `crawling.py` has no literal ad-word list: it reads `config.get("adFilter", [])`. The existing literal default was found at `frontend/src/app/pipeline/crawling/page.tsx:21`: `협찬,광고,제공받,원고료,체험단,서포터즈,중고,판매,거래`. Those entries and order were preserved, followed by the six brief additions `체험단 협찬 원고료 소정의 제공받아 서포터즈` verbatim. Duplicate words are intentionally retained and harmless. The frontend and crawling service were not edited.

All connections set `PRAGMA journal_mode=WAL`, `PRAGMA busy_timeout=10000`, and `PRAGMA synchronous=NORMAL`. Write operations use BEGIN IMMEDIATE/COMMIT with rollback on failure. Input normalization/serialization happens before the write lock; keyword exclusions use set-based SQL. Status reads are true read-only URI connections. Each spawned process opens its own queue; inherited instances reject writes. Use one connection per thread as required by sqlite3.

Extra tables preserve keyword metadata, snapshot membership, and per-snapshot exclusions; `url_hits` holds every keyword plus its order/axis/sub metadata. Additional URL fields persist worker ownership, reporting dimensions, retry timing, and filter rules. `first_seen_kw_order` remains the first discovery's value; effective `UrlRow.kw_order` is computed from surviving hits.

## Concerns and T13 integration

- No existing service ad-word literal exists; the frontend default substitution is documented above.
- T13 must call `register_run` before detail leases, heartbeat every 10 seconds, and reclaim every 60 seconds. Run `sid` is the absolute queue-parent directory because the mandated constructor/registration signatures have no sid argument; one queue file per collection/session is assumed. `config_json` defaults to `{}`.
- List task selection is a peek. A single list worker must track concurrently scheduled tasks; the list table's specified status vocabulary has no leased state. This task does not implement a list-task failure/retry scheduler or total-hint update API.
- At the third failure, T13 must write the snippet fallback, flush/fsync its shard as specified, then `mark_done(..., last_error=..., fetch_level="snippet", access=...)`. A `failed` row means awaiting fallback, not a fabricated saved document. Recovery must also inspect failed rows via the read-only connection to finish any interrupted fallback. File durability and row transactions cannot be made atomic by this SQLite-only module.
- Exclusions accumulate for a snapshot; unexclude/reset is not part of this API. Snapshots freeze URL membership, while URL statuses and hits are shared within a queue file. Use a new collection database for an independent re-crawl; snapshots are not independent copies of crawl state. Gate exclusion should complete before detail scheduling so already-materialized worker objects retain the chosen keyword.
- Source filters recognize explicit source-identity metadata keys (cafe/blog/board/channel names and IDs). T13/T12 should use these keys; arbitrary metadata is intentionally not searched.
- No changes were made to parallel tasks, and only T11 tests were run. Shared upstream normalization/hashing fixes remain outside this task.
