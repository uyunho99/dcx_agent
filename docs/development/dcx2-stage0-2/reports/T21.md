## 사용자 동작별 API
모든 keyword 경로의 prefix는 `/keywords/{sid}`다.

| 동작 | API 및 결과 |
|---|---|
| 화면 진입/새로고침 | `GET /keywords/{sid}` + `GET /session/{sid}`. 최고 라운드와 동일 gen의 `drafts.keywords.r{n}` 복원. 진입 시 POST 생성 없음 |
| 최초 생성/실패 재시도/R4 추가 생성 | 방향 지시가 있으면 먼저 events(direction), `POST rounds/{n}`, `PATCH /session/{sid}` `{step:rN}`. 서버 응답 gen 사용 |
| 실행 중 복원/진행 | `GET rounds/{n}` 즉시 조회 후 3초마다 조회. done/failed에 중지하고 GET 전체 상태 갱신. 겹치는 polling 요청 없음 |
| 방향 지시 저장 | `POST events` `{round,type:direction,text}`. 응답 feedback_md 갱신 |
| 키워드 거절 | `POST events` `{round,type:reject,kwId,tags,note}`. 미확정 라운드 선택은 dirty 표시 |
| 거절 복원 | `POST events` `{round,type:unreject,kwId}` |
| 오분류 거절 | reject 이벤트 성공 후 `POST events` `{round,type:move,kwId,to:{axis,sub}}`. 양쪽 모두 성공해야 팝오버 닫음 |
| M 이동 / HTML5 drop | 동일한 `POST events` move 요청. 성공 후 목적지 펼치기·전체 탭·해당 칩 포커스 |
| 수동 추가 | `POST manual` `{kw,axis,sub,origin:manual}`. 반환 Keyword와 volume 사용 |
| 추천 조회 | `POST suggest-words` `{axis,sub}` |
| 추천 단어 추가/모두 추가 | 각 단어 `POST manual` `{kw,axis,sub,origin:suggested}`. 성공한 항목만 추천 목록에서 제거. add 이벤트는 manual endpoint가 기록 |
| 중복 | 409의 duplicateOf를 opaque ID로 기존 키워드와 매칭해 분류/단어 안내. 중복 확인 버튼은 해당 그룹을 펼침 |
| 새 하위 카테고리 | 로컬 `custom:<이름>`, 축 선택 필수. 빈 그룹은 임시저장 payload의 groups로 저장, 단어 추가 시 서버 keyword.axis/sub로 지속 |
| 임시 저장 | `PATCH /session/{sid}` `{drafts:{keywords:{rN:{round,gen,decisions,groups}}}}`. 미생성 초기 그룹 초안만 gen=0. 실행 중에는 handler가 저장을 차단 |
| 저장 | `POST rounds/{n}/commit` `{gen,decisions}`. 승인/거절/메모 포함. 성공 후 GET 갱신과 해당 draft=null PATCH. 다음 라운드 생성이나 화면 이동 없음 |
| 다음 라운드 생성 | 확정된 R1→R2→R3→R4 순서만 `POST rounds/{n+1}`. 건너뛰기 없음 |
| R4 이후 크롤링 설정하기 | `PATCH /session/{sid}` `{step:crawl-setup}` 이후 `/pipeline/crawling` 이동 |
| 커버리지 다시 계산 | `POST coverage` + GET 전체 상태. R2 commit API도 서버에서 커버리지를 계산 |
| 탭/필터/검색/접기/도움말 | 로컬 UI 변경, 서버 쓰기 없음 |
| 구버전 차단 | keyword API 호출/편집 없이 8.1 문구와 `/pipeline/preprocess` 이동 버튼 |

v2 페이지에서 saveSession 및 store의 legacy 전체 저장 경로는 호출하지 않는다. step PATCH 성공 뒤 setSession은 공유 단계 표시/로컬 sid만 갱신한다.

## R5 회귀 계약
1. 수동 추가의 검색량은 POST manual 응답의 `volume.monthly`를 즉시 표시한다. unconnected/error는 해당 칩의 미연결/조회 실패로 표시한다.
2. duplicateOf를 클라이언트에서 재생성하거나 숫자로 변환하지 않는다. 409 안내에 기존 단어와 축/sub를 표시하고 해당 그룹을 확인할 수 있다.
3. 추천은 sub 단위로 조회하며 단건/모두 추가 모두 `origin:suggested`를 명시한다. 실패한 단어는 추천 목록에 유지한다.
4. 모든 그룹은 접힌 상태에서도 drop target이다. 전체 탭에서 축 간 드래그를 지원하며, M 팝오버에도 모든 축/sub와 custom 목적지가 있다.
5. 축 미선택/빈 이름일 때 새 그룹 추가를 비활성화한다. 실제 sub는 `custom:<trimmed name>`이다.
6. 그룹별 접기와 모두 접기/펼치기를 제공한다. 현재 탭의 sub가 10개 이상이면 기본 자동 접기이며, 사용자가 변경한 그룹 상태가 우선한다.

## 키보드 맵
- 탭/단일 필터: DS 방향키 및 Home/End, 활성 요소 하나만 tab stop.
- 그룹 내 칩: 로밍 tabindex 0 하나. Tab은 그룹 외부 컨트롤/다음 그룹으로 이동한다.
- ←/→: 문서상 이전/다음 칩. ↑/↓: 실제 getBoundingClientRect 행 위치를 측정하여 같은 열로 이동(짧은 행은 마지막 칩). Home/End: 그룹 첫/끝. 끝에서는 그룹 안에 머문다.
- Enter/Space: 거절 팝오버 열기, 이미 거절된 칩이면 unreject.
- 팝오버: Space로 사유 선택, Tab으로 메모·목적지·버튼 이동, Enter 확인, Esc 취소. 오류 시 입력 유지. 닫으면 원래 칩으로 포커스를 복원한다.
- M: 축/sub 이동 팝오버. 이동 성공 시 목적지 그룹을 펼치고 옮긴 칩에 포커스한다.
- 칩 이름에 단어·검색량·배지·거절 여부를 포함한다. role=option, aria-selected=거절 여부. 그룹 role=listbox.

## S2/S3 차이와 우려
- D-070 ruling에 따라 목업의 확정+다음 생성 결합 버튼을 SaveBar의 임시 저장/저장과 별도 다음 라운드 생성으로 분리했다.
- S2 검토와 S3 커버리지는 한 경로에서 연결된다. R2 확정 뒤 검토 아래에 넓은 커버리지 영역(Insight → 지표 → 누락 표)을 표시한다. 1100px 미만에서는 한 열로 쌓인다.
- 서버 missing_top은 `[query, volume]`만 제공한다. 목업의 분위·추정 축·가장 가까운 LLM 키워드는 추정해서 만들지 않고 표에서 제외했다. 조회 날짜 역시 제공되지 않아 표시하지 않았다. 별도 R3 입력상태 카드 대신 실제 축 분포/거절 집계/커버리지 상태를 표시한다.
- 빈 기본 sub도 drop/manual-add 대상으로 남긴다. 목업의 채워진 그룹만 보이는 예시와 다르다.
- **재생성 API 제약:** 서버는 done+미확정 결과의 재생성을 409로 거부하며 R1–R3은 확정 후 같은 라운드를 다시 생성할 수도 없다. 따라서 실패 재시도와 확정 R4 추가 생성만 허용한다. below_min 안내는 검토/저장 후 다음 라운드로 안내한다. 8.1의 빈 결과/목표 미달 상태에서 같은 라운드 재생성까지 허용하려면 backend 정책 변경이 필요하다. backend 소유권을 지켰다.
- 빈 custom 그룹은 키워드 자체가 없으므로 명시적 임시 저장으로만 복원한다. 단어가 있는 custom 그룹은 키워드에서 복원한다.
- 미연결 상태에는 서버가 지표를 반환하지 않을 수 있다. m7을 포함한 null/누락 값을 0으로 바꾸지 않고 계산 불가로 표시한다.
- 소유 범위 밖 SuggestedWordsPanel의 legacy suggestWords import가 남아 있어 해당 API helper는 유지했다. 새 페이지는 이 helper를 사용하지 않는다.
- 자동 검증은 pure logic, lint, TypeScript 및 프로덕션 빌드까지다. 실제 브라우저에서 drag/포커스/200% 확대 및 실제 작업 재시작 QA가 추가로 필요하다.
- 기존 `.DS_Store` 및 동시 작업자의 backend 파일은 수정/스테이징하지 않았다.

## Git
아래에 지정 파일만 대상으로 한 add/commit 시도 결과를 기록한다.

지정 파일만 `git add -- ...`를 실행했으나 작업 디렉터리 밖에 있는 worktree index에 쓰기 권한이 없어 실패했다(exit 128):
```text
fatal: Unable to create '/Users/persona1/Desktop/dcx_agent/.git/worktrees/dcx_agent-dcx2-stage0-2/index.lock': Operation not permitted
```
다른 작업자의 변경을 커밋하지 않도록 지정 경로만 `git commit --only -m 'feat(ui): 1단계 키워드 화면(라운드·3축·키보드 검토·회귀 계약)' -m 'Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>' -- ...`로 시도했다. add가 실패하여 새 파일이 index에 없으므로 pathspec 오류로 실패했다(exit 1). 권한 우회 없이 **uncommitted**로 남겼다.
