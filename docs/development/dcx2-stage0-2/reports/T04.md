## 디스크 배치와 후속 작업 계약
루트는 매 호출 `Path(settings.local_data_dir)`에서 계산한다.

```
sessions/{sid}/.lock
sessions/{sid}/meta.json
sessions/{sid}/versions/v1/session.json
sessions/{sid}/versions/v1/project_context.md
sessions/{sid}/versions/v1/keyword_events.jsonl  # 후속 작업이 생성
sessions/{sid}/versions/v2/...
sessions/{sid}/active -> versions/{activeVersion}
sessions/{sid}/session.json -> active/session.json
crawl/{sid}/collections/{collectionId}/...     # 버전 복사/세션 삭제 시 건드리지 않음
```

`session_dir(sid)`와 `active_version_dir(sid)`는 활성 버전 폴더다. 구버전은 기존 루트 폴더를 반환한다. `training.py`의 focused grep 결과 로더는 `load_json(f"sessions/{sid}/session.json")`였다. 루트 링크로 기존 로더가 활성 세션을 읽도록 했다. 실제 training 모듈이 가져온 로더로 labeledData 읽기와 버전 변경 후 호환 경로를 검증했다. training.py는 수정하지 않았다.

모든 새 세션 변경은 `update_session(sid, patch)`를 사용한다. `.lock` 파일 inode를 유지하고 `fcntl.flock` 안에서 읽기·깊은 병합·동일 디렉터리 임시 파일 쓰기·flush/fsync·os.replace·디렉터리 fsync를 수행한다. 배열은 교체한다. API의 검사+변경은 같은 잠금 아래 내부 `_update_locked`를 호출한다. 버전 meta 수정도 같은 잠금 아래 수행한다.

T09 작업 상태는 `keywordRounds.<라운드 문자열>.job.{status,progress,updatedAt}`다. `status=running`이면 버전 생성/전환을 차단한다. 활동 kind는 `keyword_round_<라운드>`다. `failed`, `interrupted`, `paused_blocked`는 주의 필요 상태다. 크롤링은 guarded import로 `app.crawl.control.activity(sid)`를 호출한다. 목록은 중단/차단/실패, running, 나머지 순이고 각 그룹은 updatedAt 및 sid 내림차순, 최종 20개다. 크롤링 running은 라운드 실패 배지에 가려져도 버전 생성이 차단된다.

`?version=v1`로 과거 Context/세션을 읽거나 PATCH/PUT 대상을 지정한다. 과거 버전을 활성 선택해도 readonly는 해제되지 않는다. 되살리기는 새 버전 생성으로 한다. active-version 요청은 `{ "version": "v2" }`다.

stale는 `stageN -> 이유` 맵이다. restartFrom 단계 자체부터 기존 파이프라인 stage6까지, 그리고 기존 stale/stageResults에 명시된 더 뒤 단계까지 표시한다. projectContext 저장은 stage0, keywords/keywordRounds는 stage1, crawlConfig/collectionId는 stage2 표시를 해제한다. 후속 단계는 `stageResults.stageN`을 저장하면 해당 stale이 해제된다. 3단계 이후 비교할 결과 파일은 버전 폴더의 `stageN/` 아래에 저장한다(해시로 동일성 비교, 파일별 savedAt은 mtime). 수집본이 다르면 `collections/{id}/report.json`의 `counts.{keyword}.{channel}` 숫자 맵을 비교한다. 이 두 파일 규약은 후속 단계 구현에서 맞춰야 한다.

## 결정
- D8: design 2.2의 projectContext, knownInsights, keywords, keywordRounds, coverage, crawlConfig, collectionId, version*, drafts를 incoming full save에서 제외한다. schemaVersion/sid/parentVersion/restartFrom/stale/updatedAt도 서버 메타데이터로 보호한다. labeledData 등 화면 값은 병합한다. 기존 무 schemaVersion 세션은 s3.save_json 전체 덮어쓰기를 유지한다.
- 새 API 오류는 `{status:"error", error:{kind,message}}`: validation(400/422), not_found(404), conflict(409), storage(500), LLM kind(502). 버전 생성 중 작업 실행 오류 메시지는 `진행 중인 작업이 끝난 뒤 다시 시도하세요`.
- brief/ruling을 우선하여 LLM task 이름은 `category_suggest`다(설계 본문 category_estimate와 다름). run_task와 기존 backend compose 경로를 그대로 사용한다. 세션 생성 전 제안이므로 첨부에는 입력 bk/oneLiner 본문을 넣는다.
- 쇼핑 미설정은 Unconnected. 0건/호출 실패는 LLM 추정으로 진행한다. 네트워크 예외 문자열이나 키 값은 응답/last_error에 싣지 않는다. 연동은 요청된 6개이며 settings의 빈 문자열/"x"는 미연결이다.
- 활성화 실패 시 원래 활성 버전 유지 및 실패한 복사본 정리를 회귀 테스트했다.
