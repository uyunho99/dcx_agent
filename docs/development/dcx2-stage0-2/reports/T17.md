## Implementation

CommunityAdapter provides list URL/parser hooks, injectable synchronous httpx client, browser-like User-Agent, Accept-Language beginning with ko-KR, site-specific response decoding, and per-instance request spacing. It reuses ChannelLimiter with concurrency 1 and minimum interval 1.0 seconds, accepting injected clock/sleep functions. HTTP 403 and 429 immediately raise AdapterBlocked without retry. Other unsuccessful responses raise HTTP status errors. Redirects are not followed automatically. Adapter requests are restricted to the site's HTTPS origin. Internally created clients can be released via close(); injected clients remain caller-owned. is_available() returns true because these public HTML sources need no credentials.

Queries contain the keyword as-is, with no bk or product-name filtering:

- Clien: /service/search?q=<UTF-8 keyword>&sort=recency&boardCd=&isBoard=false
- Ppomppu: /search_bbs.php?keyword=<EUC-KR percent-encoded keyword>, with Referer set to https://www.ppomppu.co.kr/.

Parsers use selectolax. Clien extracts search rows, article body, author, date, and HTML comments. Ppomppu extracts search results and .board-contents, excludes nested comment counts from titles, and parses initialCommentData with JSONDecoder.raw_decode rather than executing scripts. Supplemental server-rendered comment selectors are supported and IDs deduplicated against inline JSON.

Shared helpers centralize normalized text extraction, script/style exclusion, date extraction, and salted comment-author hashing. Post author_raw retains the masked author string. Raw comment authors are hashed with the existing author_hash function rather than added to metadata. Article body extraction stays within the article container, excluding navigation and sidebar text.

## Assumptions and limitations

- Clien pagination: captured navigation calls app.searchDetails("", "<p>"); p is treated as zero-based. The smallest later advertised page becomes next_cursor. The capture provides only the first page; subsequent request parameter propagation is tested offline.
- Ppomppu pagination: the aggregate search capture contains category “more” links but no next-page link. Its next_cursor is therefore None. Explicit search_bbs.php?page=N links use a one-based page cursor, covered by a supplemental in-memory link. Category expansion is not implemented. Later-page HTML and its pagination convention have not been verified against a real capture.
- total_hint is None because no reliable total is extracted.
- Comment has only text, depth, date, and author_hash, with extra fields forbidden. Parent relationships are preserved in aligned src_meta.comment_threads entries containing id and parent, without changing the shared schema.
- Clien captures mark replies with .re but expose no explicit parent ID. Replies retain depth 1 and are attached to the preceding root; exact reply-to-reply targets cannot be reconstructed from those attributes.
- Ppomppu preserves the JSON depth and parent IDs. All recorded initial comments are roots, so a supplemental in-memory reply tests nonzero depth/parent preservation. Supplemental rendered markup tests supported HTML selectors; a real legacy/server-rendered capture is not present.
- Captured Ppomppu visible totals are 4/3/1, but initialCommentData contains 3/2/1 comments. Only delivered comments are returned; unavailable comments are not fabricated and no comment-load-more request is made.
- One Ppomppu capture contains invalid EUC-KR bytes outside its article content. Decode uses replacement for invalid bytes; assertions confirm no replacement characters in returned titles, bodies, or comment text for all six article captures.
- Registry wiring is intentionally deferred, as requested. No live-site/network verification was performed.
