## 스토어 필드와 호환성
v2 원본은 `projectContext`이며 `bk = projectContext.bk`, `pd = projectContext.researchQuestion.text`다. `setSession`이 원본에서 파생하므로 legacy 필드를 받아도 v2에서는 덮어쓴다.

`grep -rn`을 ages/ar/gens/pd 각각 실행했다. 소유 범위 밖 keywords가 ages/ar/gens를 모두 읽고 insights가 해당 값을 setSession에 전달하며 training/personas도 pd를 읽는다. 컴파일/기능 호환을 위해 ages/ar/gens를 제거하지 않고 각각 targetScope.households/ageRanges/genders의 파생 필드로 유지했다. v2의 독립 원본으로 사용하지 않는다. legacy는 기존 값을 유지한다. SessionData의 legacy 필드 타입도 남겼다.

v2 `setPendingKw`/`clearPendingKw`는 `PATCH /session/{sid}`의 `drafts.keywords`만 변경한다. `setStep`은 step만 PATCH한다. legacy pending 저장은 기존 full-save를 유지한다. sessionPersist는 원래 full-save 호출이 없었으며 지금도 조회/복원만 수행한다. 다른 화면에 존재하는 full-save 호출은 소유 범위 밖으로 유지했다.

## 버튼별 API
| 동작 | API 및 결과 |
|---|---|
| 기존 세션 임시 저장 | `PATCH /session/{sid}` `{drafts:{start:form}}`, 검증 없음, 이동 없음 |
| 세션 없는 최초 임시 저장 | 서버 API 없음으로 localStorage `dcx_start_draft` 저장, 로컬임을 배너로 명시, 이동 없음 |
| 저장 | 신규는 `POST /context`로 sid 확보, 기존은 `PUT /context/{sid}`. 이후 PATCH로 start draft를 null로 지우고 `GET /session/{sid}`로 store 복원. 이동 없음 |
| 키워드 생성 시작하기 | 동일 context 생성/갱신 후 PATCH `{step:"r1",drafts:{start:null}}`, store 복원 후 `/pipeline/keywords` 이동 |
| 자동 제안하기 | `POST /context/category-suggest` `{bk,oneLiner}`. shopping은 쇼핑, llm_estimate는 추정. 편집하면 user로 변경 |
| 세션 열기 | `GET /session/{sid}`, 시작 화면은 추가 `GET /context/{sid}`로 저장 맥락/임시값 복원. 단계별 이동, 중단/차단은 crawling 이동 |
| 새로고침하기 | `GET /sessions` 즉시 재조회 |
| 입력값 다시 불러오기 | `GET /context/{sid}` 재시도 |
| 템플릿/추가/삭제/선택 | 로컬 폼 변경 |
| 전처리 화면으로 | `/pipeline/preprocess` 이동 |
| 새 프로젝트 만들기 | 활성 store/로컬 sid 초기화 |

저장 중 입력은 잠그며 실패 시 값은 유지한다. 저장 버튼은 필수 검증 실패 시 비활성이다. 시작 버튼은 첫 오류로 스크롤/포커스한다. 임시 저장 버튼은 항상 enabled이며 이미 진행 중인 저장과의 중복 요청은 막는다. 신규 POST 성공 후 후속 요청 실패 시 확보한 sid를 재사용한다.

## S1 차이
- 설계 본문 지시대로 세션 목록을 상단에 배치했다. 내부 preview는 오른쪽 1/3이며 비활성 시 폼이 전체 너비다.
- 버튼 동사 규칙과 명시적 SaveBar 계약을 적용했다. 선택 칩 라벨은 backend LABELS와 일치시켰다.
- DS에 Textarea가 없어 리서치 질문은 DS Input이다. 긴 질문을 여러 줄로 표시하는 목업과 다르다.
- 제품군은 0-B 선택 입력이라는 지시를 따라 필수 표시를 제거했다.
- 저장 버튼/dirty 표시/오류/로딩/임시 저장 안내를 추가했다.
- 기존 목록의 삭제 액션은 이번 목록에 포함하지 않았다.

## 우려 및 남은 계약
1. **신규 미완성 draft 서버 저장 불가**: POST /context는 완성된 ProjectContext와 필수 텍스트를 검증하고 PATCH는 기존 sid만 허용한다. 검증 없이 최초 draft를 PATCH하는 요구를 현재 API로 만족할 수 없다. 가짜 context/legacy 세션을 서버에 생성하지 않고 브라우저 저장으로 제한했다. 서버 초안 생성 계약이 필요하다.
2. **구버전 직접 진입 차단**: 시작 화면 및 목록에서 0~2단계 legacy 세션을 열 때 차단 화면을 표시한다. 소유 범위 밖 keywords/crawling 자체와 공유 layout에 전역 route guard를 추가하지 않았으므로 해당 URL 직접 진입/다른 화면에서의 sidebar 이동까지 차단하지는 않는다. 해당 화면 소유자의 guard가 필요하다.
3. **호환 필드 유지**: ages/ar/gens의 물리적 제거는 기존 keywords/insights 호출부 변경과 함께 후속 작업이 필요하다. 기존 ages의 직업/페르소나 값과 새 households 코드의 의미는 완전히 같지 않다.
4. 버전 드로어/readonly/stale/재시작은 T20 지정 파일 범위 구현에 포함하지 않았다.
5. 브라우저 상호작용/스크린샷 QA 및 실제 백엔드 왕복 QA는 실행하지 않았다. 자동 검증은 위 단위 테스트/lint/프로덕션 빌드 범위다.
6. `.DS_Store`, 다른 작업자의 backend 테스트 및 backend/app 파일은 수정/스테이징하지 않았다.
