## Concerns and measured limitations

- No Naver search API wrapper, keys, openapi calls, rendering, or live network probing were added. Blog missing/empty editor content raises ValueError; crawl4ai fallback is deliberately omitted under the revised task allowance because measured mobile HTML needs no rendering and adding a renderer is not trivial.
- Both public cafe fixtures expose `comments.items`, `alarm`, and `disableWriteReason`, with no continuation URL/cursor. Only the returned first comment batch is collected; article.commentCount preserves the server total. No unobserved comment endpoint is invented. The recorded detail-3 already contains genuine replies, so depth tests use those; a deleted-comment variant is added in memory.
- Cafe list-2 repeats the URLs of list-1 despite its recorded start=31 request. A shared adapter terminates upon a repeated URL set at a later cursor, including reordered repeats. A short page or explicit disabled next control also terminates. Blog recorded pages contain distinct URLs. No internal pagination loop exists.
- Search date positions in these masked captures contain name placeholders such as 사용자A/사용자U. Missing/unparseable dates remain None rather than being inferred from prose or image URLs. Synthetic in-memory date replacements verify actual list extraction; separate tests cover absolute and relative dates against an injected clock. Cafe millisecond timestamps normalize in Asia/Seoul.
- Search selectors reflect the measured SDS blog and legacy cafe layouts. Unknown/malformed result structures raise ValueError rather than returning silent empty results. Empty pages require an explicit no-results notice.
- A `.DS_Store` modification was already present during initial repository inspection; it was not edited by this task.

Changes:

- Cafe detail now classifies HTTP 403 bodies before treating them as channel blocks. JSON containing `result.errorCode`, or a recognized restriction reason, returns the list item's title/snippet with restricted access. Empty/HTML/unrecognized 403 responses still raise AdapterBlocked. Search/blog 403 and every 429 remain blocked. HTTP 401 returns a restricted snippet even for empty, HTML, or missing-result bodies.
- Search recognizes blog `PostView.naver?blogId=...&logNo=...` and canonicalizes it to `https://blog.naver.com/<blogId>/<logNo>`. Numeric cafe links retain `https://cafe.naver.com/ca-fe/cafes/<cafeId>/articles/<articleId>` without tracking parameters; detail requests use `useCafeId=true`. Named cafe paths retain their existing canonical form and `useCafeId=false`. Numeric IDs cannot be mapped to cafe names from these captures, so numeric and named URLs are not deduplicated across those two forms.
- Titled, linked non-article rows (ads, profiles, more links) are skipped. Missing title/link/href still raises ValueError, as does a page with result rows but zero parseable articles, even if an unrelated no-results notice exists. Canonicalized article duplicates collapse within a page.
- Pagination state now retains only the latest URL-set signature per keyword and evicts the least recently used keyword beyond 256 entries. Consecutive repeated pages terminate, including reordered URL sets; retrying the same terminal cursor remains terminal. Historical nonconsecutive signatures and evicted keywords are intentionally not retained, bounding memory independently of page count.
