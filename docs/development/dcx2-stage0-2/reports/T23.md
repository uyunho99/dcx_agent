# T23 — 내부용 외부 API 드로어 · 뒤 단계 projectContext

## 변경 파일
- `frontend/src/components/internal/IntegrationsDrawer.tsx`: 너비 360px, Overlay 토큰 라운드 18px, API별 상태/영향 기능/환경변수 이름/마지막 오류/다시 확인하기.
- `frontend/src/lib/api/integrations.ts`: GET `/integrations`, HTTP 및 응답 형식 검사, 메타데이터만 선택, 요청 취소 및 재조회 상태 공유.
- `frontend/src/lib/logic/nextTrapIndex.ts`, `nextTrapIndex.test.ts`: Tab/Shift+Tab 순환 순수 함수와 3개 테스트.
- `frontend/src/app/pipeline/layout.tsx`: 내부 버튼 연결 개수와 드로어 마운트. 버튼은 `외부 API · n/6 연결 열기`로 동사 규칙 적용. 로딩/실패 시 개수는 `—`로 표시.
- `frontend/src/app/pipeline/training/page.tsx`, `personas/page.tsx`: bk/pd 읽기만 변경.
- 이 보고서. `api.ts` 수정 불필요. 계획 파일은 읽지 않았으며 하위 에이전트를 사용하지 않았다.

## 드로어 접근성 및 상태
- native `dialog.showModal()`로 배경을 inert 상태로 만들며 `role="dialog"`, `aria-modal="true"`, 제목을 가리키는 `aria-labelledby`를 명시한다.
- 열릴 때 드로어에 포커스. Tab과 Shift+Tab은 현재 활성 컨트롤 목록 및 순수 함수로 순환한다. 컨트롤이 없으면 드로어에 머문다.
- Esc의 cancel 이벤트와 닫기 버튼으로 닫는다. unmount cleanup에서 사이드바 `integrations-trigger` 버튼으로 포커스를 돌려준다.
- 로딩은 Skeleton 및 `role="status"`의 `처리 중…`. 오류는 `role="alert"` Banner의 `외부 API 연결 상태를 불러오지 못했습니다. 다시 확인하세요.`와 재시도 버튼이다.
- 각 API의 다시 확인하기는 계약에 있는 전체 GET을 다시 호출하며 사이드바 개수도 갱신한다. 조회는 캐시하지 않고 이전 요청을 취소한다.
- 새 UI의 색/타입/라운드/그림자는 기존 DS 토큰을 사용한다. 환경변수 이름만 표시하며 키 값을 요청하거나 표시하지 않는다.

## 페이지 변경
- `sd?.schemaVersion === 2`이면 `projectContext.bk`, `projectContext.researchQuestion.text`를 사용한다. Python `ProjectContext`, `ResearchQuestion` 모델의 필드명과 일치한다.
- context 자체의 schemaVersion(1)과 세션 schemaVersion(2)을 구분한다.
- v2 context가 누락되면 빈 문자열을 사용해 오래된 legacy 값이 섞이지 않게 한다. legacy 세션은 기존 `store.bk`, `store.pd`를 그대로 사용한다.
- 시작/저장/폴링 및 기존 페이지 문구/스타일은 변경하지 않았다.

## 우려 및 검증 범위
- 브라우저에서 실제 키보드 조작/200% 확대를 통한 시각 QA는 실행하지 않았다. helper 단위 테스트, 코드 검토, 타입 및 빌드로 검증했다.
- GET `/integrations`는 백엔드의 설정 유무와 저장된 마지막 오류를 반환한다. 다시 확인하기는 실제 공급자 API에 접속해 키 유효성을 시험하는 기능이 아니다.
- 기존 페이지의 full-save 동작 등 bk/pd 이외 로직은 소유권 제한에 따라 유지했다.
- Node `module.register()` deprecation 경고가 test/build에 있다. lint 경고는 없다.
- `.DS_Store`, `decision-log.md` 등 다른 작업의 변경은 건드리지 않는다.
