## Rules and conventions

A human query matches an LLM keyword if `norm_key(llm)` is a substring of `norm_key(query)` or vice versa. Empty normalized strings never match. Normalization uses the existing NFC, Unicode whitespace removal, and lowercase helper.

SearchAd signatures are `base64(HMAC-SHA256(secret, f"{timestamp}.{method}.{uri}"))`; headers are exactly `X-Timestamp`, `X-API-KEY`, `X-Customer`, `X-Signature`. Tests calculate the expected signature independently with hmac/hashlib/base64. No credentials are logged.

Each PC/mobile `"< 10"` value becomes the documented constant 5, then PC and mobile are summed. Thus two censored counts total 10, which does not receive a badge at the default threshold. Monthly results retain original input strings. API-omitted keywords remain unknown rather than being assigned zero. Related results repeated across batches use the latest count rather than summing duplicates.

Connected volume is `{monthly: n, source: "searchad", at: ISO date}`. Missing credentials (`""` or `"x"`) yield `{monthly: None, source: "unconnected", at: None}`. Existing low_volume badges are refreshed; unrelated badges remain. Inputs are deep-copied.

m1 is search-volume weighted. m2 sorts descending by volume and partitions query ranks into ten contiguous buckets, distributing remainder items to the first buckets. Empty or zero-total buckets are None. m6 uses item-count axis distributions, returns None when axes are missing/incomplete or either population is empty, and computes the square root of base-2 JS divergence. The standalone distance rejects undefined zero-total distributions. m7 uses the design's fixed <10 cutoff and returns IDs for callers to apply llm_only badges without mutating inputs. Unknown volumes do not qualify. Without human rows, m1/m2/m6 are unavailable and m7 uses known volumes alone. An empty LLM list yields m7=0. Missing queries are descending by volume and capped at 20.

## Concerns

- Live SearchAd access was unavailable; endpoint behavior is verified with synthetic MockTransport responses only.
- Design does not specify decile tie/interpolation or axis weighting conventions; the exact deterministic choices are documented above.
- HTTP/data failures propagate after recording only `request_failed`; callers must handle failures separately from missing credentials. No failed request is converted into zero demand.
- Existing `app/config.py` emits a Pydantic class-based Config deprecation warning; it is outside this task's ownership.
- Commit attempt: `git add` failed before committing because Git could not create the worktree metadata `index.lock` (`Operation not permitted`). Changes remain uncommitted; no permission escalation was attempted.

## Fix round 1

- R-30: changed `LOW_COUNT_ESTIMATE` from 5 to 4 per censored PC/mobile side. Both censored sides now have an estimated total of at most 8 < 10, receiving the default low_volume badge and qualifying for m7 when unmatched. This supersedes the original count convention above.
- R-31: `CoverageReport.m7` is now `float | None`, returning None when no LLM keyword has a known monthly volume, including an empty LLM list. With any known volume, the existing denominator remains the full LLM list. This supersedes the original empty-list m7 convention above.
- Covering tests: updated `test_related_and_original_keys_low_counts` and `test_connected_attachment_copies_and_refreshes` to expect 4. Added `test_censored_counts_attachment` cases for two censored sides (monthly 8, badge) and one censored side plus 20 (monthly 24, no badge). Updated `test_empty_and_unknown_volume`; added `test_m7_none_without_known_volume` for absent, empty, and unconnected metadata and `test_m7_known_zero_volume_is_available` to distinguish known zero from unavailable volume.
