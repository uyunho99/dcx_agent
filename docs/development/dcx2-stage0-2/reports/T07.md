## 이벤트 스키마와 저장 계약
필수 필드: `ts`(datetime, JSON에서는 ISO 문자열), `round`(1~4), `type`(`direction`, `approve`, `reject`, `move`, `add`, `unreject`).
선택 필드: `kwId`, `kw`, `tags`, `note`, `text`, `from`, `to`. `from`/`to`는 `axis`/`sub` 문자열을 담는 사전이며 Python 모델의 `from_`는 JSON의 `from`으로 직렬화한다.
`REJECT_TAGS = ("irrelevant", "common", "sentence", "misclassified")`.
시간대 없는 ts는 UTC로 해석한다. 렌더링에는 시간값을 출력하지 않는다.

`session_dir(sid)`의 활성 버전에만 쓴다. store의 세션 잠금 안에서 writable 검사, 경로 결정, 쓰기를 수행하므로 버전 전환과 충돌하지 않는다. 구버전 및 readonly 버전의 변경은 거부한다. app/context는 수정하지 않았다.
이벤트는 UTF-8 JSON 한 줄을 O_APPEND의 단일 os.write로 추가한 후 fsync한다. 짧은 쓰기는 fsync 후 OSError로 보고한다. 기존 마지막 줄에 개행이 없으면 같은 write 앞에 개행을 추가하여 손상된 꼬리와 다음 이벤트를 분리한다. 기존 바이트는 수정하지 않는다.
로더는 손상된 JSON, 유효하지 않은 모델, 잘린 UTF-8 줄을 건너뛰고 줄 번호만 warning으로 기록한다. 마지막 줄뿐 아니라 중간의 잘못된 줄도 이후 정상 이벤트 읽기를 막지 않는다. 로그가 없으면 빈 목록이다.
feedback 저장은 같은 세션 잠금 아래에서 읽기/렌더링하고 같은 디렉터리의 임시 파일을 flush/fsync한 뒤 os.replace한다. 실패 시 임시 파일을 제거하고 기존 대상 파일을 보존한다.

## 렌더링 정책
방향 지시는 ts 최신순이고 동률이면 입력 이벤트 순서다. 나머지 항목은 이벤트 순서다.
거절은 REJECT_TAGS 순서로 건수/최대 8개 예시/`외 N건`을 출력한다. 예시 상한 밖의 자유 의견도 유지하며 태그 없는 거절은 `기타` 그룹이다.
모든 add 이벤트는 직접/제안 추가 신호다. 이전 move와 kwId 또는 정규화한 kw가 일치하는 approve는 원하는 방향에 표시한다. move는 axis/sub 이동 기록에 표시한다. 이벤트 스키마에는 origin 필드가 없으므로 추가의 출처를 별도 구분하지 않는다.
이 로그는 누적 피드백 이력이다. unreject도 저장/복원하지만 과거 reject를 삭제하지 않는다. 현재 키워드 상태를 재구성하는 API는 아니다.
빈 섹션은 `- 없음`이며, 사용자 내용은 한 줄로 정리하고 Markdown 제어 문자를 escape한다.

### Findings 및 수정
- R-28: 거절 사유에서 이벤트 순서상 뒤에 오는 unreject/add/approve와 같은 kwId 또는 norm_key(kw)를 가진 reject를 제외한다. 기존 _keys를 재사용하며 ts 순서와 무관하다. 이후 다시 reject하면 다시 집계한다. 그룹 건수, 예시 상한, 외 N건, 거절 의견은 유효한 reject만 반영하고 방향 지시는 누적 유지한다. 위 최초 보고서의 unreject 미반영 정책은 이 수정으로 대체한다.
