## View mode
별도 Zustand store에 `{sid, version}` 선택을 둔다. localStorage나 서버 active-version으로 조회 선택을 저장하지 않는다. 같은 세션의 단계 이동 중 선택을 유지하며 브라우저 전체 새로고침 때는 서버의 활성 버전으로 돌아온다. 새 세션에서는 이전 세션의 선택을 사용하지 않는다.

provider는 versions metadata와 선택 버전의 session을 읽은 뒤 자식을 mount한다. 버전 전환 시 subtree key를 바꿔 기존 폼/비동기 화면 상태가 섞이지 않게 한다. metadata의 readonly 또는 activeVersion과 다른 선택이면 읽기 전용이다. 10초마다 metadata/session을 재조회하여 readonly/stale 변경을 반영한다. 과거 버전을 전역 session store의 active 데이터로 덮어쓰지 않는다.

과거 stage0/context와 stage1/keywords/round/session 조회에 모두 `?version=vN`을 붙인다. 모든 stage 입력과 동작 버튼을 disabled fieldset으로 잠그고 drag/drop도 막는다. 읽기 전용 배너 밖의 새 버전 생성과 sidebar 조회/비교는 사용할 수 있다. 과거 키워드는 필터를 전체, 축을 전체, 그룹을 펼친 상태로 표시한다.

stale는 session의 `stale[stageN]`을 읽는다. backend의 `stageN changed in vM`과 version metadata의 parent로 결과의 기준 버전을 표시한다. 비교 화면의 stale 배너는 선택한 b snapshot을 사용한다.

## 동작별 API
| 동작 | 호출 |
|---|---|
| 목록 열기/상태 확인 | `GET /sessions/{sid}/versions` |
| 버전 선택 | 로컬 조회 선택 변경, `GET /session/{sid}?version=vN`; stage0 `GET /context/{sid}?version=vN`; stage1 `GET /keywords/{sid}?version=vN` 및 필요 시 `/rounds/{n}?version=vN` |
| 이 단계부터 다시 | `POST /sessions/{sid}/versions`, source는 metadata.activeVersion, restartFrom은 현재 단계, note는 메모 |
| 과거 버전에서 새로 시작 | 같은 POST, source는 선택한 과거 버전. 응답 `{version}`을 조회 선택하고 해당 session을 store에 복원한 뒤 해당 단계로 이동 |
| 비교하기 | `/pipeline/compare?a=&b=` 이동 후 `GET /sessions/{sid}/compare?a=&b=&stage=stageN`; b session 조회, stage1은 a session도 조회하여 이동 항목 id를 실제 키워드명으로 해석 |
| 추가된 키워드만 수집 | T22의 `POST /crawl/{sid}/list?version=...&mode=added-keywords` 유지 |

**실제 생성 JSON 계약:** `VersionRequest.from_v = Field(alias='from')`이며 populate_by_name 설정이 없다. 따라서 wire body는 `{from: from_v, restartFrom, note}`다. 사용자 brief의 `{from_v: ...}`를 그대로 전송하면 현 서버에서 validation 오류가 발생한다. API 함수 인자 이름은 from_v로 두고 실제 alias인 from을 전송한다. 테스트로 이 body를 검증했다. backend 변경은 하지 않았다.

`PUT /sessions/{sid}/active-version`은 호출하지 않는다. 현재 writable 버전 선택 역시 단순 조회로 충분하다. 생성이 새 버전을 활성화한다. 작업 중 생성 오류는 `진행 중인 작업이 끝난 뒤 다시 시도하세요`를 표시한다.

## 단계 코드
backend는 `stage[0-9]+`를 허용한다. 이 작업의 header action은 start=stage0, keywords=stage1, crawling=stage2다. 비교의 이후 단계 selector는 preprocess=stage3, labeling=stage4, training=stage5, clustering=stage6, personas=stage7을 지원한다.

## compareView 계약
입력은 backend stage1 응답의 optional `added`, `removed`, `moved`, `distribution`이다. added/removed는 kw/text/id, axis, sub를 읽고 moved는 id와 from/to 및 화면에서 보강한 kw를 읽는다.

출력은 `rows`, `counts`, `empty`, `distribution`이다. 정렬은 추가 → 삭제 → 축 이동, 같은 종류에서는 한국어 keyword 오름차순이다. 추가=success 배지, 삭제=neutral 및 취소선, 이동=neutral과 전/후 축이다. 없는 쪽은 `—`다. 축 이름/하위 분류는 한국어로 표시한다. 분포 순서는 물리→심리→행동→나머지이며 숫자는 건수 delta다. 입력을 변경하지 않는다. 빈 결과는 `키워드 변경이 없습니다.`다.

## S8 차이 및 우려
1. S8의 분포 퍼센트 대신 backend가 제공하는 축별 **건수 증감**을 명시한다. 수집본별 총 문서 수/추가 키워드 수는 versions 응답에 없어 기록 카드에서 숫자를 지어내지 않는다. stage2는 실제 counts delta 또는 `같은 수집본`을 표시한다.
2. 내부 ID·파일명은 INTERNAL_TOOLS=false일 때 렌더링하지 않는다. 수집본은 대신 목록 내 번호로 표현하며 내부 API drawer는 기존 조건부 렌더링을 유지한다.
3. 현재 `crawl_v2.status(sid)`는 version query를 지원하지 않고 active collection을 읽는다. 과거 crawl 화면은 `/session?version=`의 저장된 수집 설정/연결 여부를 disabled 입력으로 표시한다. 과거 gate/progress/report를 active 상태로 가장하지 않는다. 과거의 상세 수집 결과 조회를 위해서는 backend version-aware status/collection GET 계약이 추가로 필요하다.
4. T22의 `기존 수집본 사용 중 · 추가된 키워드 n개` 배너와 수집 버튼은 중복 없이 유지한다. 활성 버전의 session 조회를 version query에 연결했고, 생성 이후 화면이 다시 mount되어 status의 added_keywords_count를 다시 읽는다. 과거 버전에서는 version-aware status가 없으므로 추가 개수를 임의로 표시하지 않는다.
5. stage3 이후 기존 live GET들은 version query를 받지 않는다. 공유 layout 경계에서 history editor를 mount하지 않고 readonly 결과 안내를 표시한다. 실제 버전별 결과 파일의 동일성/저장 시각은 비교 화면에서 확인한다. 기존 단계 파일은 수정하지 않았다.
6. 날짜는 한국어 절대 날짜, 버튼은 동작형 문구로 표시한다. 명시적으로 요구된 `이 단계부터 다시` 및 T22 기존 문구는 유지했다. S8의 고정 예시는 실제 서버 결과로 대체했다.
7. 생성 요청의 from_v/from 불일치는 위 wire 계약 절에 기록했다. API 단위 테스트는 from alias 및 409 문구 보존을 검증하며 history 조회 중 PUT 활성화를 호출하지 않는 것을 확인한다.

## Fix round 1

### Findings and changes
1. `VersionProvider`는 셸 전체에 context만 제공한다. 로딩/오류/재시도 및 `{sid}:{version}` key는 `<main>` 안의 `VersionContent`에만 적용했다. 같은 세션의 버전 전환 동안 metadata를 유지해 버전 드로어를 유지한다. 배경 조회 실패도 재시도를 제공하며 이미 열린 본문은 유지한다. layout의 세션 복원, ChatPanel, integrations drawer 동작 코드는 유지했다.
2. `resolveVersionSelection(current, meta)`로 최초 활성 버전을 선택한 뒤 선택을 고정한다. 원격에서 새 활성 버전이 생기면 작은 안내와 명시적인 열기 버튼을 표시한다. 키워드 초기 조회는 readonly 변경만으로 재실행하지 않아 미저장 검토를 유지한다. 크롤링도 열린 폼을 유지하고 readonly가 되면 polling을 중지한다.
3. Start의 `VersionStage`를 header, 0-A/0-B 폼, SaveBar 영역으로 옮겼다. SessionList와 새 프로젝트 버튼은 잠금 밖에서 동작한다.
4. 읽기 전용 배너는 요청 문구인 `vN · 읽기 전용 · 이 버전에서 새로 시작하기`로 표시하며 마지막 구분자는 없다. 읽기 전용 키워드 화면에서는 저장을 안내하는 draft notice를 표시하지 않는다.
5. `prepareRestartVersion`이 생성과 snapshot 조회를 모두 완료한 후 반환한다. 호출부는 store 복원/이동 뒤 마지막에 select한다. 조회 실패 시 기존 팝오버에 오류가 남는다.
6. compare처럼 route로 단계를 결정할 수 없는 경우 새로 시작 팝오버에서 0~7단계를 명시적으로 선택한다. 초기 선택은 비어 있으며 선택 전 생성 버튼은 비활성이다. stage0으로 묵시적으로 대체하지 않는다.
