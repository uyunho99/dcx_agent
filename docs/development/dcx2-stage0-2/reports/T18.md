## Collection-chain algorithm

1. `load_session(sid)` resolves the active version and snapshots its `collectionId`.
2. If no collection pointer exists, use the existing `load_data("crawl/{sid}/")` storage abstraction, preserving old JSONL sessions and the existing S3 path.
3. Resolve `LOCAL_DATA_DIR/crawl/{sid}/collections/{collectionId}`. Read `manifest.json` and iterate `writer.read_docs(root / "docs")`.
4. Traverse child → parent → oldest ancestor. Insert each record with `docs.setdefault(doc_id, doc)`, so the child wins conflicts. `read_docs` handles within-collection replay duplicates and malformed records; the merge handles cross-collection duplicates.
5. Validate collection IDs and reject cycles. Missing/broken manifests fail the existing preprocess job rather than silently reading unrelated data. Unreferenced collections and historical version pointers are never selected.
6. Apply compatibility mapping, existing ad/cafe filters, identity dedupe, and quality rules; write the existing `preprocessed/{sid}/{timestamp}.jsonl` output and unchanged status payload. The chain is deduplicated before the `original` count.

## Field mapping and quality

All normalized document fields remain in the output; `idx` remains the existing preprocessing index.

| Added field | Mapping |
|---|---|
| `desc` | `body + "\n" + comment text`, with comment texts joined by newline, truncated to 4,000 characters |
| `cafe` | `src_meta.cafe` or channel display name from `context.labels.LABELS["channels"]` |
| `link` | `url` |

Full documents use body length >= 10, independently of title/comments. The brief specifies body-based filtering but no full-body numeric threshold; 10 reuses the description minimum. Snippet documents require title >= 5 chars AND description >= 10; description uses preserved `snippet`, falling back to body. Legacy records retain their exact old quality predicate (title >= 5 OR desc >= 10), existing fields, and link dedupe.

Training, persona, clustering, and cluster-refine fill only missing/empty `bk` and `problemDef` from the active session's `projectContext.bk` and `projectContext.researchQuestion.text`. Explicit modeled request fields keep precedence. No service behavior or request models changed.

`GET /integrations` directly returns `integration_status()` with its names, connected flags, env-var names, affected features, and last_error. The new router is registered before context so requests reach the new handler, verified by the test.
