## Implementation decisions

- Brief class definitions and exact CONTEXT_HEADER take precedence over the older design's dataclass example and differing context heading. Attachment bodies are concatenated without normalization; user instructions remain a separate message.
- JSON extraction handles fenced output, surrounding prose and trailing commas using a string-aware scan, preserving comma-like content inside JSON strings.
- Backends validate direct calls. `run_task` also validates successful raw output and retries only parse/schema failures, once, using the same backend instance. SDK transport retries are disabled on the lazily created OpenAI client.
- OpenAI uses injected SDK-compatible clients in tests and requests JSON schema structured output. Empty key/model settings produce the exact unconnected error without calling transport. Claude uses requests, preserving the legacy `x` placeholder semantics. Transport exception details and response error bodies are not exposed.
- Override patterns use fnmatchcase; the first matching pattern in configuration insertion order wins. Unknown backends become a generic backend error through run_task.
- FakeBackend distinguishes omitted responses from an explicitly empty mapping. The default fixture directory is backend/tests/fixtures/llm; tests override this to a temporary directory, so no permanent fixture files were added.
- ClaudeApiBackend.generate supplies the shared composed raw-text transport for the compatibility wrapper; ClaudeApiBackend.run adds schema validation for new tasks.
- codex_exec uses settings.local_data_dir/llm_runs/{run_id}, the required subdirectories, a manifest with task/sid, non-secret backend settings and SHA-256 input hashes. Existing run IDs with different inputs/settings are rejected to avoid reusing unrelated answers.
- Each CodexExecBackend instance keeps a generated run ID across run_task retries. run_many preserves input order while using a bounded thread pool. Successful existing answers are validated and reused; live PID workers return interrupted without launching another exec. Stale PID files permit execution.
- A nonblocking advisory lock on the persistent worker-log inode protects the PID check and process lifetime, avoiding an unlink/reopen race on ephemeral PID files. PID files are removed after owned work completes. Logs append attempt separators and sanitized process output.
- Worker instructions begin with `답만 answers/task-{n}.json.part에 쓰고 rename하라` (the actual path is backtick-delimited), followed by the entire composed prompt and output JSON schema. Workers perform the .part-to-.json rename. Invalid completed answers move to answers/bad with a .reason.txt explanation.
- The fake is executable with `#!/usr/bin/env python3`; settings.codex_bin points directly to it. Its first-line path parser writes the requested .part file and renames it. Sleep mode spawns a child, allowing the test to verify both worker and child PIDs cease to exist.
- Timeout uses a separate process session, group SIGTERM, a brief reap grace period and group SIGKILL fallback. The error kind is timeout, following the explicit brief/test/ruling rather than the older design sentence saying backend. Test timeout is one second.
