## API

All paths below have prefix `/keywords/{sid}`. Errors use `{status:"error",error:{kind,message}}`; duplicate errors additionally have top-level `duplicateOf`. Every POST accepts `?version=` and rejects readonly/past versions with the store's 409. GET supports historical version reads.

| Method | Path | Request | Response | Errors |
|---|---|---|---|---|
| POST | `/rounds/{n}` | none | `{jobId,status,round,gen,progress,startedAt,updatedAt,error}` | 409 order/already committed/unreviewed draft/readonly, 422 round, 404 session |
| GET | `/rounds/{n}` | optional version query | job plus keywords, inputs, below_min, committed, promptVersion | 404 missing round, 422 round |
| POST | `/rounds/{n}/commit` | `{gen,decisions:[{id,status:"approved"\|"rejected",reject?:{tags,note,to}}]}` | `{status:"ok",round,gen}` | 409 stale gen/order/job/readonly, 422 invalid or incomplete decisions |
| POST | `/events` | `{round,type,kwId?,kw?,tags?,note?,text?,to?}`; server stamps ts/from | `{status:"ok",feedback_md}` | 409 readonly, 422 invalid event/keyword/classification |
| POST | `/manual` | `{kw,axis,sub,origin?:"manual"\|"suggested"}` | Keyword, including volume | 409 duplicate with `duplicateOf`/readonly, 422 invalid axis/sub/empty kw |
| POST | `/suggest-words` | `{axis,sub}` | `{status:"ok",words:[{word,type}]}` | 409 readonly, 422 invalid classification, 502 LLM error |
| POST | `/coverage` | none | coverage report or unconnected/failed state | 409 readonly |
| GET | empty | optional version query | `{keywords,keywordRounds,coverage,feedback_md}` | 404 session |

Malformed requests return 422. Storage I/O errors return 500. No client-provided project context enters LLM tasks. Manual suggested additions explicitly set `origin:"suggested"`.

## Persistence and IDs

`keywordRounds.<n>` contains:

- `round`, `gen` (positive integers), `committed` (boolean).
- `job: {jobId,status,round,gen,progress,startedAt,updatedAt,error}`. Status is running/done/failed; interrupted is `error.kind` on a failed job. Activity is derived by T04 as `keyword_round_<n>`.
- `keywords`: current generation's Keyword records (pending until review); accepted/rejected committed records also live in top-level `keywords` so R4 regeneration preserves previous generations.
- `promptVersion`, `inputs: {rejection,coverage,prior_session,promptVersion}`, `below_min: {got,min}` or null, and normalization log.

IDs are `r{n}g{gen}-{i}` with a one-based index. Initial R4 is g1; successive generations are g2, g3, etc. Retries also advance gen. Manual/suggested IDs are `manual-<uuid>`. Job IDs are UUID hex. Stale generation checks run inside the same storage lock as commit validation, including empty decision arrays.

All session writes call `store.update_session`. `_CheckedPatch.items()` defers validation/patch computation until the store's deep merge runs under its existing lock, avoiding a nested non-reentrant flock. The state, generation and job ID check/write therefore share one critical section. This adapter depends on T04's documented deep-merge implementation and is covered by concurrent-start tests. The executor starts one daemon thread per new job and is injectable for deterministic tests; it contains no authoritative job registry.

R2 coverage uses bk plus the four highest-volume approved keywords, caches human queries, calls `kw_axis_classify` through the shared LLM layer for m6, and uses T08 compute including nullable m7. Missing credentials store `{status:"unconnected"}`. Connected lookup failures preserve unknown volume and an error instead of failing keyword generation. Connected coverage has a nonblank prompt signal, including `부족 축 없음` when there are no gaps. Prior zero signals include explicit stored signals and zero-count collection reports from same-bk prior sessions. Feedback is regenerated and supplied for R2+, and for R1 when events exist.

- Worker exceptions, including StoreError from input assembly or volume lookup, persist failed/backend with a generic message while the same job is still running. Volume StoreError propagates to the worker failure handler; ordinary external volume lookup failures retain the existing unknown-volume fallback. Only the explicit superseded-job conflict is silent. If storage also rejects failure persistence, log only the sid without exception/file contents.
- Prior-session scans skip invalid ids, unreadable or corrupt sessions/reports. Startup recovery isolates each session and logs only its sid; valid interrupted jobs still recover and TestClient lifespan starts.
- R3 uses 부족 축 없음 only for connected/ok coverage without missing_top gaps. Failed coverage supplies 커버리지 계산 실패 — 축 분포 균형에 집중. This supersedes the original ID format documented above; existing saved IDs are not rewritten. commit_round(sid, n, decisions, gen: int | None = None) receives generation explicitly, and the router passes a plain list plus gen. Stale generations still return 409, including empty decisions.
