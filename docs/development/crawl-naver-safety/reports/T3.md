# T3 — 차단 재시도 보호 · 재개 복귀 · 공유 검색 제한기 하한

## 변경 파일

- `backend/app/crawl/queue.py`: 목록 차단 실패는 attempts를 증가시키지 않고 pending으로 반환한다. 기존 failed/AdapterBlocked 목록은 지정 채널에 한해 pending으로 복귀하고 과거 소진 횟수를 초기화한다. 본문 차단은 lease 시 증가한 attempts를 되돌리고 pending, retry_at=now+backoff, exhausted=0으로 저장하며 lease를 해제한다. 기존 제외 키워드 처리를 유지한다.
- `backend/app/crawl/worker.py`: 목록·본문 실패 처리에 `blocked=isinstance(error, AdapterBlocked)`를 전달한다. 공유 Naver 검색 제한기는 `max(DEFAULT_INTERVAL_S, *configured_intervals)`로 0.5초 하한을 적용한다. 더 큰 사용자·재개 간격 및 기존 jitter는 유지한다.
- `backend/app/crawl/control.py`: done 목록 실행에도 failed/AdapterBlocked 작업이 남으면 미완료로 판정한다. 재개할 때 지정 채널 또는 manifest 채널의 기존 차단 실패를 복귀시킨다. 실행 중인 워커의 중복 생성 방지를 유지한다.
- `backend/tests/crawl/test_queue.py`: 목록·본문 차단 시 재시도 보존, backoff, lease 해제, 재개 후 성공을 검증한다.
- `backend/tests/crawl/test_naver_safety.py`: 실제 워커의 목록·본문 차단 결과를 확인하고 기존 0초·0.2초 기대값을 0.5초 하한으로 갱신한다. 저장 설정 0초·2초도 각각 검증한다.
- `backend/tests/crawl/test_crawl_api.py`: legacy 차단 목록의 재개, 채널 제한, 일반 실패 유지, 연속 재개 시 중복 워커·작업 방지를 검증한다.
- `backend/app/label/jev.py`: 사용자 승인으로 소유 범위를 확대했다. Jev 제한기에 `jitter=0`을 명시하여 기존 라벨링 요청 간격을 유지한다.
- `backend/tests/label/test_jev.py`: 가짜 제한기 세 곳이 jitter 키워드를 받으며 0임을 검증한다. 가짜 시계 제한기는 이를 실제 제한기에 전달한다.
- `backend/tests/label/test_judge.py`: 추가 사용자 승인에 따라 별도 가짜 제한기 lambda가 jitter를 받아 실제 제한기에 전달하도록 수정했다. 전체 backend/tests의 가짜 제한기 호출부를 검색했으며 다른 호환성 변경은 필요하지 않았다.
- 증거: `logs/T3-red.txt`, `logs/T3-baseline.txt`, `logs/T3-full-before-jev.txt`, `logs/T3-before-judge-fix.txt`, `logs/T3-green.txt`, 본 보고서.

## 범위 및 검토

참고 커밋 `2c4aed1`의 blocked-retry/resume 부분만 옮겼으며 Naver OpenAPI 코드는 반입하지 않았다. 공유 검색 간격 하한은 `adapters/community.py`의 기존 `DEFAULT_INTERVAL_S`를 사용한다. jitter ±20%는 크롤링에 유지되므로 0.5초는 설정 간격 하한이며 개별 지연의 절대 하한을 뜻하지 않는다.

HTTP 테스트는 MockTransport, API 테스트는 TestClient와 가짜 Popen을 사용한다. 기존 네트워크 차단 fixture가 적용되며 실제 외부 요청·사용자 서버 조작·git commit은 수행하지 않았다.
