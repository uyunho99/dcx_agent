# T2 — Naver 공용 검색 제한기와 즉시 차단 감지

## 구현

- `backend/app/crawl/adapters/base.py`: `AdapterBlocked(message='', *, host=None)` 추가.
- `backend/app/crawl/adapters/naver_common.py`: 기본 `search_limiter`는 자체 제한기이며 `blocked=False`. 검색 호스트만 공용 제한기를 사용한다. 차단 문구는 상태 코드 검사 전에 감지하며, 잠금을 해제하기 전에 차단 플래그를 설정한다. 이미 차단된 요청은 대기 없이 거절하고, 잠금 획득 후에도 재검사하여 동시 요청의 추가 전송을 막는다. 본문 호스트는 자체 제한기를 유지한다.
- `backend/app/crawl/worker.py`: 목록·본문 실행마다 존재하는 Naver 어댑터에 공용 제한기 하나를 주입한다. 동시성 1, 간격은 해당 채널 제한기 간격의 최댓값, 기본 0.5초, 기본 jitter 0.2를 유지한다. 검색 호스트 차단이면 두 Naver 채널을 즉시 `paused_blocked`로 표시한다. 다른 차단은 기존 20회 연속 규칙을 유지한다.
- `backend/tests/crawl/test_naver_safety.py`: HTTP 200/403/500 차단, 목록·본문 실행, 차단 후 요청 0건·대기 없음, 동시 목록 검색의 합산 0.5초 간격, 본문 호스트별 자체 제한기, 단일/양쪽 채널 설정과 0 간격, 기존 차단 임계값을 검증한다.
- `backend/tests/crawl/adapters/test_naver.py`: 문구 없는 403/429가 호스트 전체 차단으로 바뀌지 않는지 검증한다.

## 범위 확인

참조 커밋 `2c4aed1`에서 B-115 공용 제한기·호스트 차단 관련 부분만 반영했다. OpenAPI 코드(`api_list_page`, `api_configured`, `api_limiter`, API용 `ChannelLimiter(2, ...)` 교체, external `naver` 통합, `total_hint`, `url_hits`)는 반입하지 않았다. 기존 `ListPage.total_hint` 계약은 변경하지 않았다.

모든 신규 HTTP 테스트는 `httpx.MockTransport`를 사용했다. 실제 외부 요청, 사용자 서버 조작, git commit은 수행하지 않았다. 재시도 횟수 보존 및 재개 복귀(T3)는 변경하지 않았다.
