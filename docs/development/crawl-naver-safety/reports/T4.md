# T4 — Merge channel defaults when loading crawl configuration

Resolved P2: partial saved `perChannel` entries omitted `concurrency` and
`min_interval_s`, causing frontend validation to disable Save/Start.

`deriveCrawlLoad` now normalizes saved configurations and restored drafts using
`{ ...limits(source), ...entry }`. For `naver_blog`, a saved
`{ max_per_keyword: 25 }` becomes
`{ concurrency: 1, min_interval_s: 0.5, max_per_keyword: 25 }`.
Explicit values, including `min_interval_s: 0`, are preserved. Input objects
are not mutated, and restoring a draft leaves the saved configuration separate.
Backend storage is unchanged.
