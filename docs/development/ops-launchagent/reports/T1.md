# T1 — 운영 LaunchAgent 설치

- 변경 파일: `ops/macmini/install.sh`, `backend/tests/ops/test_install.py`, 이 보고서.
- `--agent`와 `[--agent|--qa]` 사용법 추가, 두 플래그 동시 사용은 exit 2.
- QA 환경 설정은 `qa`, gui 등록 방식은 `agent_domain`으로 분리. 운영 에이전트는 운영 라벨·포트·공개 주소를 유지하고 UserName 및 root:wheel 소유권 변경을 생략한다.
- 실제 운영 에이전트 설치는 sudo/root를 지정 문구로 거부하고, ASSUME_YES를 무시하며 대화형 y 확인을 요구한다.

## RED

명령: `backend/.venv/bin/python -m pytest backend/tests/ops/test_install.py -q -p no:cacheprovider -k agent`

결과: `6 failed, 24 deselected, 1 warning in 5.76s`. 미구현 `--agent`가 사용법 오류를 반환하여 렌더·확인·sudo 거부 테스트가 실패하고 새 사용법 문구도 없음을 확인했다.

## GREEN

명령: `backend/.venv/bin/python -m pytest backend/tests/ops -q -p no:cacheprovider`

검증: 지정 포트와 기본 운영 포트의 렌더, 세 plist에서 UserName만 제거되는지, daemon/agent runtime.env 및 launch.env 바이트 일치, 플래그 충돌, ASSUME_YES 무시, 파이프 y 거부, sudo 거부. 기존 데몬/QA 테스트는 유지했다. 서비스 명령은 테스트 스텁만 사용했다.

첫 전체 실행: `1 failed, 125 passed, 1 warning in 166.51s (0:02:46)`. 신규 기본 포트 테스트가 기존 보호 규칙(8400/3400은 `$HOME/srv/dcx-agent`에서만 허용)에 걸렸다. 임시 HOME/APP_ROOT를 그 구조로 맞춰 테스트만 수정했다.

수정 후 GREEN 명령: `backend/.venv/bin/python -m pytest backend/tests/ops/test_install.py -q -p no:cacheprovider`

결과: `30 passed, 1 warning in 10.28s`. T1 GREEN 확인 후 T2를 시작했다. 최종 전체 회귀 결과는 T2 보고서에 기록한다.

T2까지 완료한 최종 전체 회귀: `142 passed, 1 warning in 161.72s (0:02:41)`.
