# 01 · Brainstorm — DCX STEP 07~11 + 선결 데이터 계약

실행 ID `dcx-step07-11` · base `1ff09c8` · 2026-09-18

## 1. 무엇을 하려는가

DCX 1.0(한양대 차경진 교수 연구팀, GS건설 프로젝트, 2023)의 11단계 방법론 중 **STEP 07~11**을 DCX Agent 2.0으로 구현한다. 1.0은 6개월짜리 연구 프로젝트였고 단계마다 산출물이 문서로 넘어갔다. 2.0은 세션 단위 파이프라인이고 단계 간 산출물이 스키마로 넘어간다.

07~11이 1.0에서 하던 일:

| STEP | 1.0이 한 것 |
|---|---|
| 07 | Ward 군집화 → 8개 Touch Point |
| 08 | 공출현 행렬 + 중심성 → 사람이 Desire를 해석해 14개 Actor 정의 |
| 09 | LDA 토픽 모델링 → 59개 Action |
| 10 | CAM(Customer Action Map)을 사람이 수기 작성 + 기회 영역 |
| 11 | Pain Point를 사람이 카테고리화 → 7개 Insight → 16개 컨셉 |

## 2. 왜 지금인가

STEP 01~06은 이미 돌아간다(수집 · 전처리 · 임베딩 · 준지도 판정). **07부터 끊겨 있다.** 판정된 문서가 `classified/{sid}/relevant_*.jsonl`에 쌓이는데 그다음이 없다.

그리고 기존 구현에는 구조적 문제가 있다.

- `personas.py`가 `{name, situation, pain_point, insight}`를 **한 번의 LLM 호출로** 뱉는다. 08이 할 일(누구인가)과 10이 할 일(무엇을 겪는가)이 섞여 있고, 그 결과 **상황과 결론만 있고 그 사이가 비어 있다.**
- 산출물 스키마가 존재하지 않는다. `schemas.py`는 전부 요청 모델이다. 06이 07에 무엇을 건네는지 어디에도 적혀 있지 않다.

## 3. 무엇을 바꾸는가 — 세 가지 전환

### 3-1. 검색 순위를 관련성 단독에서 떼어낸다 (STEP 09)

관련성이 가장 높은 문서는 대개 실무자가 이미 아는 이야기다. **근거로는 맞고 인사이트로는 0이다.**

```
quality = relevance × (1 − α·max_sim_to_known) × (1 + β·combo_rarity)
                      └ 아는 것과 유사하면 감점 ┘   └ 조합이 희소하면 가점 ┘
```

화면에는 세 항을 컬럼으로 분해하고 **관련성 정렬 대비 순위 이동량**을 함께 찍는다. 공식만 적어두면 무슨 일이 일어났는지 아무도 확인할 수 없다.

### 3-2. CAM의 열 단위를 Action으로 바꾸고 장벽 행을 신설한다 (STEP 10)

1.0 CAM의 행 구조(Action · Context · Keywords · Sentiment · Opportunity)는 그대로 승계한다. 바꾸는 것은 **열이 계층 ID를 가진 구획**이 된다는 것과, **장벽(Barrier) 행 하나를 신설**한다는 것이다. 상황 → 행동 → 장벽이 한 열에서 세로로 읽히면 비어 있던 중간 과정이 강제로 채워진다.

### 3-3. 관측/추론/추측을 기계가 판정한다 (STEP 10)

인용할 원문이 있으면 관측, 유도만 가능하면 추론, 어느 쪽도 아니면 추측. 이 판정은 `retrieve(서술문, scope=이 Action의 Evidence Package)`의 히트 여부라는 기계적 사실로 결정된다. **모델에게 "이건 관측인가요"를 묻지 않는다** — 물으면 모델은 자기가 방금 쓴 문장을 변호한다.

## 4. 선결 조건 — 이번 범위에 포함

07~11을 먼저 손대면 09에서 반드시 막힌다. 코드 확인 결과 다음이 없다.

| 없는 것 | 만드는 곳 | 없으면 막히는 것 |
|---|---|---|
| `doc_id` | 04 수집 | 09 인용 추적 · 10 Reviews · 11 계보 |
| `author_hash` | 04 수집 | 08·10의 "작성자 N명" 전부 |
| `known_insights[]` + 임베딩 | 01 선언 / 05 임베딩 | **09 감점 항 전체** |
| Pinecone 메타 확장 | 05 임베딩 | 09 filter 3키 · 밴드 |
| 06 산출 계약 | 06 판정 | 07 입력 |

특히 `known_insights`가 없으면 감점 항이 항상 1이 되어 **quality가 relevance와 같아진다.** 3-1의 전환이 통째로 무력화된다.

사용자 결정(2026-09-18): **선결 조건을 이번 범위에 포함한다.**

## 5. 범위 밖

- STEP 01~05의 기능 변경 (필드 추가를 제외하고)
- 다크 테마 (Person A 디자인 시스템이 Light 단일 테마로 정의)
- Ward 군집 갈래의 프로덕션 승격 — 비교용으로만 실행하고 ID는 임베딩 갈래에서만 발급
- 인터랙티브 목업 제작 — 별도 세션으로 분리

## 7. 성공 기준

1. 세션 하나가 STEP 01 → 11-B까지 **끊김 없이** 흐른다
2. 최종 컨셉의 임의 문장에서 **원문 `doc_id`까지 역추적**된다
3. STEP 09에서 관련성 1위 문서가 quality 정렬에서 내려간 사례가 **화면에서 확인**된다
4. STEP 10의 등급이 LLM 자기판정이 아니라 **검색 히트로 결정**됨이 로그로 증명된다
5. 반례(counter) 인용이 07 Edge 밴드부터 11 컨셉까지 **한 줄로 이어진다**
