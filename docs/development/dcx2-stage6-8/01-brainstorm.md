기획 · 설계는 6~8단계를 한 번에 하고, 구현은 세 묶음으로 나눈다. 묶음 사이는 계약 파일로만 이어진다.

| 묶음 | 내용 | 다음 묶음에 넘기는 계약 |
|---|---|---|
| ① 6단계 구획 | L1 Cluster · L2 Persona · L3 Context(1.0 방법), 품질 진단, 6.5 Core dims 표본 추출, 6-A · 6-B · 6-C 확정 화면 | `stage_6.json` + 문서별 구획 · 신호 테이블 |
| ② 7단계 근거 탐색 | Context별 2층 HyDE 쿼리, 지연 태깅, quality × DPP 리랭킹, 새로움 신호, 전체 / 새 발견 탭, novelty 교차 확인, 7 근거 탐색 화면 | Evidence Package(8단계의 유일한 입력) |
| ③ 8단계 서술 | 페르소나 카드(헤더 · 8-A CCM · 8-B · 8-C · 8-D), Opportunity Map, SNAGraph 트리, 8-E 인사이트 · 8-F 컨셉(구조화 화면 + 채팅 수정) | — |

### 검토한 대안 (채택하지 않음)
- 두 갈래 병행: 계산 · 화면 · HITL 확정 대상이 두 배(21 → 48)가 된다. 사용자가 1.0 하나로 정했다.
- L1 입력을 TF-IDF 벡터로: 뜻이 같고 표현이 다른 글("워치랑 이어폰 둘 다 챙기기 귀찮다" / "기기 두 개 차는 게 번거롭다")이 갈린다.
- 6.5 전량 추출: Core가 9만 건 수준이면 호출이 수천~수만 회로 데이터 규모에 비례한다.

## 4. Claude 제안 (설계에서 확정, 사용자 이견 시 수정)

1. **미결 산식은 설정값 + "잠정" 표시.** Opportunity 점수(잠정 I + max(I − S, 0)), Persona 집계(문서 수 가중 평균), L3 k 결정, centrality 정규화, DPP kernel 폭, combo_rarity 임계를 `stage_6/7/8` 설정 파일의 값으로 두고 화면에 "잠정"을 붙인다. 1.0 장표 산식이 확인되면 설정만 바꾼다.
2. **LDA 기반 `dist_centroid` 재정의.** 문서는 LDA 최대 확률 토픽으로 Context에 하드 배정하고(7단계 filter용), Context 센트로이드 = 배정 문서 Voyage 벡터 평균. `dist_centroid` · 밴드(P50/P90) · 8-E 레이더가 이 센트로이드를 쓴다.
3. **인용 위치는 원문 기준, 🟢 관측은 코드 검사.** `quote{field: title|body|comment, idx, start, end}`는 벡터 텍스트(앞 2,000자)가 아니라 수집 원문에서 잡는다. 인용 문자열이 원문에 그대로 있으면 🟢, 없으면 등급을 낮춘다.
4. **LLM 캐시는 D-120 방식.** 지연 태깅 결과는 (문서, 프롬프트 버전) 단위로 버전 밖에 캐시한다. Known Insight를 추가하면 그 항목에 대한 `known_match`만 다시 판정한다.
5. **감성사전.** KNU 한국어 감성사전 파일을 저장소에 넣고 3단계 kiwi 토큰에 건다. 1.0 장표 수치와 절대값은 비교하지 않는다.
6. **규모.** 31만~100만 건 기준: Ward · 실루엣은 표본(예: 2만 건)으로, K-means는 전체. 재표집 ARI는 L1 5회 · L2 3회 시작값. 맥미니에서 6단계 전체 목표 시간은 설계에서 측정 계획과 함께 정한다.
7. **테스트 데이터.** 지금 `FakeEmbedder`는 해시 난수라 군집 구조가 없다. 군집 구조를 일부러 넣은 합성 벡터 + 토큰 말뭉치 픽스처를 만들어 k 선택 · 네트워크 분할 · LDA · 밴드를 결정적으로 시험한다. LLM은 기존 `llm/fake.py`로 대체한다.

| ID | 묶음 | 기준 |
|---|---|---|
| AC-01 | ① | 5단계 Core + Supporting 문서로 6단계를 돌리면 L1 · L2 · L3 구획과 ID(`CL0` · `CL0-P1` · `CL0-P1-C2`)가 나오고, 모든 대상 문서가 정확히 하나의 Context에 배정된다(0벡터 · 잘림 문서 수는 보고). |
| AC-02 | ① | 6-A에서 클러스터마다 응집 · 경계 · 안정 · 채널 분포(80% 이상 편중 경고)가 보이고, 지표는 진단만 하며 분리 · 병합을 실행하지 않는다. |
| AC-03 | ① | 6-B에서 어휘 네트워크 centrality 상위 어휘 · Desire 초안 · Goal · 대표 원문이 보이고, Desire를 확정해야 6-C가 열린다. 클러스터 간 Desire 유사 시 제안 배지만 보인다. |
| AC-04 | ① | 6-C에서 Context 이름 · 행동 요약 · 주된 제약 · "목적 · 제약이 빈 Core 비율"이 보이고, 확정해야 7단계가 열린다. |
| AC-05 | ① | 6.5 추출은 Context당 최대 100건이며, `stage_6.json`에 기획안 11절 항목(1.0 재현성 제외)이 남는다. |
| AC-06 | ② | Context마다 persona_query + context_query 8문장이 생성되고, 코드 검증 (a)~(d) 실패 시 1회 재생성 후 `query_gen_fail`이 기록된다. 검색은 Context 필터 없이 돌지 않는다. |
| AC-07 | ② | 노출 10건이 quality × DPP로 선택되고, rare가 2건 미만일 때만 fallback이 발동한다. 아는 얘기는 감점하지 않고 전체 / 새 발견 탭으로 나뉘며, 새 발견이 10건 미만이면 50건씩 더 가져온다. |
| AC-08 | ② | "아는 얘기로 넘기기"가 Known Insight에 저장되고 다음 검색의 새 발견 탭에서 그 원문과 복붙 원문(코사인 ≥ 0.95)이 빠진다. |
| AC-09 | ② | Evidence Package가 기획안 10절 스키마로 저장되고, 근거마다 채널 · 인용 위치 · novelty · known_match가 있다. |
| AC-10 | ③ | 페르소나 카드 헤더의 Desire · Goal은 6-B 확정값과 같다(8단계가 다시 만들지 않는다). CCM Context 행마다 🟢/🟡/🔴 등급이 코드로 판정되고 반례 Context가 표시된다. |
| AC-11 | ③ | 8-C 속성은 근거가 없으면 null로 남고, 감도는 상/중/하, 여정은 분포로만 표시된다. 8-D 처방은 사내 제약을 위반하지 않고 스코프 대조로 FUTURE 판정이 붙는다. |
| AC-12 | ③ | Opportunity Map이 Context 점 · Persona 색 · 1.0 기준선 3개 · 6구역으로 그려지고, novelty 高 ∧ Opportunity 高 지점에 마커가 붙는다. 산식이 잠정이면 "잠정"이 보인다. |
| AC-13 | ③ | 8-E 인사이트(기여 Context ID · 레이더 · 막대 + 평균선)와 8-F 컨셉(PERSONA 합성값 🔴 표시 · Pain Points 원문 + 계층 ID · JOURNEY AS-IS/TO-BE + 4D-CX · 사내 제약 검증)이 생성되고, 채팅 수정본이 저장 · 다시 열람된다. |
| AC-14 | 공통 | 모든 테스트는 네트워크 없이 돈다. 기존 백엔드 · 프론트 테스트가 모두 통과한다. 6~8단계 결과는 버전별로 저장되고 이전 버전은 읽기 전용이다. |
