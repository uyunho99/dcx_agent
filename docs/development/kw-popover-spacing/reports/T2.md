## Chip data source

The page calls `reviewKeywords({ keywordRounds, keywords })`, applies decision overrides, filters the result, and passes it through `KeywordGroup` to `KeywordChip`.
The existing `reviewKeywords` function inserts eligible round entries first and top-level entries last into a Map keyed by ID. Top-level keywords therefore already replace matching nested entries and carry their `display` values into chips; no additional merge is needed.
Nested-only keywords without `display` fall back to `kw`. Round polling responses can carry `display` directly. Initial loads, reloads and coverage polling use `getVersionKeywords`; round polling uses `getVersionRound`.
Manual additions use the matching entry in the new response `keywords` list immediately. Review/move actions reload the full state as before.
The only other direct keyword-text site in the allowed paths was the duplicate-keyword message. Coverage tables show separate query strings, not Keyword objects.
