# 키워드 거절 팝오버 가림 · 키워드 표시 띄어쓰기 — 기획

## 문제
1. 키워드 단계에서 오른쪽 끝 키워드 칩을 누르면 거절 팝오버가 왼쪽으로 펼쳐지고, 왼쪽 부분이 좌측 사이드바(단계 목록·세션) 뒤로 가려진다. "거절 사유" 칩, 메모 입력이 잘려 보인다.
2. 키워드가 "귀촌휴식죄책감", "귀촌부부온도차"처럼 붙어 있어 읽기 어렵다. 원인은 D-325 규칙(두 단어 이하)을 피하려고 모델이 세 단어를 붙여 쓰는 것.

## 결정 (사용자, 2026-10-02)
- 사이드바: **접기 버튼 + 팝오버가 열리면 자동 접기, 닫으면 원래 상태로 복귀.** 팝오버 위치도 본문 안으로 맞춘다.
- 띄어쓰기: **생성 규칙(D-325 두 단어 이하 · 8자 이하)은 그대로, 화면 표시만 띄어쓰기.** 저장값 `kw`·검색어·중복 판정은 바꾸지 않는다.

## 대안
| 안 | 설명 | 판단 |
|---|---|---|
| A. 표시용 띄어쓰기 (선택) | 서버가 Kiwi(`kiwipiepy`, 이미 의존성) 띄어쓰기로 `display` 값을 만들어 API로 내려준다. 화면은 `display`를 보여주고 모든 동작은 `kw`로 한다. | 생성·수집 규칙 무변경 |
| B. 세 단어 허용 | D-325 변경 | 사용자 거절 |
| C. 두 단어로 강제 축소 | 맥락 손실 | 사용자 거절 |

Kiwi 시험 결과: 귀촌휴식죄책감 → 귀촌 휴식 죄책감, 전원혼자시간 → 전원 혼자 시간, 캠핑장비보관 → 캠핑 장비 보관. 단, "온도 차", "미완성 감", "층 간"처럼 한 글자를 떼는 경우가 있어 **한 글자 조각은 앞 단어에 붙인다**(→ 부부 온도차, 농가 미완성감, 층간 소음 스트레스). 띄울 곳을 못 찾으면 원문 그대로 보여준다(귀촌후회).

## 수용 기준
- AC1: 화면 오른쪽 끝 칩에서 거절 팝오버를 열면 팝오버 전체가 보인다(사이드바에 가려지는 부분 0).
- AC2: 팝오버가 열리면 사이드바가 자동으로 접히고, 닫거나 거절·이동을 마치면 열기 전 상태로 돌아간다. 원래 접혀 있었으면 접힌 채로 둔다.
- AC3: 사이드바에 접기/펴기 버튼이 있고 키보드로 조작 가능하며 `aria-expanded`가 맞다.
- AC4: 키워드 칩·목록에 띄어쓴 표시값이 나온다(예: 귀촌 휴식 죄책감). 한 글자 조각은 생기지 않는다.
- AC5: 저장된 `kw`, 수집 검색어, 중복 판정, 거절·이동·직접 추가 API 요청 값은 변하지 않는다.
- AC6: 기존 백엔드·프런트 테스트 통과.

## 제외 범위
- D-325 생성 규칙·라운드 지시문 변경, 기존 저장 데이터 이전.
- 키워드 외 단계(크롤링·라벨링 등) 표시 변경.

## 위험
- Kiwi 띄어쓰기 오판(고유명사·신조어) → 표시만 영향, 원문 `kw` 툴팁으로 확인 가능하게 한다.
- Kiwi 초기화 비용 → 프로세스당 1회 생성, 결과 캐시.
- 사이드바 자동 접힘이 화면 흔들림을 줄 수 있음 → 팝오버를 연 칩 위치 기준으로 다시 배치.
