## Behavior and integration contract

- Calls `insight.concept` through the LLM registry by default with an output schema. Injected run_task remains supported. Registry owns schema retry; concept code owns the single AS-IS semantic regeneration budget.
- `persona_profile` is `{text, grade: 'speculated', label: '합성값'}`. The LLM cannot supply grades or basis.
- `basis` is code-filled verbatim as `근거 {n}건 · 작성자 {m}명에서 종합`. Counts sum package metrics for distinct target Context IDs; unrelated Contexts do not contribute.
- Exactly three pain point evidence numbers are expanded into `{evidence_number, persona_id, quote, channel, doc_id, location: {field, idx, start, end}, context_id, verified}`. No source text or offsets are generated by the LLM.
- Single-Persona evidence preserves `evidence_index` numbering. Multiple Personas use `persona_id:E1` to avoid collisions. Evidence from unrelated Contexts is rejected; Persona-level Desire evidence remains available and retains its package `context_id=None`.
- Each journey row pairs AS-IS context/action/feeling with TO-BE service/service_action. Every context_id must belong to the target insight; otherwise regenerate once, then fail without saving. Service stays a string and gains `service_grade='prescription'`, `service_label='처방'`.
- `cx_4d_distribution` contains all four configured axes, including zero counts.
- Reuses `app.persona.prescribe._call` with `ConstraintCheckOut` and the existing `persona.constraint_check` prompt. Checks every configured constraint exactly once. A violation allows one regenerated concept plus another check; continuing violations save a blocked concept with the existing Korean failure copy. `review` does not block. Check/backend failures, including `PrescriptionError`, preserve the previous revision.
- Optional model-produced `constraint_check` is accepted for compatibility with the committed fake fixture, discarded, and replaced with the separate check result.
- Saved items contain `id=insight_id`, `insight_id`, content, `constraint_check`, `blocked`, `represcribed`, and `regenerated`. Return value adds `revision`. Existing concepts for other insights and complete history are preserved via `PersonaStore.new_revision('concepts', ..., by='generate', message=None)`; no outer sessions.locked is acquired.

## Concerns / downstream notes

- The existing prescription module exposes its reusable call helper as private `_call`; this task leaves that committed module unchanged. A future public constraint-check function could replace this dependency.
- Package author metrics are provisional Context aggregates; summing them cannot deduplicate authors across Contexts because the package does not provide author identities. This calculation is documented in the module.
- PersonaStore locks each mutation internally, but its API does not atomically combine a caller's read/merge with new_revision. Concurrent concept generators for one session/version need worker-level serialization to avoid replacing another generator's newly saved item.
