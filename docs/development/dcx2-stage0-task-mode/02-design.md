# 02 · 설계 — 0단계 과제 유형 분기 · 생각하는 페르소나(디멘션)

- 실행: `dcx2-stage0-task-mode` · 승인된 기획: `01-brainstorm.md`(제품 승인 2026-10-02)
- 결정: `decision-log.md` D-301~D-309 (이 설계에서 D-310~ 추가)
- **기획과의 차이:** 기획 AC-06(분석 목적 기본값)은 디자인 리뷰 D-317(분석 목적 제거)로 없어졌습니다. 기획 2-1 표의 "분석 목적" 행도 해당 없음입니다. 기획 AC-03(탐색·기획형 포지셔닝 필수)은 D-319로 "선택 + 직접 입력"으로 바뀌었습니다. 기획 2-2 · AC-07(디멘션 4칸)은 D-320으로 "생각하는 페르소나 목록 + 디멘션 태그"로 바뀌었습니다.

## 1. 전체 구조

바뀌는 곳은 0단계 입력 모듈과 R1 프롬프트뿐입니다. 2단계 이후 코드(수집 · 라벨링 · 클러스터링 · 페르소나)는 건드리지 않습니다.


## 2. 데이터 모델

### 2.1 `ProjectContext` (`schemaVersion: 1` 유지)

```python
class TaskMode(str, Enum):        # 화면 "과제 유형". projectType(프로젝트 성격)과 별개
    metric = "metric"             # 지표 개선형
    explore = "explore"           # 탐색·기획형

class KeyMetric(BaseModel):
    name: str                     # 지표명
    source: str = ""              # 출처 (예: 보건복지부 환자경험평가)
    item: str = ""                # 관련 설문 문항

class Positioning(BaseModel):     # 축마다 "기본 선택지 하나" 또는 "직접 입력 하나" 또는 빈 값 (D-319)
    price: Price | None = None    # "" → None
    market: Market | None = None  # "" → None
    priceText: str = ""           # 가격대 직접 입력 (예: 중상가 · 구독형)
    marketText: str = ""          # 시장 위치 직접 입력
    # 같은 축에 price와 priceText가 둘 다 있으면 422. 앞뒤 공백은 지움

class PersonaDimension(str, Enum):   # 교수님 디멘션 4개 (D-320)
    social = "social"             # 사회적 외부 페르소나
    taste = "taste"               # 개인 취향·활동
    movement = "movement"         # 신체 외부 동선
    bio = "bio"                   # 내부 바이오

class PersonaSeed(BaseModel):     # 사용자가 떠올린 페르소나 한 줄
    text: str                     # 예: 초진 보호자 (앞뒤 공백 제거, 1~40자)
    dimension: PersonaDimension | None = None   # 태그는 선택

class PersonaSeeds(BaseModel):
    items: list[PersonaSeed] = []  # 최대 20개, 입력 순서 유지
    exploreBeyond: bool = True     # 예시와 다른 페르소나 우선 발굴

class ProjectContext(BaseModel):
    ...
    taskMode: TaskMode | None = None                 # None = 과제 유형 이전에 저장된 세션
    analysisGoal: ChoiceWithNote[AnalysisGoal] | None = None   # 화면에서 없앰(D-317). 예전 세션 값은 보존
    keyMetrics: list[KeyMetric] = []                 # 글자 항목은 {"name": 글자}로 읽음
    positioning: Positioning = Positioning()
    personaSeeds: PersonaSeeds | None = None
    schemaVersion: Literal[1] = 1
```

`schemaVersion`은 올리지 않습니다. 새 필드는 모두 기본값이 있어서, 예전 세션 JSON이 그대로 검증을 통과합니다.

**분석 목적 제거 (D-317, 디자인 리뷰 4B):** 화면에서 "분석 목적" 칩과 보충 설명 칸을 없앱니다. 목적은 리서치 질문 문장에 녹입니다. 모델에서는 필수에서 선택(`None` 허용)으로만 바꾸고 지우지 않습니다.
- 예전 세션: 저장된 `analysisGoal` 값은 그대로 남습니다. md의 "- 분석 목표:" 줄도 그대로 나옵니다(바이트 동일 조건 유지). 화면에는 보이지 않습니다. 0단계를 다시 저장해도 `mergeStartForm`이 불러온 값을 그대로 넘기므로 값은 유지됩니다.
- 새 세션: `analysisGoal`이 없으므로 md에 "- 분석 목표:" 줄이 없습니다.
- `Enum AnalysisGoal`, 라벨 `analysisGoal`, `AlignmentSource.analysisGoal`은 예전 데이터 읽기용으로 남깁니다.

### 2.2 필수 규칙 (모델 검증, 저장 · PATCH 모두 적용)

| taskMode | 핵심 지표(이름 있는 항목 ≥ 1) | 포지셔닝 | 분석 목적 |
|---|---|---|---|
| `None`(예전 세션) | 필수 | 필수: `price` · `market` 기본 선택지 둘 다 (지금 규칙 유지) | 필수 (지금 규칙 유지) |
| `metric` | 필수 | 선택 | 받지 않음(있으면 보존) |
| `explore` | 선택 | 선택 (D-319) | 받지 않음(있으면 보존) |

이름이 빈 지표(`{"name": "  "}`)는 개수에 넣지 않습니다. 하나라도 어기면 `ValidationError`가 납니다. 이때 응답은 기존 동작과 같습니다. POST · PUT은 FastAPI 422, PATCH는 `StoreError('입력값을 확인하세요', 422)`입니다.

### 2.3 예전 데이터 읽기 (D-302)

- `keyMetrics: ["편의성", "만족도"]`는 검증 전에 `[{"name":"편의성"}, {"name":"만족도"}]`로 바꿉니다(`field_validator(mode="before")`). 구조 항목과 글자 항목이 섞여 있어도 됩니다.
- 저장 파일은 다음 저장 때 구조 형태로 바뀝니다. 일괄 변환은 하지 않습니다.
- 알려진 차이(D-311): 예전 버전과 새로 저장한 버전을 "버전 비교"로 보면, 지표 이름이 같아도 `keyMetrics`가 바뀐 항목으로 한 번 나옵니다(글자 → 구조). 비교 로직(`versions.py`)은 6~8단계 브랜치가 고치는 중인 파일이라 이번에는 건드리지 않습니다. backlog로 남깁니다.

## 3. project_context.md 렌더링

예전 세션(`taskMode=None`, `personaSeeds=None`, 지표에 출처 · 문항 없음, 포지셔닝 있음)은 **바이트 단위로 지금과 같습니다**. 새 줄은 값이 있을 때만 나옵니다.

```
## 0-A 프로젝트 개요

- 제품명: 서울아산병원
- 과제 유형: 지표 개선형 — 외부·사내 평가 지표를 올리는 과제. 지표가 떨어지는 순간을 우선 탐색   ← taskMode 있을 때만, 제품명 바로 뒤
- 한줄 정의: …
- 리서치 질문: …
- 질문 템플릿: m1
- 프로젝트 유형: UX개선 (…)            ← 기존 줄. 이름은 바꾸지 않는다(바이트 동일 조건)
- 핵심 지표 (방향 지시자, 측정값 아님): 환자경험 점수 (출처: 보건복지부 환자경험평가 · 문항: 수납 대기 시간이 적절했다)
- 사내 제약: …
- 가격 포지셔닝: …                      ← 값이 있을 때만. 기본 선택지면 한글 이름, 직접 입력이면 그 글자
- 시장 포지셔닝: …                      ← 같은 규칙
- 수집 채널: …
- 제품 분류: …
- 제품 분류 출처: …

## 생각하는 페르소나 · 디멘션            ← personaSeeds 있을 때만

- 초진 보호자 (사회적 외부 페르소나)
- 간병인 (사회적 외부 페르소나)
- 만성 통증 환자 (내부 바이오)
- 응급실 재방문자                        ← 태그 없는 줄은 이름만
- 아직 적지 않은 디멘션: 개인 취향·활동, 신체 외부 동선   ← 태그가 하나도 없는 디멘션이 있을 때만

디멘션: 사회적 외부 페르소나 · 개인 취향·활동 · 신체 외부 동선 · 내부 바이오
예시는 출발점일 뿐이다. 네 디멘션 각각에서 예시와 비슷한 페르소나에 머물지 말고, 예시와 다른 페르소나와 맥락을 우선 발굴할 것

## 0-B 분석 대상 · 초기 기준선
…(변경 없음)
```

- 탐색·기획형 설명: "아직 드러나지 않은 맥락과 기회를 찾는 과제. 넓게 탐색"
- `exploreBeyond=false`일 때 마지막 줄: "예시는 참고 시드이며 제약이 아니다. 범위 밖 발견도 배제하지 말 것"
- 페르소나가 하나도 없으면 목록 자리에 "- 없음"을 쓰고, "아직 적지 않은 디멘션" 줄은 쓰지 않습니다. 디멘션 줄과 마지막 지시 줄은 그대로 씁니다(목록이 비어도 네 디멘션으로 넓게 찾으라는 지시는 남김).
- 지표 표기: 출처만 있으면 `이름 (출처: …)`, 문항만 있으면 `이름 (문항: …)`, 둘 다 없으면 `이름`.
- md의 기존 줄 "프로젝트 유형:"은 화면의 "프로젝트 성격"과 같은 값입니다. md 문구를 바꾸면 예전 세션의 바이트 동일 조건이 깨지므로 그대로 둡니다. 과제 유형 줄과 헷갈리지 않도록 과제 유형은 "과제 유형"이라는 다른 이름을 씁니다(D-312).

## 4. R1 프롬프트 (D-303)

- `r1.v2.md` = `r1.v1.md` + `발산 톤: {tone}` 바로 다음 줄에 `{task_focus}` 한 줄. 나머지는 글자 하나도 바꾸지 않습니다.
- `PROMPT_VERSION = {1: "r1.v2", 2: "r2.v1", 3: "r3.v1", 4: "r4.v1"}`. `r1.v1.md`는 남기되 읽지 않습니다.
- `RoundInputs`에 `task_mode: str | None = None` 추가(마지막 필드, 기본값 있음 → 기존 호출 · 테스트 그대로 동작).
- `task_focus`는 R1에서만 채웁니다. R2~R4 템플릿에는 자리가 없으므로 영향이 없습니다.

```python
              "이용 과정의 어느 단계 · 어느 순간에 막히고, 기다리고, 헷갈리고, 불안해지는지 그 순간의 사물·현상 단어를 우선 발산한다.",

}
# task_mode가 None이거나 모르는 값이면 "" (빈 줄)
```

- 기존 테스트 `test_no_role_sentence_no_domain_examples`(역할 문장 · 도메인 예시 금지)를 두 문구 모두 통과해야 합니다. 문구에 병원 · 에어컨 같은 도메인 단어를 넣지 않습니다.

### 5.2 동작

| 동작 | 결과 |
|---|---|
| 새 프로젝트 | 과제 유형 = 탐색·기획형이 선택되어 있음. 페르소나 목록 비어 있음, 체크 ON |
| 페르소나 추가 | 입력 칸 + "추가하기"(Enter 가능, 한글 조합 중 제외). 빈 글자 · 같은 글자(공백 무시) 중복은 추가 안 함. 20개가 차면 입력 칸 비활성 + 안내 "20개까지 적을 수 있습니다." |
| 디멘션 태그 | 줄마다 단일 선택 칩 4개(짧은 이름: 사회적 외부 · 취향·활동 · 동선 · 바이오). 다시 누르면 해제. 태그 없이 둬도 됨 |
| "아직 안 적은 관점" 줄 | 페르소나가 1개 이상일 때만, 태그가 하나도 없는 디멘션을 정식 이름으로 나열. 네 디멘션이 다 있으면 "네 관점이 모두 있습니다." |
| 예전 세션 열기 | 서버 저장값(`getVersionContext`의 `projectContext`, 병합 전 원본)에 `taskMode`가 없으면 탐색·기획형을 미리 선택하고, 0단계 제목 아래에 **정보 배너**(`Banner tone="info"`)를 띄움(5.4 문구). 저장에 성공하면 배너가 사라짐. 임시 저장만으로는 사라지지 않음 (D-315, 리뷰 2A) |
| 과제 유형 바꾸기 | 입력한 지표 · 포지셔닝 · 질문은 지우지 않음. 템플릿 버튼만 그 유형 것으로 바뀜 (분석 목적 기본값 채우기는 D-317로 없어짐) |
| 지표 개선형에서 포지셔닝 | `<details>`로 접힘. 이미 값이 있으면 펼친 상태로 시작. 탐색·기획형에서는 펼친 상태 |
| 포지셔닝 칩 고르기 · 해제 (D-319) | `Segmented` 대신 단일 선택 `ChoiceChips`. 고른 칩을 다시 누르면 해제(페이지에서 `v === 현재값 ? 비움 : v` 처리, 컴포넌트 변경 없음). 기본 칩을 고르면 그 축의 직접 입력은 비워짐 |
| 포지셔닝 직접 입력 (D-319) | 축마다 "+ 직접 입력" 버튼 → 그 자리에 입력 칸 + "추가하기"(Enter 가능, 한글 조합 중 제외). 추가하면 입력 칸이 사라지고 선택된 칩(글자 + ✕)으로 보임. 기본 칩 선택은 해제됨. ✕로 지우면 빈 값. 축마다 하나만, 최대 40자 |
| 지표 추가하기 | 지표명이 비어 있으면 버튼 비활성. 지표명 칸에서 Enter(한글 조합 중 제외)로도 추가. 추가 후 세 칸 비움 |
| 템플릿 버튼 | 지금처럼 리서치 질문 칸을 채우고 `template` 번호를 저장. 번호: 탐색·기획형 `1`·`2`·`3`(기존) · `4`(새), 지표 개선형 `m1`·`m2`·`m3` |
| 저장 · 키워드 생성 시작 | `validateStartForm`이 실패하면 첫 오류 칸(`aria-invalid="true"`)으로 스크롤 · 포커스(기존 동작) |
| 임시 저장 | 검증 없이 저장(기존 동작). 불러올 때 `mergeStartForm`이 예전 지표 글자를 구조로 바꿈 |

### 5.5 미리보기 · 버전 비교

- 미리보기(`preview()`, 내부 도구 모드)에 과제 유형 줄, 지표 출처 · 문항, 생각하는 페르소나 섹션을 3장 형식대로 추가합니다. 포지셔닝은 값이 있을 때만 보입니다.
- 버전 비교 `fieldNames`에 `taskMode: '과제 유형'`, `personaSeeds: '생각하는 페르소나'`을 추가합니다.

### 5.6 접근성 · 반응형

- 과제 유형은 새 `ChoiceCards`(radiogroup, 화살표 · Home · End 이동, 고른 카드만 `tabIndex=0`)를 씁니다. 그룹 제목은 `aria-labelledby`, 요약 줄은 `aria-describedby`로 연결합니다. 카드는 넓은 화면에서 두 열, 768px 미만에서 한 열로 쌓이며 카드 높이는 최소 64px입니다. 색은 기존 토큰(`--action`, `--action-soft`, `--line`)만 씁니다.
- 핵심 지표 그룹은 지표 개선형이고 비어 있을 때만 `aria-invalid="true"`와 오류 문구(`id` 연결)를 가집니다. 탐색·기획형에서는 오류를 표시하지 않습니다. 포지셔닝은 두 유형 모두 선택이라 오류가 없습니다. 직접 입력 칩의 ✕ 버튼은 `aria-label="가격대 직접 입력 지우기"`처럼 축 이름을 포함합니다.
- 지표 세 칸은 `md:grid-cols-3`, 좁은 화면에서는 세로로 쌓입니다. 페르소나 줄은 넓은 화면에서 이름 · 태그 칩 · 삭제가 한 줄, 좁은 화면(< 768px)에서는 이름과 삭제가 첫 줄, 태그 칩이 둘째 줄로 내려갑니다(칩 줄바꿈 허용, 높이 36px 이상).
- 포지셔닝 접힘은 네이티브 `<details>/<summary>`(키보드 · 스크린리더 기본 지원)를 씁니다.
- 체크박스는 기존 `ds/Checkbox`를 씁니다.
