# 결정 기록 — dcx2-stage0-task-mode

근거 자료: 교수님 피드백 기반 수정 제안(대화로 전달, 2026-10-02). 범위는 그 제안의 P0 두 개입니다.

### D-301 새 분기 이름은 `taskMode` / "과제 유형" · 확정
- 사용자: "이름이 겹치는건 너가 해결해주고"
- 제안서의 "프로젝트 유형"은 기존 `projectType`(화면 "프로젝트 성격")과 이름이 겹친다. 그래서 새 필드 `taskMode`(`metric` 지표 개선형 / `explore` 탐색·기획형)를 따로 두고, 화면 이름은 "과제 유형"으로 한다. 기존 "프로젝트 성격"과 R1 발산 톤은 그대로 둔다.
- 기획안과의 차이: 제안서의 "프로젝트 유형" 명칭을 쓰지 않는다.

### D-302 기존 세션은 그대로 · 확정
- 사용자: "기존 세션은 그대로"
- `taskMode`가 없으면 지금 규칙(핵심 지표 · 포지셔닝 필수)을 쓴다. 글자 목록 핵심 지표는 읽을 때 구조로 바꿔 읽는다. 일괄 변환은 하지 않는다. 다시 렌더한 project_context.md는 바이트 단위로 같아야 한다.
- 기획안과의 차이: 제안서는 "없음을 탐색·기획형 기본값으로 처리"였다. 탐색형으로 처리하면 핵심 지표가 선택이 되어 규칙이 바뀌므로, 저장 규칙은 기존대로 두고 화면에서만 탐색·기획형을 미리 선택한다.

### D-303 R1 분기는 한 템플릿 + 지시 단락 교체 · 확정
- 사용자: "쉬운 쪽으로"
- `r1.v1.md`를 복사해 `r1.v2.md`에 `{task_focus}` 자리를 추가하고 `PROMPT_VERSION[1] = "r1.v2"`로 올린다. `r1.v1.md`는 보존한다. R2~R4는 바꾸지 않는다.

### D-304 범위는 P0 두 개 · 제안
- 과제 유형 분기와 페르소나 디멘션까지만 한다. P1(기대 산출물)과 P2(화면 밀도)는 backlog로 미룬다.

### D-305 핵심 지표 구조 = 지표명(필수) · 출처 · 관련 설문 문항(선택) · 제안
- 지표 개선형에서도 출처는 필수로 막지 않는다. 화면 안내 문구로 출처 입력을 유도한다.
- 예: 환자경험 점수 · 보건복지부 환자경험평가 · "수납 대기 시간이 적절했다"

### D-306 지표 개선형의 포지셔닝은 접힘 · 선택, 비우면 md에서 줄 생략 · 제안

### D-307 페르소나 디멘션은 디멘션당 자유 텍스트 한 칸 + "예시와 다른 페르소나 우선 발굴" 기본 ON · ~~제안~~ → D-320으로 대체
- 체크를 끄면 고정 문구가 "참고 시드이며 제약이 아니다"로 바뀐다.

### D-308 과제 유형별 리서치 질문 템플릿 · 제안
- 지표 개선형 3개(막힘 · 지표 하락 순간 · 불안/헷갈림), 탐색·기획형은 기존 3개 + "드러나지 않은 맥락" 1개. 기존 템플릿 번호 1~3은 바꾸지 않는다.

### D-309 분석 목적 기본값은 비어 있을 때만 채움 · ~~제안~~ → D-317로 폐기
- 지표 개선형 → 니즈탐색, 탐색·기획형 → 컨셉발굴. 제안서의 "Journey", "상품 기회"는 지금 선택지에 없으므로 추가하지 않는다(P1에서 다룸).

## 디자인 리뷰 (plan-design-review, 2026-10-02, 모두 사용자 개별 승인)

### D-315 기존 세션 열기 = 탐색·기획형 미리 선택 + 정보 배너 · 확정 (리뷰 2A)
- 사용자 선택: "2A 안내 배너 + 미리 선택"
- 서버 원본에 `taskMode`가 없을 때만 배너. 저장 성공 시 사라짐.

### D-316 과제 유형 카드 안에 "무엇이 필수인지" 요약 한 줄 · 확정 (리뷰 3A)
- 사용자 선택: "3A 카드 안 요약 한 줄"

### D-317 "분석 목적" 항목 제거 — 목적은 리서치 질문에 녹인다 · 확정 (리뷰 4B, 기획 AC-06 폐기)
- 사용자: "리서치 질문보다 오히려 중요한게 프로젝트 목적 / 성격인거 같아. 어쩌면 분석 목적이 리서치 질문과 하나로 포함될 수 있을 것 같고." → 선택 "4B 분석 목적 항목 없애기"
- 화면에서 분석 목적 칩 · 보충 설명 칸을 없앤다. 모델은 `analysisGoal`을 선택값으로만 바꾸고(예전 세션 `taskMode=None`은 필수 유지), 저장된 값은 보존한다. 새 세션 md에는 "분석 목표" 줄이 없다.
- 기획안과의 차이: 교수님 피드백 표의 "분석 목적 4종 + 보충 설명"을 쓰지 않는다. P1(기대 산출물)은 이제 분석 목적이 아니라 별도 항목으로 설계해야 한다(backlog에 남김).

### D-318 0-A 순서: 제품명 · 한줄 정의 → 프로젝트 성격 → 리서치 질문 · 확정 (D-317과 같은 요청)
- 프로젝트 성격을 리서치 질문 위, 한 줄 전체 폭으로 둔다.

### D-319 브랜드 포지셔닝: 축별 직접 입력 + 다시 눌러 해제, 두 유형 모두 선택 · 확정 (리뷰 5A, 기획 AC-03 변경)
- 사용자: "그리고 이것도 다른 걸 추가할 수 있도록 하고, 선택할 수 있게 하는게 맞지 않을까?" → 선택 "5A 축별 직접 추가 + 해제, 모두 선택"
- 가격대 · 시장 위치마다 기본 칩 하나 또는 직접 입력 하나(`priceText` · `marketText`) 또는 빈 값. 빈 축은 md에서 줄 생략. 예전 세션(`taskMode=None`)은 기존 필수 규칙 유지.
- 기획안과의 차이: 기획 AC-03의 "탐색·기획형 포지셔닝 필수"를 없앤다. 축 자체를 추가하는 기능(5C)은 하지 않는다.

### D-320 "생각하는 페르소나" 목록을 먼저, 줄마다 디멘션 태그(선택) · 확정 (리뷰 6A, 기획 2-2 · AC-07 변경)
- 사용자: "이거를 맨 처음에 바로 제시하는것보다는, 좀 다르게 만드는게 맞지 않겠어? 생각하는 페르소나의 종류를 나열하게 한다거나 등등" → 선택 "6A 목록 먼저 + 줄마다 디멘션 태그"
- 데이터: `personaSeeds{items[{text, dimension?}], exploreBeyond}` (기획의 `personaDimensions` 4칸 대체). 최대 20개, 40자.
- 화면: 한 줄씩 추가 → 줄마다 디멘션 칩 4개 중 하나(다시 누르면 해제) → "아직 안 적은 관점" 줄로 빈 디멘션을 보여 줌.
- md: 목록(디멘션 표시) + 빈 디멘션 줄 + 네 디멘션 이름 + "네 디멘션 각각에서 예시와 다른 페르소나 우선 발굴" 지시.
- 기획안과의 차이: 기획 2-2의 "디멘션 4칸 자유 텍스트"를 쓰지 않는다.

### D-321 과제 유형은 큰 선택 카드 2개(새 `ChoiceCards`) · 확정 (리뷰 7A)
- 사용자 선택: "7A 큰 선택 카드 2개"
- 키보드 동작은 `ChoiceChips`와 같게, 색은 기존 토큰만.

## 세라젬 실행 후속 (2026-10-02)

### D-325 키워드 형태 = 맥락어 + 핵심어 두 단어 이하 · 확정
- 사용자: "지금 키워드가 너무 길거든? 한단어로만 나올수 있게 해줄 수 있어?" → 선택지 3개 중 "2번(맥락어 + 핵심어 두 단어)"
- 이유: 수집은 키워드를 네이버 검색창에 그대로 넣는다(카페 · 블로그 전체, 앵커 없음). "농작업후손부종"처럼 길면 결과가 거의 0건, "부종" 한 단어면 귀농과 무관한 글이 대부분이다. "귀촌불면 · 시골집외풍"처럼 맥락어를 붙이면 짧으면서 대상 글 위주로 수집된다.
- 버린 안: ① 한 단어만(노이즈 · 라벨링 부담 급증) ③ 한 단어 생성 + 검색 시 맥락어 자동 부착(수집 코드와 0단계 입력 칸 추가가 필요해 일요일 일정에 맞지 않음).
- 구현: 지시문 새 버전 r1.v3 · r2.v2 · r3.v2 · r4.v2(형태 규칙 3줄만 추가, 옛 버전 파일은 보존). 맥락어는 첨부 맥락에서 가져오고 여러 개를 고르게 바꿔 쓴다.

### D-326 형태 규칙 위반 키워드는 정리 단계에서 버림(세 단어 이상 · 공백 제거 8자 초과) · 기록
- 지시문만으로는 새는 경우가 있어 `clean_generated`에 같은 기준을 둔다. 버린 이유는 기존 정리 로그에 남는다.
- 실제 LLM 확인(세라젬 전략 2 맥락, gpt-6.1-sol): 90개 생성 · 90개 통과, 평균 6.0자 · 최대 8자. 맥락어는 귀촌 · 시골집 · 전원주택 · 산골 · 주말집 · 농촌 · 마을 등으로 분산(분산 지시 추가 전에는 귀촌 · 시골집 두 개에 몰림).
