# DCX 2.0 0단계 — 과제 유형 분기 · 페르소나 디멘션

- 실행: `dcx2-stage0-task-mode` · 기준 커밋 `9c1e3d7`(`plan/dcx2-stage6-8`, 코드는 main과 같음)
- 근거: 교수님 피드백을 정리한 수정 제안(대화로 전달, 2026-10-02) 중 **P0 두 개**
- 결정 기록: 같은 폴더 `decision-log.md` D-301~D-309

## 1. 문제

교수님 피드백 중 가장 크게 강조된 것은 "목표에 따라 질문 체계를 유연하게"입니다. 지금 0단계 화면은 프로젝트가 무엇이든 **같은 폼, 같은 필수 항목, 같은 R1 프롬프트**를 씁니다.

| 지금 | 실제로 생기는 일 |
|---|---|
| 핵심 지표가 늘 필수다(한 줄 텍스트) | 지표가 없는 탐색형 과제(세라젬 모듈러 주택)도 지표를 지어내서 적어야 저장된다. 지표 개선형 과제(서울아산병원)는 "어떤 평가의 어떤 문항인지"를 적을 칸이 없다. |
| 브랜드 포지셔닝(프리미엄/가성비, 선도자/도전자)이 늘 필수다 | 아산병원 원무 경험 개선 과제에서도 골라야 한다. 의미 없는 값이 project_context.md에 실려 키워드 프롬프트를 흐린다. |
| 리서치 질문 템플릿 3개가 고정이다 | 지표 개선형에 맞는 "어느 순간 막히는가" 계열 질문이 없다. |
| R1 프롬프트가 하나다(톤은 "프로젝트 성격"으로만 갈림) | 아산용과 세라젬용이 같은 지시로 발산한다. |
| 0-B에 인구통계만 있다 | 교수님이 제시한 페르소나 디멘션 4개(사회적 외부 · 취향·활동 · 신체 외부 동선 · 내부 바이오)와 예시를 넣을 곳이 없다. "예시와 비슷한 것만 나오면 의미 없다"는 지시도 없다. |

## 2. 무엇을 만드나 (P0 두 개)

### 2-1. 과제 유형 분기

0-A 맨 위에 **과제 유형**을 고릅니다. 고른 값에 따라 필수 항목, 질문 템플릿, R1 지시가 바뀝니다.

| | 지표 개선형 (예: 서울아산병원) | 탐색·기획형 (예: 세라젬) |
|---|---|---|
| 핵심 지표 | **필수**. `지표명 · 출처 · 관련 설문 문항` 구조로 입력 (예: 환자경험 점수 · 보건복지부 환자경험평가 · "수납 대기 시간이 적절했다") | 선택 |
| 브랜드 포지셔닝 | 접힘 · 선택. 비우면 project_context.md에 줄이 아예 없다 | **필수** (지금과 같음) |
| 리서치 질문 템플릿 | "어느 순간 막히는가" 계열 3개 | 지금 3개 + "아직 드러나지 않은 맥락" 1개 |
| 분석 목적 | 비어 있을 때만 니즈탐색으로 미리 채움 | 비어 있을 때만 컨셉발굴로 미리 채움 |
| R1 지시 | 지표가 떨어지는 순간(막힘 · 대기 · 헷갈림 · 불안)의 사물·현상 단어를 우선 발산 | 기존 사용 장면 밖의 상황 · 대체 행동 · 인접 니즈로 넓게 발산 |

**이름 충돌 해결(D-301):** 코드에 이미 `projectType` = 화면의 "프로젝트 성격"(브랜딩 · 신규기획 · 리뉴얼 · UX개선)이 있고, R1 발산 톤이 이 값으로 정해집니다. 그래서 새 값은 **`taskMode`, 화면 이름 "과제 유형"** 으로 따로 둡니다. "프로젝트 성격"은 그대로 둡니다. 두 값은 서로 다른 축입니다. 예를 들어 아산병원은 과제 유형 = 지표 개선형, 프로젝트 성격 = UX개선입니다.

### 2-2. 페르소나 디멘션 · 예시 (선택 입력)

0-A와 0-B 사이에 새 카드를 둡니다.

```
페르소나 디멘션 · 예시 (선택)
  사회적 외부 페르소나  [예: 초진 보호자, 간병인]
  개인 취향·활동        [..........]
  신체 외부 동선        [예: 원무과 → 검사실 이동]
  내부 바이오           [..........]
  ☑ 예시와 다른 페르소나를 우선 발굴 (기본 ON)
```

project_context.md에는 이렇게 들어갑니다.

```
## 페르소나 디멘션 · 예시

- 사회적 외부 페르소나: 초진 보호자, 간병인
- 개인 취향·활동: 없음
- 신체 외부 동선: 원무과 → 검사실 이동
- 내부 바이오: 없음

예시는 출발점일 뿐이다. 예시와 비슷한 페르소나에 머물지 말고, 예시와 다른 페르소나와 맥락을 우선 발굴할 것
```

체크를 끄면 마지막 줄이 "예시는 참고 시드이며 제약이 아니다. 범위 밖 발견도 배제하지 말 것"으로 바뀝니다. 0-B의 "범위 밖 발견도 배제하지 말 것"과 같은 결입니다.

## 3. 기존 세션 (D-302)

**기존 세션은 그대로 열리고, 그대로 돕니다.**

- 저장된 세션에는 `taskMode`가 없습니다. 이 경우는 **지금 규칙 그대로**입니다. 핵심 지표와 포지셔닝 모두 필수입니다.
- 예전 핵심 지표(`["편의성"]` 같은 글자 목록)는 읽을 때 `{지표명: "편의성"}`으로 바꿔 읽습니다. 저장된 파일을 고치는 일괄 변환은 없습니다.
- 기존 세션을 다시 돌리면 project_context.md가 **한 글자도 달라지지 않습니다**. 과제 유형 줄과 디멘션 카드는 값이 있을 때만 나옵니다. 테스트로 고정합니다.
- 기존 세션을 0단계 화면에서 열면 과제 유형이 "탐색·기획형"으로 미리 선택되어 있습니다. 사용자가 바꿔서 저장하면 그때부터 새 규칙이 적용됩니다.

## 4. R1 프롬프트 — 쉬운 쪽 (D-303)

템플릿은 하나로 둡니다. "발산 톤" 바로 아래에 **과제 유형 지시 한 단락**만 끼웁니다.

- 지표 개선형: "첨부 맥락의 핵심 지표와 관련 문항이 떨어지는 순간을 겨냥한다. 이용 과정의 어느 단계 · 어느 순간에 막히고, 기다리고, 헷갈리고, 불안해지는지 그 순간의 사물·현상 단어를 우선 발산한다."
- 탐색·기획형: "아직 드러나지 않은 맥락을 겨냥한다. 기존 사용 장면 밖의 생활 상황 · 대체 행동 · 인접 니즈로 넓게 발산하고, 이미 아는 것과 비슷한 단어에 머물지 않는다."
- 과제 유형 없음(기존 세션): 빈 줄입니다. 지금 지시와 같습니다.

지시 내용이 바뀌므로 프롬프트 버전을 `r1.v1` → `r1.v2`로 올립니다. 기록 보존을 위해 `r1.v1.md` 파일은 남깁니다. R2~R4는 바꾸지 않습니다. 첨부되는 project_context.md에 과제 유형이 실려 있으므로 R2~R4도 그 맥락은 받습니다.

## 5. 검토한 대안 (채택하지 않음)

| 대안 | 채택하지 않은 이유 |
|---|---|
| "프로젝트 성격"에 지표 개선형 · 탐색형을 칩으로 추가 | 성격(브랜딩 · 리뉴얼 …)과 과제 유형은 다른 축이다. 하나에 섞으면 아산병원을 "UX개선"과 "지표 개선형" 중 하나로만 고르게 된다. 두 축을 동시에 가질 수 없다. |
| 유형별 R1 템플릿 파일 두 개 | 사용자가 쉬운 쪽을 선택했다. 파일이 둘이면 사고 절차 · 분류 · 출력 규칙을 고칠 때마다 두 곳을 맞춰야 한다. |
| 기존 세션을 일괄 변환(예: `taskMode` = 탐색형 저장) | 사용자가 "기존 세션은 그대로"를 선택했다. 변환하면 기존 세션의 project_context.md가 바뀌어 0단계 이후가 모두 "다시 실행 필요"가 된다. |
| 핵심 지표를 새 필드(`kpis`)로 따로 두고 기존 글자 목록 유지 | 같은 뜻의 필드가 둘이 된다. 읽을 때 바꿔 읽기만 해도 기존 세션은 깨지지 않는다. |
| 플랫폼을 "상품기획 / 지표관리"로 분리 | 장기 과제다. 지금은 과제 유형 분기가 그 역할을 대신한다. |

## 6. 수용 기준

| ID | 기준 |
|---|---|
| AC-01 | 0-A 맨 위에 "과제 유형"(지표 개선형 / 탐색·기획형)이 있고, 새 프로젝트는 탐색·기획형이 미리 선택되어 있다. "프로젝트 성격"은 지금처럼 남아 있다. |
| AC-02 | 지표 개선형: 지표명을 하나 이상 넣어야 저장된다. 포지셔닝은 접혀 있고 비워도 저장된다. 비우면 project_context.md에 포지셔닝 줄이 없다. |
| AC-03 | 탐색·기획형: 포지셔닝 두 값을 골라야 저장된다. 핵심 지표는 비워도 저장된다. |
| AC-04 | 핵심 지표는 지표명 · 출처 · 관련 설문 문항으로 입력하고, project_context.md에 `환자경험 점수 (출처: 보건복지부 환자경험평가 · 문항: 수납 대기 시간이 적절했다)` 형태로 나온다. 출처 · 문항이 비면 괄호가 없다. |
| AC-05 | 과제 유형마다 리서치 질문 템플릿이 다르다. 지표 개선형 3개, 탐색·기획형은 지금 3개와 새 1개. 기존 템플릿 번호 1~3은 그대로다. |
| AC-06 | 과제 유형을 바꿀 때 분석 목적이 비어 있으면 기본값(지표 개선형 → 니즈탐색, 탐색·기획형 → 컨셉발굴)이 채워지고, 이미 고른 값은 바뀌지 않는다. |
| AC-07 | 페르소나 디멘션 카드가 0-A와 0-B 사이에 있다. 네 칸은 모두 선택이고, "예시와 다른 페르소나를 우선 발굴"은 기본 ON이다. project_context.md에 2-2의 형태로 들어간다. |
| AC-08 | R1 프롬프트에 과제 유형 지시 단락이 들어가고 버전은 `r1.v2`다. 과제 유형이 없는 세션은 단락이 비어 있다. |
| AC-09 | 기존 세션(과제 유형 없음 · 핵심 지표가 글자 목록)이 그대로 열리고 저장된다. 다시 렌더한 project_context.md가 바뀌기 전과 바이트 단위로 같다. 핵심 지표와 포지셔닝 필수 규칙도 지금과 같다. |
| AC-10 | 백엔드와 화면의 한글 이름 목록이 같다(기존 비교 테스트 통과). 0단계 미리보기 · 버전 비교 화면에 새 항목이 보인다. |

## 7. 제외 범위

- P1 "분석 목적"과 "기대 산출물" 분리, 8단계 출력 형식 연동 → backlog
- P2 화면 밀도 정리(필수 / 권장 / 선택 순서 재배치) → backlog
- R2~R4 프롬프트의 유형별 분기
- 6~8단계(페르소나 생성)에서 디멘션 값을 직접 쓰는 일. 지금은 project_context.md를 통해서만 전달된다.
- 상품기획 / 지표관리 플랫폼 분리
