## 사용자 답 (2026-09-30)

### D-111 Jev = jevmodel.org의 판정 모델 API · 확정
- 사용자: "https://jevmodel.org 이거 내용 참고해줘."
- 확인한 계약(2026-09-30, 공개 문서 기준): `POST https://jevmodel.org/v1/systemone`, `Authorization: Bearer $JEVMODEL_API_KEY`, 본문 `{model: "jev-latest" | 고정 버전, state: 문자열/JSON ≤ 8,000자, questions: {이름: {type: choice|score|noul, instructions, criteria?}} 1~8개}`. `noul`은 보정된 예/아니오 확률이고 별도 confidence 필드는 없다. 키당 분당 120회. 입력 토큰 100만 개당 $0.042, 출력 무료. 실패한 요청은 환불되고, 재시도에는 `Idempotency-Key` 헤더를 붙인다.
- 기획안의 "구조화 판정 전용 · 필드별 확률 제공 · 입력 토큰만 과금"과 일치한다.
- 운영 메모: 튜닝이 끝나면 `jev-latest` 대신 고정 버전을 쓴다(문서 권고). 모델 버전을 라벨의 `votes.jev`에 남긴다.

### D-112 1.0 사람 정답은 없다 · 확정

### D-113 GPT 판정은 cvc-agent 방식 `codex_exec` 레인 · 확정 · 0~2단계 D-076과의 관계
- 사용자: "전에 얘기했던 cvc_agent를 활용하라는게 여기서 사용하라는거야."
- 0~2단계 D-051에서 `codex_exec`를 만든 이유가 바로 4단계 대량 판정이었다. 4단계 GPT 라벨러의 기본 백엔드는 `codex_exec`(`run_many`)이고, `openai_api`는 설정으로 바꾸는 선택 경로다. 0~2단계 과업(키워드 등)의 기본값 `openai_api`(D-076)는 그대로다.
- 영향: 사용량 한도(B-007)는 배치 API 대신 "한도에 걸리면 멈추고 이어서 실행 + 설정으로 `openai_api` 전환"으로 대응한다.

### D-114 Jev에는 등급을 정하는 8개 필드만 묻는다 · 대체됨(D-116)
- Jev는 요청 1회에 질문 8개까지다. `anchor` + 6차원 + `situation`이 정확히 8개라 문서 1건 = 요청 1회로 끝난다. `signal` · `reason_code`까지 물으면 요청이 문서당 2회가 되어 100만 건이 약 6일 → 12일로 늘어난다.
- `signal` · `reason_code`는 등급을 정하지 않으므로 GPT 판정만 쓴다. 이 두 필드는 두 라벨러 교차가 없고, 감사 샘플(⑤)로만 품질을 본다. 기획안 `votes: {jev, gpt}`와의 차이.

### D-115 3~5단계를 한 번의 실행으로 · 확정
- 사용자 선택: "3~5단계 한 번에". 마일스톤 M0~M5로 나눈다(01-brainstorm 4절 A).

### D-114 보완 — Jev 한도 재확인, 질문 합치기로 Non 사유까지 한 번에 받기 · 제안 (2026-09-30)
- 사용자: "jev가 255차원 분류가 가능한걸로 알고 있는데 signal까지는 아니더라도 Non 사유를 받을순 없어? 다시 한번 확인해봐."
- 공개 API 문서(`jevmodel.org/docs`, "Models and limits") 재확인 결과: 요청당 질문 8개 · `choice` 선택지 2~20개 · `score` 2~10단계 · 질문 지시문 1,800자 · 선택지 설명 2,000자. "255"는 문서에서 찾지 못했다(문서는 "API 검증기 기준"이라고 적혀 있다). `/batch`는 화면에서 파일 1,000행까지만 되는 도구라 대량 판정에는 쓸 수 없다.
- 병목은 선택지 수가 아니라 **질문 개수(8개)**다. `choice`는 선택지별 확률을 모두 돌려주므로, 예/아니오 두 칸을 선택지 4개짜리 질문 하나로 합쳐도 칸별 확률을 되살릴 수 있다. 예: `relate_outcome` = {둘 다 없음, relate만, outcome만, 둘 다} → P(relate) = P(relate만) + P(둘 다).
- 이렇게 한 칸을 비우면 Non 사유(`reason_code` 4개 + "Non 아님")를 9번째 칸 대신 8번째 질문으로 넣을 수 있다. 두 쌍을 합치면 `signal`까지 넣을 수 있다. 어느 쪽이든 글 1건 = 요청 1회(약 6일)다.
- 위험: 질문을 합치면 Jev가 판단하는 방식이 달라질 수 있다. 캘리브레이션 세트에서 칸별 κ를 재서 확인한다.

### D-116 Jev 질문 8개 구성 확정 — relate + outcome을 한 질문으로, 8번째에 Non 사유 · 확정 (사용자, 2026-09-30) · D-114 대체
- 사용자: "너가 말한거처럼 진행하면 될거 같은데. 어차피 8개를 한쌍만으로 진행하면 될거 같아. 그러고 signal은 그걸 토대로 gpt가 판별해도 되는거니까."
- 논의 중 사용자 안(anchor · situation을 빼고 6차원 + Non 사유만 묻기, "signal · situation · anchor는 다 저걸 토대로 만들 수 있다")도 나왔으나 사용자가 스스로 거두고 위 안으로 정했다. anchor · situation은 등급 규칙의 독립 조건이라 Jev가 직접 판정한다.
- Jev 요청 1회(글 1건) = 질문 8개:
  1. `anchor` noul · 2~5. `sense` · `feel` · `think` · `act` noul 각각 · 6. `relate_outcome` choice 4개(없음 · relate만 · outcome만 · 둘 다) → 선택지 확률을 더해 `relate` · `outcome` 확률로 되살린다 · 7. `situation` noul · 8. `reason_code` choice 5개(`ad` · `no_needs` · `pure_criticism` · `other` · `not_non`)
- `signal`은 GPT만 판정한다(교차 없음, 감사 샘플로 확인). 나머지 9칸은 두 라벨러 교차.
- 100만 건 ≈ 6일(키 1개, 분당 120회).
- 확인할 것: 합친 질문(6번)의 칸별 κ가 따로 물은 칸과 비슷한지 캘리브레이션 세트에서 잰다. 크게 낮으면 다른 쌍으로 바꾼다(질문 구성은 설정값).

## 설계 단계 결정 (02-design.md, 2026-09-30) — 제안

### D-120 LLM 판정 캐시는 버전 밖 모듈 · 제안
- `judge/{sid}/{prepKey}/{labeler}/{qver}/votes.sqlite`. 같은 문서 집합 · 같은 라벨러 · 같은 질문 버전이면 새 버전에서도 다시 부르지 않는다. 이유: 100만 건 Jev 판정이 약 6일 걸리는데, "4단계부터 다시"(사람 판정 · α만 바꾸기)마다 다시 사면 안 된다. D-078(수집본 모듈)과 같은 원리.

### D-121 RAG 검색은 로컬 벡터 검색 하나 · 확정 (사용자, 2026-09-30) · Pinecone 제거
- 3단계 벡터가 맥미니에 있으므로 Core + Supporting 문서만 골라 코사인 검색한다(100만 건 약 1~2초). 지금은 Pinecone 키가 없어 채팅 · 페르소나의 RAG가 빈 결과를 돌려준다.
- 사용자: "로컬로 하는게 맞는거 같아. 아직 천만건 이상의 데이터로 되진 않을거라서. 굳이 설정을 둘 필요도 없을 거 같아." → 설정 없이 로컬 하나. `pinecone` 의존성 · 6.5단계 적재 작업을 없앤다(6.5단계 화면은 완료 표시만). 1,000만 건을 넘기면 로컬 색인(FAISS 등)을 그때 붙인다.
- 비교 근거(채팅 요약): 로컬 = 업로드 · 비용 · 외부 전송 없음, 버전 · 아는 얘기 필터 · 등급 필터와 바로 맞물림, 100만 건 1~2초. Pinecone 실익 = 호스팅 · 다중 접속, 1,000만 건 이상, 혼합 검색 · 리랭커 — 지금은 해당 없음.

## 설계 단계 사용자 결정 (2026-09-30)

### D-129 임베딩 모델은 `voyage-4` · 확정 (사용자)
- 사용자: "voyage-4로 하면 될거 같고." 기존 코드는 `voyage-multilingual-2`. Voyage 4 제품군(2026-01)은 2048 · 1024 · 512 · 256 차원을 지원한다. 차원은 1024를 유지한다(기존 Pinecone 인덱스 · 설계 계산과 같음). 임베딩 모델 비교 실험은 하지 않는다.

### D-130 5단계 모델 구조: 멀티태스크 MLP 앙상블 → 선택적 증류 · 확정 방향 (사용자) · D-107 대체
- 사용자 질문 흐름: 모델 구조(입력 · 층 · 활성화) → 웹 조사 요청 → "단일 모델보다 다중 모델로 앙상블한 다음 나중에 경량화 · 단일 모델 · 증류 선택".
- 구조(각 멤버): 입력 1032(Voyage 1024 + 채널 원-핫 5 + log 길이 + 스니펫 표시 + Jev 잘림 표시) → LayerNorm → Linear 512 → GELU → Dropout 0.2 → Linear 256 → GELU → Dropout 0.2 → 헤드(anchor 1 · 6차원 6 · situation 1 sigmoid / signal 5 · reason_code 4 softmax). 헤드별 마스크 손실(BCE · CE), 소프트 라벨(합의분 = (Jev 확률 + GPT 0/1)/2, 사람 = 0/1 · 가중치 3), AdamW 1e-3, 조기 종료, 헤드별 temperature.
- 앙상블: MLP × 3(시드 · 부트스트랩 다름) + 선형 모델 × 1. 출력 = 평균 확률 + 모델 간 불일치(분산). 분류 모델 구간 라우팅에 불일치를 함께 쓴다.
- 증류: "단일 모델 만들기"로 앙상블 → 단일 MLP 학생(전량 벡터 사용). 모델 저장소에 별도 모델로 저장하고 캘리브레이션 세트 지표를 나란히 보여 준다. 기본 사용은 앙상블.
- 라이브러리: PyTorch(CPU). 마스크 손실 · 소프트 라벨을 scikit-learn으로 할 수 없어서. 01의 "scikit-learn 로지스틱 회귀 / 작은 MLP"(D-107)를 대체한다.
- 이유: AS-IS 3중 앙상블은 같은 입력 · 같은 데이터라 오류가 겹쳤다. 다양성(초기값 · 표본 · 구조)을 넣은 앙상블은 불확실성 추정이 좋아지고, 학습 때와 다른 글에서 불확실성이 커진다(Lakshminarayanan et al., 2017). 오토인코더(낯선 글 감지)는 앙상블 불일치로 먼저 확인하고 백로그(B-105)로 둔다.

### D-144 τ · α(목표 오류율)는 당분간 제외 · 확정 (사용자, 엔지니어링 리뷰 D5) · 기획안과의 차이
