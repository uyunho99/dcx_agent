# DCX 2.0 · 3~5단계 백로그

지금 하지 않기로 한 것과 그 이유. 0~2단계 백로그(B-0xx)는 `../dcx2-stage0-2/backlog.md`.

## B-101 Core 강화 조건 (← 기획안 6절 경계 사례)
- 정황 + 반응만 있는 원문("새벽에 짜증나서 그냥 껐다")이 기본 규칙에서 Core가 된다. 캘리브레이션에서 쓸 만한지 확인한 뒤, 아니면 Core 조건에 `signal ≠ none` 또는 `think ∨ outcome`을 더한다. 규칙 한 곳만 고치면 되고 재라벨링 · 재학습은 없다.

## B-102 `actor` 태그 (← 기획안 5절 보류)
- 페르소나 집계 공식이 "문서별 단서를 세어 올리는 방식"으로 확정될 때만 추가.

## B-103 1.0 정답 11,550건 불러오기 (← H2)
- 파일이 오면 anchor · reason_code 검증 세트로 불러오는 기능. 없으면 앱 안 캘리브레이션 세트만 쓴다.

## B-104 1.0 방법 트랙(Ward · SNA · LDA)
- 형태소 토큰은 이번에 만들지만, 토큰을 쓰는 분석은 해당 단계 개편 때.

## B-105 오토인코더 기반 낯선 글 감지 (← D-130)
- 공유 몸통 → 입력 복원 디코더, 복원 오차가 크면 사람 큐. 앙상블 불일치로 부족할 때 추가.

## B-106 두 번째 임베딩으로 앙상블 다양성 추가 (← D-130)
- 다른 임베딩(예: 공개 가중치 모델) 위 멤버를 추가하면 다양성이 가장 크지만 임베딩 저장 · 시간이 두 배.

## B-107 단일 모델 만들기(증류) (← D-130, 엔지니어링 리뷰 D1)
- 앙상블을 선생으로 단일 MLP 학생을 전량 벡터에 학습해 모델 저장소에 `kind: distilled`로 저장. 앙상블만으로 속도가 충분해 이번에는 만들지 않는다. 저장소 `meta.kind` 필드는 남겨 두었다.
