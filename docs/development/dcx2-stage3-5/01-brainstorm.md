## 1. 의도 — 사용자가 말한 것과 가정 구분

**사용자가 말한 것 (기획안 + 대화)**
- 3~5단계를 기획안대로 바꾼다. 0~2단계가 끝났으니 이어서 한다(D-001 후속).
- 사람 1명이 2%에 0/1을 다는 지금 방식을 버린다. 두 LLM 라벨러(Jev · ChatGPT)가 **전량**에 경험 태그를 달고, 등급(Core · Supporting · Non)은 **코드가 계산**하고, 사람 검수량은 **목표 오류율 α**가 정한다.
- 두 라벨러가 합의한 라벨로 분류 모델을 만들어 맥미니에 올리면, 이후 세션은 LLM 없이 돈다.
- 임베딩은 3단계에서 한 번만 만들어 5 · 6 · 6.5단계가 같이 쓴다.
- 실무자가 이미 아는 이야기(`known_insights`)는 모든 RAG 검색에서 뺀다.
- 내부 실험용 · 맥미니 로컬(D-002). 실행 중 LLM 기본 백엔드는 GPT API, 설정으로 `codex_exec`(D-076). 개발은 Codex(D-050).
- 모든 단계 결과는 임시 저장 · 저장 + 버전으로 남는다(D-070 보완, D-078).

**Claude의 가정 (틀리면 고쳐 주세요)**
- H1. **Jev** = TypeSafe의 판정 모델 API(jevmodel.org, 사용자 지정 2026-09-30, D-111). `POST https://jevmodel.org/v1/systemone`에 `state`(글, 최대 8,000자)와 `questions`(한 번에 1~8개, `choice` · `score` · `noul`)를 보내면 질문별 값과 확률이 온다. `noul`은 보정된 예/아니오 확률이다. 입력 토큰 100만 개당 $0.042, 출력 무료, 키당 분당 120회. 키는 `JEVMODEL_API_KEY`로 받고, 키가 없으면 가짜 Jev로 테스트한다.
- H2. **1.0 사람 정답 11,550건은 없다**(사용자 확인, D-112). 앱 안에서 사람이 만드는 캘리브레이션 세트(300~500건)만으로 진행한다.
- H2b. **GPT 판정은 cvc-agent 방식의 `codex_exec` 레인으로 돈다**(사용자 지정, D-113). 0~2단계에서 만든 `codex_exec` 백엔드(`run_many`: 작업 1건 = exec 1개, 이어서 실행, 불량 격리)가 바로 이 4단계 대량 판정을 위한 것이다. 기획안의 "ChatGPT CLI"가 이 경로다. GPT API는 설정으로 바꿀 수 있는 선택 경로로 남긴다.
- H3. Voyage · Pinecone · OpenAI · Jev 키가 지금 `.env`에 없다. 0~2단계처럼 **키 없이도 전 과정이 끝까지** 돌아야 한다. 임베딩은 가짜 임베더(같은 글 → 같은 벡터), 라벨러는 가짜 라벨러로 테스트한다.
- H4. 분류 모델은 **세션을 넘어 재사용**된다("이후 세션은 LLM 없이"). 그래서 모델은 세션 밖 `models/` 저장소에 두고 세션 버전이 모델 ID를 가리킨다. 수집본을 가리키는 D-078 방식과 같다.
- H5. "맥미니에 올린다" = 지금 백엔드 프로세스 안에서 로컬 추론한다. 별도 서버를 세우지 않는다.
- H6. 6단계 이후(K-means · 6.5 Pinecone · 7단계 근거 선정 · 8단계 페르소나)는 **새 3~5단계 결과를 읽는 최소 수정**만 한다. 단, `known_insights` 검색 제외는 기획안이 RAG 조회부 수정까지 요구하므로 범위에 넣는다(3절 25~27).

**성공의 모습**
LG 에어컨 세션에서 3단계를 돌리면 규칙 필터 → 정형 문구 치환 → 형태소 토큰 → 임베딩 한 벌이 저장되고 `stage_3.json`이 나온다. 4단계에서 두 라벨러가 전량을 판정하고, 화면에서 α를 0.10 → 0.05로 내리면 사람이 볼 escalate 건수가 214건 → 400건처럼 바로 바뀐다. 사람이 escalate 큐를 한 건씩 제출하면 그때마다 저장된다. 5단계에서 합의 라벨로 분류 모델을 학습해 저장하고, 다음 세션은 그 모델을 골라 LLM 호출 없이 등급과 confidence를 받는다. 키가 없어도 가짜 Jev · 가짜 codex로 같은 흐름이 끝까지 돈다. 6단계 군집은 3단계 벡터를 그대로 쓴다. 이 흐름이 네트워크 없이 테스트로 재현된다.

## 3. 범위

### 3단계 · 전처리 + 임베딩
1. 규칙 필터는 **본문 기준**(지금 `desc` 호환 필드 = 본문 + 댓글 4,000자)으로 적용한다. 광고어 · 제외 출처 · 중복은 0~2단계 규칙을 그대로 쓴다(D-084 · D-085 · D-086 유지).
2. **타겟 무관 단어 규칙 제거는 하지 않는다.** 타겟은 소프트 스코프라 4단계 `anchor`가 판단한다(기획안 2절).
3. **채널 정형 문구 사전**: 채널별 문자열 목록으로 치환 제거한다(카페 가입 안내 · 블로그 공감 버튼 문구 등). 사전은 설정 파일이고 화면에서 추가 · 삭제한다.
4. 텍스트 정제는 두 갈래다. HTML 정제는 모든 경로, **문장부호 · 특수문자 삭제는 토큰 경로에만**. 임베딩 · LLM 판정은 원문(HTML만 정제)을 쓴다.
5. **형태소 토큰**을 `tokens/{sid}/`에 저장한다. 형태소 분석기는 Kiwi(`kiwipiepy`, pip 설치만으로 동작) — 1.0의 OKT는 Java가 필요하다(D-102 확정).
6. **임베딩 한 벌**: Voyage 1024D, Non 포함 전량, 3단계에서 한 번. 임베딩 실패 건은 0벡터로 폴백하고 건수를 센다. 6단계 군집 · 6.5단계 적재는 새로 부르지 않고 이 벡터를 읽는다.
7. 임베딩은 **수집본 + 전처리 규칙 버전**에 묶어 세션 밖에 저장하고, 같은 수집본 · 같은 규칙이면 버전끼리 재사용한다(D-078과 같은 방식, D-103). 저장 형식은 float16 샤드 + 문서 ID 색인 제안(100만 × 1024 ≈ 2GB).
8. `stage_3.json`: 원본 / 후 건수 · 규칙별 제거 건수 · 정형 문구 치환 건수 · 임베딩 실패(0벡터) 건수 · 토큰 생성 건수.

### 4단계 · 라벨링
9. **라벨 스키마**(문서마다): `anchor` · `sem{sense, feel, think, act, relate, outcome}` · `situation` · `reason_code`(Non만: `ad | no_needs | pure_criticism | other`) · `signal`(Core · Supporting만: `pain | unmet | workaround | delight | none`) · `evidence_level`(계산) · `confidence` · `source`(`agreed | human | model`) · `votes{jev, gpt}`.
10. **등급 규칙** `evidence_rule` 한 곳: Core = anchor ∧ 6차원 ≥ 2 ∧ situation / Supporting = anchor ∧ 6차원 ≥ 1 / Non = 나머지. 화면 · 두 라벨러 · 분류 모델이 **같은 구현**을 부른다. 기획안 6절 표 6행을 고정 테스트로 둔다.
11. **라벨러 두 개**
    - **Jev**(H1): 문서 1건 = 요청 1회 = 질문 8개(D-116). `anchor` · `sense` · `feel` · `think` · `act` · `situation`은 예/아니오 확률(`noul`), `relate` · `outcome`은 4지선다 한 질문(없음 · relate만 · outcome만 · 둘 다)으로 묻고 선택지 확률을 더해 칸별 확률로 되살린다, `reason_code`는 5지선다(광고 · 니즈 없음 · 순수 비방 · 기타 · Non 아님). `signal`만 Jev에 묻지 않는다.
    - **GPT**(H2b): `codex_exec` 레인 기본, 설정으로 `openai_api`. 작업 1건에 여러 문서를 묶어 전체 스키마(8개 필드 + `signal` · `reason_code`)를 JSON으로 받는다.
    - 두 라벨러 모두 첫 줄에 0단계 `one_liner`를 싣고 도메인 예시는 넣지 않는다(기획안 횡단 규칙). 질문 문구(태그 정의)는 두 라벨러가 같은 원문을 쓴다.
12. 전량 판정은 **이어서 실행**된다. 0~2단계 수집기처럼 진행을 기록하고, 강제 종료 후 재시작하면 끝난 문서를 다시 부르지 않는다(중복 과금 방지). 한 번 호출에 여러 건을 묶는 크기는 설정값(D-106).
13. `confidence` = 등급 결정 필드(anchor · 6차원 · situation) 일치 비율 × 해당 필드 Jev 최소 확률 〔튠〕.
14. **검수량 6절차**: ① 캘리브레이션(키워드 축 × 채널 계층 샘플 300~500건, 2인 이중 라벨 → κ_human) ② 전량 판정 ③ 정답으로 임계 τ 계산(채택 라벨 오류율 ≤ α 보장) ④ 라우팅(confidence < τ · 등급 불일치 · 경계 근접 → escalate) ⑤ 채택분 무작위 감사 → κ_AI 추이 ⑥ κ_AI 두 번 연속 하락 또는 등급 분포 급변 시 재캘리브레이션 안내.
15. α를 바꾸면 τ · 채택 건수 · escalate 건수 · 예상 소요 시간이 **즉시 다시 계산되어 화면에 보인다**(재판정 없음).
16. **라벨링 화면**: escalate 큐 한 건씩 · 태그 입력 · 계산 등급 실시간 표시 · 한 건 제출 = 저장 · 라벨러 판정은 제출 **뒤에만** 공개(앵커링 방지) · 3모드(calibration · independent · re-issue).
17. 옛 `labeledData[].label` 0/1은 `anchor`로 읽는다(읽기 호환). 옛 세션 화면은 D-060대로 열람만.

### 5단계 · 학습
18. 학습셋 = 두 라벨러 합의분 + 사람 판정분. 입력 = 3단계 벡터. 헤드 = anchor · 6차원 × 6 · situation · signal(5-class) · reason_code(4-class). anchor = 0 문서는 태그 헤드 손실에서 가린다. **등급은 학습하지 않고** 예측 태그에 `evidence_rule`을 적용한다.
19. 모델은 가벼운 것(scikit-learn 로지스틱 회귀 / 작은 MLP 제안, TensorFlow 제거)으로 맥미니 CPU에서 학습 · 추론한다. temperature scaling으로 확률을 보정한다.
20. P(Core) = P(anchor) × P(6차원 중 2개 이상) × P(situation). 이 확률이 `confidence`이자 6~7단계 `pred_entropy`의 원천이다. Core 규칙을 바꿔도 재학습 없이 등급 · 확률이 다시 나온다.
21. **모델 저장소**: 학습한 모델은 세션 밖 `models/{model_id}`에 버전과 학습 근거(세션 · 건수 · 필드별 정확도)와 함께 저장한다. 새 세션의 4단계는 "LLM 라벨 구간"과 "분류 모델 구간" 중에서 고른다(H4).
22. 분류 모델 구간: 확신 구간(보정 후 0.2 미만 / 0.8 초과) → 채택, 애매 구간 → 사람 큐. 무작위 약 1%를 LLM으로 다시 판정해 괴리율을 보고한다.
23. 뒤 단계 호환: 5단계는 지금처럼 `classified/{sid}/relevant_*`(= Core + Supporting)를 쓰고, 각 문서에 `evidence_level_pred` · `confidence` · 태그 확률을 붙인다. `relevance_score` = P(Supporting 이상)로 남긴다.
24. `stage_5.json`: κ_human · 필드별 κ(Jev · GPT) · 합의율 · 등급 분포 · 채택률 · α · τ · escalate 건수 · 분류 모델 필드별 정확도 · 감시 괴리율.

### 공통 · known_insights
25. `knownInsights[]`를 `{id, type: statement|doc, text, doc_id?, from: stage0|drawer|rag|prev_session}` 객체 목록으로 바꾼다. 옛 `string[]`은 `statement`로 읽는다.
26. **공통 서랍**(모든 단계 화면에서 열기): 문장 추가 · 수정 · 삭제, 출처 표시. 같은 `bk`의 이전 세션 확정 인사이트를 자동으로 채운다.
27. **RAG 검색 제외**: 원문을 찾는 모든 RAG 호출(6.5 Pinecone 조회 · 공통 Mini-RAG · 8단계 근거 검색)에 ⓐ 넘긴 원문 `doc_id` 제외 ⓑ 기지 항목과 최대 코사인 ≥ θ(0.85) 제외. "새 발견 찾기" 토글(기본 ON). 결과 카드에 "아는 얘기로 넘기기" 버튼. 문장 항목만 추가 시 1회 임베딩, 원문 항목은 3단계 벡터 재사용.

### 공통 · 저장 · 실행
28. 3 · 4 · 5단계 화면을 0~2단계와 같은 **임시 저장 · 저장 + 버전** 구조로 옮긴다(D-070 보완 이행). "4단계부터 다시" = 새 버전에서 3단계 결과(벡터 포함)를 재사용하고 라벨부터 다시.
29. 오래 걸리는 작업(임베딩 · 전량 판정 · 학습)은 0~2단계 수집기처럼 웹 서버와 분리된 워커 + 진행 기록 + 재시작 이어하기.
30. 외부 키(Voyage · OpenAI · Jev)가 없으면 "미연결"로 표시하고 가짜 백엔드로 끝까지 돈다(D-023 확장).

## 4. 대안

**A. 한 번의 하네스 실행 + 마일스톤 분할 (선택, D-115)**
- M0 기반(작업 워커 · 가짜 임베더/라벨러 · `evidence_rule`) → M1 3단계 전처리 · 토큰 · 임베딩 → M2 4단계 라벨러 · 전량 판정 → M3 α 계산 · 라우팅 · 라벨링 화면 → M4 5단계 분류 모델 · 모델 저장소 → M5 known_insights · 6단계 이후 호환 · 통합 시연.
- 장점: 라벨 스키마 · `evidence_rule` · 벡터가 세 단계 모두에 물려 있어 한 번에 맞춰야 덜 흔들린다. 0~2단계와 같은 방식이라 검증된 흐름이다.
- 단점: 계획이 크다(0~2단계와 비슷한 규모).

**B. 두 번 나눈다 — ① 3 · 4단계(+ known_insights) ② 5단계**
- 장점: 라벨이 실제로 쌓인 뒤 5단계 모델을 설계할 수 있다. 첫 실행이 작다.
- 단점: 4단계의 `confidence` · escalate 규칙이 5단계 출력 계약(`pred_entropy`)을 모른 채 굳을 수 있다. 하네스 실행이 순차라 대기가 길다.

**C. known_insights를 떼어 별도 실행**
- 장점: 3~5단계 본선에 집중한다.
- 단점: 기획안이 "3단계 벡터 재사용"을 전제로 해 결국 3단계와 같이 만든다. 따로 하면 서랍 · 검색 제외를 두 번 손본다.
