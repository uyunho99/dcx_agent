## 1. 문제

| 묶음 | 지금 문제 | 사용자에게 보이는 결과 |
|---|---|---|
| B-108 안정화 | 3~5단계 최종 리뷰 · 재리뷰에서 넘긴 작은 결함 6건 | 비용 중복 호출, 쓸데없는 폴링, 감사 일정 밀림, 새 버전 생성이 막힘, 31만 건에서 개요가 느려질 수 있음 |

## 2. 해결 방향

### B-108 (6건, 기존 설계대로 고친다)
1. **감시 사유 유지:** 학습 상태 API의 `monitor.reason`이 done+오류일 때 저장된 사유("감시 표본 N건을 완료하지 못했습니다.")를 덮지 않는다. 실패 사유가 예외 클래스 이름만이면 "감시 중 오류가 났습니다(<종류>)."로 보인다.
2. **투표 임대 갱신:** 워커 하트비트(10초)마다 자기 임대의 `at`을 갱신해, 600초 넘는 배치도 다른 버전 워커가 회수하지 않게 한다(비용 중복 방지).
3. **읽기 전용 버전의 일시 정지 워커 정리:** 새 버전을 만들어 이전 버전이 읽기 전용이 되면, 그 버전의 일시 정지 판정 워커를 멈춤(중지) 처리한다. 폴링을 끝낸다.
4. **수동 감사와 자동 일정 분리:** 수동으로 만든 감사 라운드는 자동 감사 일정(채택 1,000건 → 이후 1만 건마다)의 칸을 쓰지 않는다.
5. **감시 실행 중 새 버전 생성 허용:** 설계(판정 · 전처리 · 학습 · 추론 중에만 막음)대로, 감시 실행만 돌 때는 새 버전을 만들 수 있게 하고 그 감시는 멈춘다.
6. **개요 폴링 측정 · 개선:** 31만 건 합성 데이터로 라벨링 개요 응답 시간을 잰다. 목표는 캐시가 따뜻할 때 0.5초 이하. 넘으면 전체 표 훑기를 줄이는 쪽으로 고친다.

### B-109 (2건)
1. 새 버전에서 해당 단계를 다시 실행해 끝내면 그 단계의 "이 결과는 vN의 K단계 기준입니다" 배너를 숨긴다.
2. 세션을 처음 열 때 사이드바 단계 완료 표시를 서버 상태로 바로 계산한다(다음 단계로 이동할 때까지 기다리지 않음).

### B-110 키 없는 커버리지 소스(네이버 자동완성)
- **사람 검색어 목록:** 네이버 자동완성(키 없음)에 `bk`와 승인 LLM 키워드 상위 20개를 각각 넣어 추천어(질의당 최대 10개, 인기순)를 받는다. 호출 간격 1초, 총 21회 안팎. 같은 검색어가 여러 번 나오면 가장 높은 순위만 쓴다.
  - "상위 20개" 기준: 지금 라운드 결과에서 승인된 LLM 키워드를 화면 표시 순서(라운드 순 · 생성 순)대로 앞에서 20개.
- **가중치:** 검색량이 없으므로 순위 가중 `1/순위`(1위 1.0, 2위 0.5, 3위 0.33 …).
- **지표**
  - ① 커버리지 = 매칭된 검색어 가중치 합 ÷ 전체 가중치 합(매칭 규칙은 지금처럼 정규화 후 부분일치).
  - ② 순위 구간별 커버리지 = 1~3위 / 4~6위 / 7~10위 구간마다 ①.
  - ⑥ 축 분포 차이 = 지금처럼 사람 검색어를 3축으로 나눠 계산.
  - ⑦ LLM 단독 = 검색량이 없으므로 "계산 불가(검색량 없음)".
  - 누락 검색어 = 매칭 안 된 검색어를 순위 순으로 상위 20개 → R3 `{coverage_signals}` 입력(지금과 같은 자리).
- **소스 우선순위:** 네이버 검색광고 키가 있으면 지금 설계(검색량 가중)를 그대로 쓰고, 없으면 자동완성을 쓴다. 카드에 출처를 표시한다("네이버 자동완성 · 순위 가중" / "네이버 검색광고 · 검색량 가중").
- **오프라인 · 테스트:** 자동완성 백엔드 설정(`AUTOCOMPLETE_BACKEND=http|fake`)을 둔다. 테스트는 네트워크 없이 가짜 응답으로 돈다.

## 3. 수용 기준

| ID | 기준 |
|---|---|
| AC-01 | 감시가 오류와 함께 끝나면 학습 상태 API `monitor.reason`이 저장된 사유를 유지한다. 예외 클래스 이름만 있으면 "감시 중 오류가 났습니다(<종류>)." |
| AC-02 | 600초 넘게 걸리는 배치에서 살아 있는 워커의 임대가 회수되지 않는다(테스트로 하트비트 갱신 확인). |
| AC-03 | 새 버전 생성 후 이전 버전의 일시 정지 워커가 중지 상태가 되고 폴링을 멈춘다. |
| AC-04 | 수동 감사 라운드를 만들어도 다음 자동 감사 시점(1,000 / 11,000 …)이 바뀌지 않는다. |
| AC-05 | 감시 실행만 돌 때 새 버전 생성이 성공하고 감시는 멈춘다. 판정 · 전처리 · 학습 · 추론 중에는 지금처럼 409. |
| AC-06 | 31만 건 합성 데이터에서 개요 응답(캐시 따뜻함)이 0.5초 이하. 측정 결과를 보고서에 남긴다. |
| AC-07 | 새 버전에서 3단계를 다시 실행해 완료하면 3단계 stale 배너가 사라진다(4 · 5단계도 같은 규칙). |
| AC-08 | 세션을 처음 열었을 때 끝난 단계의 완료 표시가 바로 보인다. |
| AC-09 | 검색광고 키가 없을 때 R2 뒤 커버리지가 자동완성으로 계산되고, 카드에 ① ② ⑥ 값과 출처 "네이버 자동완성 · 순위 가중"이 보인다. ⑦은 "계산 불가(검색량 없음)". |
| AC-10 | 자동완성 호출은 질의당 1회, 1초 간격, 세션당 1번(R2 뒤 저장 · 재사용). "다시 계산하기"로만 다시 받는다. |
| AC-11 | 자동완성을 못 받으면(네트워크 오류 · 형식 변경) 카드가 "네이버 자동완성을 받지 못해 커버리지를 계산할 수 없습니다."를 보이고 파이프라인은 계속 진행된다. |
| AC-12 | 누락 검색어 상위 20개(순위 순)가 R3 입력으로 들어간다. |
| AC-13 | 검색광고 키가 있으면 기존 검색량 가중 계산을 그대로 쓴다(기존 테스트 유지). |
| AC-14 | 모든 테스트는 네트워크 없이 돈다(가짜 자동완성). 기존 백엔드 · 프론트 테스트가 모두 통과한다. |

## 4. 제외 범위

- B-108 · B-109 · B-110 외의 백로그(B-001~B-009, B-101~B-107).
- 커버리지 지표 ③ ④ ⑤(B-002), 프롬프트 A/B(B-003).
